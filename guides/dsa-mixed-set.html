"Shortest"

Unit steps → BFS. Weights → Dijkstra. Capped edges → Bellman-Ford rounds.

"Maximise the minimum"

Bottleneck Dijkstra, or binary search on the answer.

Post-order DFS: return one side, record both sides.

"O(n)" or "O(log)"

O(n) on unsorted data → hashing. O(log) on sorted data → binary search.

  • "Shortest" with unit-cost steps → BFS. With weights → Dijkstra. With a cap on the number of edges → Bellman-Ford rounds or Dijkstra with (node, steps) state.
  • "Maximise the minimum" or "minimise the maximum" → bottleneck path (modified Dijkstra) or binary search on the answer plus a feasibility check.

  • "O(n)" on unsorted data that sounds like it needs sorting → hashing.
  • "O(log)" on sorted inputs → binary search, often on something other than the values (a partition, an answer).

04Java templates

Tree DFS: return one thing, record another

private int best;                                  // answer that may use both children
int dfs(TreeNode node) {
    if (node == null) return 0;                    // identity for the combine step
    int l = dfs(node.left), r = dfs(node.right);
    best = Math.max(best, combineBoth(node, l, r));
    return extendOne(node, l, r);                  // what the parent can use
}
// O(n) time, O(h) stack; h = n for a skewed tree (recursion depth risk at ~10^4+)

for (int level = 0; !q.isEmpty(); level++) {

Show Java template: Dijkstra and its bottleneck variant
PriorityQueue<int[]> pq = new PriorityQueue<>(Comparator.comparingInt(a -> a[1]));  // {node, dist}
pq.add(new int[] {src, 0});
while (!pq.isEmpty()) {
    int[] cur = pq.poll();
    if (cur[1] > dist[cur[0]]) continue;           // stale entry (lazy deletion)
    for (int[] e : adj.get(cur[0])) {
        int nd = cur[1] + e[1];                    // bottleneck: Math.min(cur[1], weight) with a max-heap
        if (nd < dist[e[0]]) { dist[e[0]] = nd; pq.add(new int[] {e[0], nd}); }
    }
}
// O((V + E) log V)
Show Java template: binary search on a partition
int lo = 0, hi = m;                                // how many elements to take from the shorter array
while (lo <= hi) {
    int i = (lo + hi) >>> 1, j = half - i;
    if (tooMany(i, j)) hi = i - 1; else if (tooFew(i, j)) lo = i + 1; else return answer(i, j);
}
// O(log min(m, n))

1. Product of Array Except Self LeetCode 238 · Medium ↗

Task
Product of every other element, O(n), no division. Common warm-up.
Insight
Left products, then a right-to-left running product (stepper above).
Cost
O(n) time, O(1) extra space (output doesn't count)
1234→241286
Show Java solution
class Solution {
    public int[] productExceptSelf(int[] nums) {
        int n = nums.length;
        int[] ans = new int[n];
        ans[0] = 1;
        for (int i = 1; i < n; i++) {
            ans[i] = ans[i - 1] * nums[i - 1];   // product of everything to the left of i
        }
        int right = 1;                            // running product of everything to the right of i
        for (int i = n - 1; i >= 0; i--) {
            ans[i] *= right;
            right *= nums[i];
        }
        return ans;
    }
}
Edge cases

One zero (only that position is non-zero), two zeros (all zero), negatives. Division fails on zeros, which is why the interviewer bans it.

2. Longest Consecutive Sequence LeetCode 128 · Medium ↗

Task
Longest run of consecutive integers in an unsorted array, in O(n). Amazon, Media.net, Walmart.
Insight
Set; count only from x when x − 1 is absent. Each number joins one run: O(n).
Cost
O(n) average time, O(n) space
[100,4,200,1,3,2]: only 1 starts a run → 1,2,3,4 = 4
1004200132
Show Java solution
import java.util.HashSet;
import java.util.Set;

class Solution {
    public int longestConsecutive(int[] nums) {
        Set<Integer> set = new HashSet<>();
        for (int x : nums) {
            set.add(x);
        }
        int best = 0;
        for (int x : set) {                       // iterate the set, not nums: duplicates would repeat work
            if (set.contains(x - 1)) {
                continue;                         // x is not the start of a run
            }
            int len = 1;
            while (set.contains(x + len)) {
                len++;
            }
            best = Math.max(best, len);
        }
        return best;
    }
}
Edge cases

Empty array (0), duplicates, negatives, values near Integer.MAX_VALUE (the constraints keep values within ±109, so x + len cannot overflow; say so). Sorting gives a simpler O(n log n) answer; say it first, then optimise.

3. Binary Tree Maximum Path Sum LeetCode 124 · Hard ↗

Task
Max sum of any path of connected nodes, not necessarily through the root. Microsoft (twice), Goldman Sachs.
Insight
A path bends at one highest node: record val + l + r, return val + max(l, r). Clamp negative gains to 0.
Cost
O(n) time, O(h) recursion stack
best path bends at 20: 15 + 20 + 7 = 42
−10915207
Show Java solution
class Solution {
    private int best;

    public int maxPathSum(TreeNode root) {
        best = Integer.MIN_VALUE;
        gain(root);
        return best;
    }

    // best sum of a downward path starting at node (may use one child, never both)
    private int gain(TreeNode node) {
        if (node == null) {
            return 0;
        }
        int left = Math.max(0, gain(node.left));      // a negative branch is dropped, not taken
        int right = Math.max(0, gain(node.right));
        best = Math.max(best, node.val + left + right); // path that bends at node: both sides allowed
        return node.val + Math.max(left, right);      // parent can extend only one side
    }
}
Trace and edge cases

Trace on [-10, 9, 20, null, null, 15, 7] uses the same idea on a tree: children report before parents. gain(node) returns the best downward path; best records the path that bends at the node.

4. Lowest Common Ancestor of a Binary Tree LeetCode 236 · Medium ↗

Task
Deepest common ancestor of two nodes in a binary tree (not a BST). Swiggy.
Insight
Each call returns p, q, the LCA or null. Both subtrees non-null → this node is where they split.
Cost
O(n) time, O(h) space
left finds p, right finds q → root is the LCA
p←LCA→q
Show Java solution
class Solution {
    public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
        if (root == null || root == p || root == q) {
            return root;
        }
        TreeNode left = lowestCommonAncestor(root.left, p, q);
        TreeNode right = lowestCommonAncestor(root.right, p, q);
        if (left != null && right != null) {
            return root;                          // p and q found in different subtrees
        }
        return left != null ? left : right;       // pass up whichever side found something
    }
}
Details and edge cases

A node can be its own ancestor. If the current node is p or q, return it immediately: if the other is below, this node is the answer anyway.

p is an ancestor of q, p == q. The early return assumes both nodes exist; if they might not (LeetCode 1644), count how many you found and return null unless it is 2.

5. All Nodes Distance K in Binary Tree LeetCode 863 · Medium ↗

Task
Values of all nodes exactly k edges from a target. ShareChat, Goldman Sachs.
Insight
Distance goes up through parents. Record parent pointers (tree → graph), then BFS k levels with a visited set.
Cost
O(n) time and space
target 5, k = 2 on LeetCode's example → [7, 4, 1]
5→741
Show Java solution
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Queue;
import java.util.Set;

class Solution {
    public List<Integer> distanceK(TreeNode root, TreeNode target, int k) {
        Map<TreeNode, TreeNode> parent = new HashMap<>();
        Queue<TreeNode> q = new ArrayDeque<>();
        q.add(root);
        while (!q.isEmpty()) {                    // pass 1: record parent pointers, turning the tree into a graph
            TreeNode n = q.poll();
            for (TreeNode c : new TreeNode[] {n.left, n.right}) {
                if (c != null) {
                    parent.put(c, n);
                    q.add(c);
                }
            }
        }
        Set<TreeNode> seen = new HashSet<>();
        q.add(target);
        seen.add(target);
        for (int dist = 0; dist < k && !q.isEmpty(); dist++) {   // pass 2: BFS k levels out from target
            for (int size = q.size(); size > 0; size--) {
                TreeNode n = q.poll();
                for (TreeNode nb : new TreeNode[] {n.left, n.right, parent.get(n)}) {
                    if (nb != null && seen.add(nb)) {
                        q.add(nb);
                    }
                }
            }
        }
        List<Integer> ans = new ArrayList<>();
        for (TreeNode n : q) {
            ans.add(n.val);
        }
        return ans;
    }
}
Edge cases

k = 0 (just the target), k larger than the tree height (empty list), target is the root. Without the visited set BFS bounces between a node and its parent forever.

6. Cheapest Flights Within K Stops LeetCode 787 · Medium ↗

Task
Cheapest price src → dst with at most k stops, or −1. Amazon, Goldman Sachs.
Insight
k stops = k + 1 edges = k + 1 Bellman-Ford rounds, each from a copy (stepper above). Plain Dijkstra fails.
Cost
O(k × E) time, O(n) space
010016003
Show Java solution
import java.util.Arrays;

class Solution {
    public int findCheapestPrice(int n, int[][] flights, int src, int dst, int k) {
        final int inf = Integer.MAX_VALUE;
        int[] cost = new int[n];
        Arrays.fill(cost, inf);
        cost[src] = 0;
        for (int round = 0; round <= k; round++) {   // k stops = at most k + 1 edges
            int[] next = cost.clone();                // relax from last round's values only
            for (int[] f : flights) {
                int from = f[0];
                int to = f[1];
                int price = f[2];
                if (cost[from] != inf && cost[from] + price < next[to]) {
                    next[to] = cost[from] + price;
                }
            }
            cost = next;
        }
        return cost[dst] == inf ? -1 : cost[dst];
    }
}
Why not Dijkstra, and edge cases

Bellman-Ford's round r finds the cheapest paths with at most r + 1 edges, so run exactly k + 1 rounds, relaxing from a copy of the previous round. Plain Dijkstra fails because the cheapest path to an intermediate city may use too many stops.

src == dst (0), unreachable (−1), cycles (harmless, the round limit bounds them). Alternative: BFS by levels with a cost array, or Dijkstra on state (city, stops used); both are accepted.

7. Find the Safest Path in a Grid LeetCode 2812 · Medium ↗

Task
Path from corner to corner that stays as far from thieves as possible. Amazon.
Insight
Multi-source BFS from thieves, then max-heap Dijkstra on the path minimum.
Cost
O(n² log n) time, O(n²) space
distance to the thief at (0,2); best path keeps ≥ 2

Show Java solution
import java.util.ArrayDeque;
import java.util.Arrays;
import java.util.List;
import java.util.PriorityQueue;
import java.util.Queue;

class Solution {
    private static final int[][] DIRS = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

    public int maximumSafenessFactor(List<List<Integer>> grid) {
        int n = grid.size();
        int[][] dist = new int[n][n];
        for (int[] row : dist) {
            Arrays.fill(row, -1);
        }
        Queue<int[]> q = new ArrayDeque<>();
        for (int r = 0; r < n; r++) {
            for (int c = 0; c < n; c++) {
                if (grid.get(r).get(c) == 1) {        // step 1: multi-source BFS from every thief
                    dist[r][c] = 0;
                    q.add(new int[] {r, c});
                }
            }
        }
        while (!q.isEmpty()) {
            int[] cur = q.poll();
            for (int[] d : DIRS) {
                int r = cur[0] + d[0];
                int c = cur[1] + d[1];
                if (r >= 0 && c >= 0 && r < n && c < n && dist[r][c] == -1) {
                    dist[r][c] = dist[cur[0]][cur[1]] + 1;
                    q.add(new int[] {r, c});
                }
            }
        }
        // step 2: maximise the minimum dist along a path; a max-heap Dijkstra on the bottleneck value
        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> b[2] - a[2]);
        boolean[][] done = new boolean[n][n];
        pq.add(new int[] {0, 0, dist[0][0]});
        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            if (done[cur[0]][cur[1]]) {
                continue;
            }
            done[cur[0]][cur[1]] = true;
            if (cur[0] == n - 1 && cur[1] == n - 1) {
                return cur[2];
            }
            for (int[] d : DIRS) {
                int r = cur[0] + d[0];
                int c = cur[1] + d[1];
                if (r >= 0 && c >= 0 && r < n && c < n && !done[r][c]) {
                    pq.add(new int[] {r, c, Math.min(cur[2], dist[r][c])});
                }
            }
        }
        return 0;
    }
}
Details and edge cases

A path's safeness is the minimum Manhattan distance from any cell on it to any thief. "Maximise the minimum along a path" is a bottleneck shortest path: Dijkstra with a max-heap where a path's value is the minimum seen so far. The first time the target is popped, its value is optimal.

A thief on the start or end cell (answer 0), single cell. Alternative that interviewers also accept: binary search the answer d in [0, 2n] and BFS only through cells with dist ≥ d, O(n² log n).

8. Reorganize String LeetCode 767 · Medium ↗

Task
Rearrange so no two adjacent characters are equal, or "". Amazon, DE Shaw.
Insight
Impossible iff a char appears more than ⌈n/2⌉ times. Else place the most frequent, holding the last one out for a turn.
Cost
O(n log 26) = O(n) time, O(26) space
aab→aba
Show Java solution
import java.util.PriorityQueue;

class Solution {
    public String reorganizeString(String s) {
        int[] count = new int[26];
        for (char ch : s.toCharArray()) {
            count[ch - 'a']++;
        }
        PriorityQueue<Integer> pq = new PriorityQueue<>((a, b) -> count[b] - count[a]); // most frequent first
        for (int i = 0; i < 26; i++) {
            if (count[i] > (s.length() + 1) / 2) {
                return "";                        // pigeonhole: some gap would have to hold two copies
            }
            if (count[i] > 0) {
                pq.add(i);
            }
        }
        StringBuilder sb = new StringBuilder();
        int held = -1;                            // the char just placed sits out one turn
        while (!pq.isEmpty()) {
            int c = pq.poll();
            sb.append((char) ('a' + c));
            count[c]--;
            if (held >= 0 && count[held] > 0) {
                pq.add(held);                     // re-enter only after a different char was placed
            }
            held = c;
        }
        return sb.length() == s.length() ? sb.toString() : "";
    }
}
Edge cases and the "abba" bug

One character ("a"), all the same ("aaa" → ""), exactly ⌈n/2⌉ ("aab" → "aba"). A common bug pops two at a time and appends them as a pair: with tied counts the heap can return the second character first next round and produce "abba". Fuzz-testing 20,000 random strings against the ⌈n/2⌉ rule caught that version. The O(n) alternative fills even indices with the most frequent character first, then the rest. Follow-ups: rearrange so equal characters are k apart (LeetCode 358) and Task Scheduler (621).

9. Median of Two Sorted Arrays LeetCode 4 · Hard ↗

Task
Median of two sorted arrays in O(log (m + n)). Oracle.
Insight
Take i from a and j = half − i from b. Correct when a[i-1] ≤ b[j] and b[j-1] ≤ a[i]. Binary search i on the shorter array.
Cost
O(log min(m, n)) time, O(1) space
a = [1,3], b = [2]: left half {1, 2} → median 2
13|2
Show Java solution
class Solution {
    public double findMedianSortedArrays(int[] a, int[] b) {
        if (a.length > b.length) {
            return findMedianSortedArrays(b, a);  // binary search the shorter array
        }
        int m = a.length;
        int n = b.length;
        int half = (m + n + 1) / 2;               // size of the left half (gets the extra element when odd)
        int lo = 0;
        int hi = m;
        while (lo <= hi) {
            int i = (lo + hi) >>> 1;              // elements taken from a
            int j = half - i;                     // elements taken from b
            int aLeft = i == 0 ? Integer.MIN_VALUE : a[i - 1];
            int aRight = i == m ? Integer.MAX_VALUE : a[i];
            int bLeft = j == 0 ? Integer.MIN_VALUE : b[j - 1];
            int bRight = j == n ? Integer.MAX_VALUE : b[j];
            if (aLeft > bRight) {
                hi = i - 1;                       // took too many from a
            } else if (bLeft > aRight) {
                lo = i + 1;                       // took too few from a
            } else {
                int leftMax = Math.max(aLeft, bLeft);
                if ((m + n) % 2 == 1) {
                    return leftMax;
                }
                return (leftMax + (double) Math.min(aRight, bRight)) / 2;
            }
        }
        throw new IllegalArgumentException("inputs not sorted");
    }
}
Edge cases

The median splits the merged array into a left half and a right half; sentinels handle empty sides. One array empty, all of a smaller than all of b, even total (average of two middles; the (double) cast avoids integer overflow when both are near Integer.MAX_VALUE), duplicates. Verified against a merge-and-sort reference on 2,000 random cases. Start by stating the O(m + n) merge, then optimise.

10. Word Ladder LeetCode 127 · Hard ↗

Task
Fewest words from begin to end, one letter changed per step. Goldman Sachs.
Insight
Words = nodes, one-letter changes = edges → BFS. Generate L × 26 candidates.
Cost
O(N × L² × 26) time, O(N × L) space
hithotdotdogcog
Show Java solution
import java.util.ArrayDeque;
import java.util.HashSet;
import java.util.List;
import java.util.Queue;
import java.util.Set;

class Solution {
    public int ladderLength(String beginWord, String endWord, List<String> wordList) {
        Set<String> unvisited = new HashSet<>(wordList);
        if (!unvisited.contains(endWord)) {
            return 0;
        }
        Queue<String> q = new ArrayDeque<>();
        q.add(beginWord);
        unvisited.remove(beginWord);
        for (int steps = 1; !q.isEmpty(); steps++) {
            for (int size = q.size(); size > 0; size--) {
                char[] w = q.poll().toCharArray();
                for (int i = 0; i < w.length; i++) {
                    char original = w[i];
                    for (char c = 'a'; c <= 'z'; c++) {   // generate neighbours: L * 26 candidates
                        if (c == original) {
                            continue;
                        }
                        w[i] = c;
                        String next = new String(w);
                        if (next.equals(endWord)) {
                            return steps + 1;
                        }
                        if (unvisited.remove(next)) {      // remove = mark visited, done at enqueue time
                            q.add(next);
                        }
                    }
                    w[i] = original;
                }
            }
        }
        return 0;
    }
}
Details and follow-ups

Generate neighbours by trying 26 letters at each position (L × 26 candidates) instead of comparing against every dictionary word (N × L). Each of N words generates 26L candidates, each costing L to build and hash.

endWord not in the list (0), beginWord not in the list (allowed), beginWord == endWord is excluded by the constraints. Follow-ups: bidirectional BFS (expand the smaller frontier; large speed-up on big dictionaries) and Word Ladder II (return all shortest paths: BFS to build a parent DAG, then DFS).

07Common mistakes

Common mistakes
  • Plain Dijkstra for Cheapest Flights (ignores the stop limit).
  • Relaxing Bellman-Ford in place.
  • Returning l + r to the parent in Max Path Sum.
  • Marking BFS nodes visited on poll.
  • No visited set in Distance K: infinite bouncing.
  • Binary searching the longer array in Median.

08Interview questions

Why not Dijkstra for Cheapest Flights?

Standard Dijkstra keeps only the cheapest cost per city. The cheapest route to a middle city may already use too many stops, while a pricier route with fewer stops is the one that reaches dst in time. Either track (city, stops) as the state or use k + 1 Bellman-Ford rounds.

In Bellman-Ford rounds, why copy the array?

Relaxing in place lets one round use edges relaxed earlier in the same round, so a path with more edges than allowed sneaks in. The copy makes each round add at most one edge.

Max Path Sum: why return max(l, r) but record l + r?

A path that uses both children bends at this node and cannot continue to the parent (it would visit this node twice in a fork). The parent can only extend a straight path, so it gets the better single side.

Longest Consecutive: is it really O(n) with the inner while loop?

Yes. The while loop only runs from run starts, and every element belongs to exactly one run, so the inner loop runs n times in total across the whole outer loop.

Word Ladder: why mark visited at enqueue time?

If you mark on poll, the same word can be enqueued many times from different parents at the same level, which multiplies the work and the memory. Marking when enqueuing is correct for BFS because the first time a node is reached is already the shortest distance.

LCA follow-up: what if it is a BST, or nodes have parent pointers?

BST: walk from the root; if both values are smaller go left, both larger go right, else this is the LCA; O(h), no recursion needed. Parent pointers (LeetCode 1650): it becomes "intersection of two linked lists", two pointers that switch heads, O(h) time and O(1) space.

Median: why binary search the shorter array?

So j = half − i is never negative or greater than n, and the complexity becomes O(log min(m, n)).

A problem says "find the minimum effort path where effort is the maximum height difference along the path". Which pattern?

Minimise the maximum along a path: bottleneck Dijkstra (min-heap on the max seen so far) or binary search on the answer with BFS. Same family as Safest Path, mirrored. (LeetCode 1631.)

What does Product Except Self return for [0, 0, 5]?

[0, 0, 0]. Every position's product includes at least one of the zeros.

Distance K: why is a plain DFS from the target not enough?

Children are reachable but the parent and the parent's other subtree are not, because tree nodes do not point upwards. The parent map is what makes upward moves possible.

Can "aaabc" be reorganized? What does the ⌈n/2⌉ rule say?

n = 5, ⌈5/2⌉ = 3, and 'a' appears 3 times, so yes: "abaca".

Cheapest Flights with k = 0: what are you computing?

Only direct flights: one Bellman-Ford round, so cost[dst] is the direct price from src or −1.

09Quick check

"Longest run of consecutive integers in an unsorted array, in O(n)." First idea?

Sorting is O(n log n). "O(n) on unsorted data that sounds like sorting" is the hashing cue.

In Max Path Sum, what does gain(node) return to its parent?

The parent can only extend a straight path. The bent path val + l + r is recorded in best, not returned.

Why does Cheapest Flights relax from a copy of last round's costs?

In place, one round can chain several edges (0→1→2→3 in the example) and break the k-stop limit.

"Shortest transformation sequence, one letter changed per step." Which tool?

Every step costs 1, so BFS levels are distances. Dijkstra works but adds a log factor for nothing.

10Cheat sheet

Cheat sheet
  • "Without division" → prefix × suffix products.
  • O(n) on unsorted data → hash set; start only at run beginnings.
  • Tree path that bends → post-order: return one side, record both.
  • "Distance k" from a non-root → parent map, then BFS.
  • "At most k stops" → k + 1 Bellman-Ford rounds from a copy.
  • "Maximise the minimum" on a path → multi-source BFS + max-heap Dijkstra (or binary search the answer).
  • "No two adjacent equal" → max-heap, hold the last char out; impossible if count > ⌈n/2⌉.
  • Two sorted arrays, O(log) → binary search the partition of the shorter one.
  • Shortest with unit steps → BFS; mark visited on enqueue.
