Graphs: BFS, DFS, Topological Sort, Union-Find

Four tools cover nearly every graph question in SDE-2 rounds: BFS for shortest steps and spreading processes, DFS for reachability, Kahn's algorithm for dependency order and cycle detection, and union-find for connectivity as edges arrive. Learn to model the problem as a graph first; the algorithm follows.

01When to use this pattern

Most graph questions do not say "graph". Spot the nodes and edges: grid cells and their 4 neighbours, courses and prerequisites, rooms and keys, variables and ratios, bombs and "is inside the blast radius of".

02The mental model, from scratch

A graph is nodes plus edges. In Java you represent it as an adjacency list, List<List<Integer>> (or Map<String, Map<String, Double>> for named, weighted nodes), or you leave it implicit: a grid where neighbours are computed from (r ± 1, c) and (r, c ± 1). Every traversal is the same loop: take a node from a container, look at its neighbours, add the unvisited ones. A queue makes it BFS (wide, by distance); a stack or recursion makes it DFS (deep). The visited set is what makes it O(V + E) instead of infinite.

Mark visited when you enqueue, not when you dequeue

If you mark on dequeue, the same cell can be enqueued by several neighbours before it is processed. On a 1000×1000 grid that turns into millions of duplicate entries and a TLE or out-of-memory. Every solution below marks on enqueue.

Union-find in one paragraph

Each node points to a parent; a root points to itself and names the component. find(x) follows parents to the root. union(a, b) finds both roots and, if different, hangs one under the other. Two optimisations make it practically O(1): path compression (while finding, re-point nodes closer to the root) and union by rank (hang the shorter tree under the taller, so trees stay shallow). Together the amortised cost is O(α(n)), the inverse Ackermann function, which is ≤ 4 for any input that fits in memory. Use either one alone and you still pass most interviews; use both and say why.

03Java templates

BFS on an adjacency list (shortest unweighted distances) and a reusable union-find. Grid BFS is the Number of Islands solution below; Kahn's algorithm is Course Schedule II.

import java.util.ArrayDeque;
import java.util.Arrays;
import java.util.Deque;
import java.util.List;

class GraphTemplates {
    // BFS on an adjacency list: shortest edge-count distance from src to every node (-1 = unreachable).
    // O(V + E) time and space.
    static int[] bfs(List<List<Integer>> adj, int src) {
        int[] dist = new int[adj.size()];
        Arrays.fill(dist, -1);
        Deque<Integer> queue = new ArrayDeque<>();
        dist[src] = 0;                          // dist doubles as the visited set
        queue.offer(src);
        while (!queue.isEmpty()) {
            int u = queue.poll();
            for (int v : adj.get(u)) {
                if (dist[v] == -1) {            // mark on enqueue so no node is queued twice
                    dist[v] = dist[u] + 1;
                    queue.offer(v);
                }
            }
        }
        return dist;
    }

    // Union-find with path compression and union by rank: near-O(1) amortised per operation.
    static final class Dsu {
        private final int[] parent;
        private final int[] rank;
        private int components;

        Dsu(int n) {
            parent = new int[n];
            rank = new int[n];
            components = n;
            for (int i = 0; i < n; i++) {
                parent[i] = i;
            }
        }

        int find(int x) {
            if (parent[x] != x) {
                parent[x] = find(parent[x]);    // full path compression (recursive)
            }
            return parent[x];
        }

        boolean union(int a, int b) {           // false if a and b were already connected
            int ra = find(a), rb = find(b);
            if (ra == rb) {
                return false;
            }
            if (rank[ra] < rank[rb]) {
                int t = ra;
                ra = rb;
                rb = t;
            }
            parent[rb] = ra;
            if (rank[ra] == rank[rb]) {
                rank[ra]++;
            }
            components--;
            return true;
        }

        int components() {
            return components;
        }
    }
}

Recursion depth in Java

Recursive DFS on a 300×300 all-land grid can go 90,000 frames deep; the default thread stack (512 KB–1 MB) overflows somewhere around 10–20k frames depending on frame size. Prefer an explicit ArrayDeque stack or BFS for grids, and mention it. The recursive find in the DSU is fine because union by rank keeps trees O(log n) deep.

04Worked problems

1. Number of Islands

LeetCode 200 · Medium. Grid of '1' (land) and '0' (water). Count islands: groups of land connected up/down/left/right.

Key insight: count connected components. Scan every cell; each unvisited land cell starts a new island, and a BFS from it marks the whole island visited. Here the grid itself is the visited set (land is overwritten with '0'); if mutating input is not allowed, use a boolean[][].

import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    private static final int[][] DIRS = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

    public int numIslands(char[][] grid) {
        int rows = grid.length, cols = grid[0].length, islands = 0;
        for (int r = 0; r < rows; r++) {
            for (int c = 0; c < cols; c++) {
                if (grid[r][c] != '1') {
                    continue;
                }
                islands++;
                grid[r][c] = '0';                       // mark visited when ENQUEUED, not when polled
                Deque<int[]> queue = new ArrayDeque<>();
                queue.offer(new int[]{r, c});
                while (!queue.isEmpty()) {
                    int[] cell = queue.poll();
                    for (int[] d : DIRS) {
                        int nr = cell[0] + d[0], nc = cell[1] + d[1];
                        if (nr >= 0 && nr < rows && nc >= 0 && nc < cols && grid[nr][nc] == '1') {
                            grid[nr][nc] = '0';
                            queue.offer(new int[]{nr, nc});
                        }
                    }
                }
            }
        }
        return islands;
    }
}

Complexity: O(R·C) time, O(min(R, C)) queue space for BFS (the frontier is a diagonal band).

Edge cases: all water → 0; all land → 1; a single row or column; diagonal neighbours do not connect. Interviewers often ask whether you may modify the input: ask, then choose.

2. Rotting Oranges

LeetCode 994 · Medium. Every minute, each rotten orange rots its 4-neighbour fresh oranges. Return the minutes until no fresh orange remains, or −1 if some can never rot.

Key insight: multi-source BFS. Put all rotten oranges in the queue at time 0 and process level by level (queue.size() snapshot). Count fresh oranges up front so the answer check is O(1) and so you can stop as soon as the count hits 0 (otherwise you count one extra minute for the last level).

import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public int orangesRotting(int[][] grid) {
        int rows = grid.length, cols = grid[0].length, fresh = 0;
        Deque<int[]> queue = new ArrayDeque<>();
        for (int r = 0; r < rows; r++) {
            for (int c = 0; c < cols; c++) {
                if (grid[r][c] == 2) {
                    queue.offer(new int[]{r, c});   // every rotten orange is a source at minute 0
                } else if (grid[r][c] == 1) {
                    fresh++;
                }
            }
        }
        int[][] dirs = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
        int minutes = 0;
        while (!queue.isEmpty() && fresh > 0) {
            minutes++;
            for (int size = queue.size(); size > 0; size--) {   // process exactly one BFS level
                int[] cell = queue.poll();
                for (int[] d : dirs) {
                    int nr = cell[0] + d[0], nc = cell[1] + d[1];
                    if (nr >= 0 && nr < rows && nc >= 0 && nc < cols && grid[nr][nc] == 1) {
                        grid[nr][nc] = 2;
                        fresh--;
                        queue.offer(new int[]{nr, nc});
                    }
                }
            }
        }
        return fresh == 0 ? minutes : -1;
    }
}

Complexity: O(R·C) time and space.

Edge cases: no fresh oranges at all → 0 (even with no rotten ones); fresh but no rotten → −1; an isolated fresh orange → −1. The BFS-from-each-rotten-orange approach is O((R·C)²) and is the classic wrong first answer.

3. Keys and Rooms

LeetCode 841 · Medium · CoinDCX. Room 0 is open; every other room is locked. Each room holds keys to other rooms. Can you visit every room?

Key insight: rooms are nodes, keys are directed edges. The question is "is every node reachable from 0?". Any traversal works; this one is iterative DFS with a counter so you do not need a final scan.

import java.util.ArrayDeque;
import java.util.Deque;
import java.util.List;

class Solution {
    public boolean canVisitAllRooms(List<List<Integer>> rooms) {
        boolean[] seen = new boolean[rooms.size()];
        Deque<Integer> stack = new ArrayDeque<>();
        seen[0] = true;
        stack.push(0);
        int visited = 1;
        while (!stack.isEmpty()) {                  // iterative DFS: no recursion-depth risk
            for (int key : rooms.get(stack.pop())) {
                if (!seen[key]) {
                    seen[key] = true;
                    visited++;
                    stack.push(key);
                }
            }
        }
        return visited == rooms.size();
    }
}

Complexity: O(N + K) time where K = total keys, O(N) space.

Edge cases: a room containing its own key; duplicate keys; keys only to already-visited rooms; a single room → true.

4. Course Schedule

LeetCode 207 · Medium. numCourses courses and pairs [a, b] meaning "take b before a". Can you finish all courses?

Key insight: this is "does the directed graph have a cycle?". Kahn's algorithm: if every course gets polled, there is no cycle. Get the edge direction right: [a, b] is an edge b → a, and it increments indegree[a].

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;

class Solution {
    public boolean canFinish(int numCourses, int[][] prerequisites) {
        List<List<Integer>> next = new ArrayList<>();
        for (int i = 0; i < numCourses; i++) {
            next.add(new ArrayList<>());
        }
        int[] indegree = new int[numCourses];
        for (int[] p : prerequisites) {             // p = [course, prereq]: edge prereq -> course
            next.get(p[1]).add(p[0]);
            indegree[p[0]]++;
        }
        Deque<Integer> queue = new ArrayDeque<>();
        for (int i = 0; i < numCourses; i++) {
            if (indegree[i] == 0) {
                queue.offer(i);
            }
        }
        int taken = 0;
        while (!queue.isEmpty()) {
            int c = queue.poll();
            taken++;
            for (int n : next.get(c)) {
                if (--indegree[n] == 0) {
                    queue.offer(n);
                }
            }
        }
        return taken == numCourses;                 // anything left over sits on a cycle
    }
}

Complexity: O(V + E) time and space.

Edge cases: no prerequisites → true; self-loop [0,0] → false; duplicate pairs (indegree counts them twice but each is also decremented twice, so it still works); disconnected components. The DFS alternative uses three colours (unvisited, in progress, done); hitting an "in progress" node means a back edge, which is a cycle.

5. Course Schedule II

LeetCode 210 · Medium. Same input; return one valid order to take all courses, or an empty array if impossible.

Key insight: the order in which Kahn's algorithm polls nodes is a topological order. Return it when its length is numCourses; otherwise there was a cycle. (The trace in section 02 is this problem.)

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;

class Solution {
    public int[] findOrder(int numCourses, int[][] prerequisites) {
        List<List<Integer>> next = new ArrayList<>();
        for (int i = 0; i < numCourses; i++) {
            next.add(new ArrayList<>());
        }
        int[] indegree = new int[numCourses];
        for (int[] p : prerequisites) {
            next.get(p[1]).add(p[0]);
            indegree[p[0]]++;
        }
        Deque<Integer> queue = new ArrayDeque<>();
        for (int i = 0; i < numCourses; i++) {
            if (indegree[i] == 0) {
                queue.offer(i);
            }
        }
        int[] order = new int[numCourses];
        int k = 0;
        while (!queue.isEmpty()) {
            int c = queue.poll();
            order[k++] = c;                         // the poll order IS a topological order
            for (int n : next.get(c)) {
                if (--indegree[n] == 0) {
                    queue.offer(n);
                }
            }
        }
        return k == numCourses ? order : new int[0];
    }
}

Complexity: O(V + E) time and space.

Edge cases: many valid orders exist and any is accepted. If the interviewer wants the lexicographically smallest order, swap the queue for a PriorityQueue<Integer> (O((V + E) log V)). If they want "minimum number of semesters", process level by level like Rotting Oranges and count levels.

6. Number of Provinces

LeetCode 547 · Medium. An n×n adjacency matrix says which cities are directly connected. A province is a group of cities connected directly or indirectly. Count provinces.

Key insight: connected components again, this time with union-find: start with n components and decrement every time a union actually merges two different roots. DFS over the matrix works equally well; union-find shines when edges arrive as a stream.

class Solution {
    private int[] parent;
    private int[] rank;

    public int findCircleNum(int[][] isConnected) {
        int n = isConnected.length, components = n;
        parent = new int[n];
        rank = new int[n];
        for (int i = 0; i < n; i++) {
            parent[i] = i;
        }
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {           // matrix is symmetric: upper triangle is enough
                if (isConnected[i][j] == 1 && union(i, j)) {
                    components--;                       // each successful merge removes one component
                }
            }
        }
        return components;
    }

    private int find(int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];              // path halving: point to grandparent
            x = parent[x];
        }
        return x;
    }

    private boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) {
            return false;
        }
        if (rank[ra] < rank[rb]) {                      // attach the shorter tree under the taller
            int t = ra;
            ra = rb;
            rb = t;
        }
        parent[rb] = ra;
        if (rank[ra] == rank[rb]) {
            rank[ra]++;
        }
        return true;
    }
}

Complexity: O(n² · α(n)) time (reading the matrix dominates), O(n) space.

Edge cases: the diagonal is always 1 (ignore it); one city → 1; fully connected → 1. The matrix is symmetric, so only the upper triangle is read.

7. Redundant Connection

LeetCode 684 · Medium. A tree with n nodes (labelled 1..n) had one extra edge added. Given the n edges, return an edge whose removal leaves a tree; if several qualify, return the one that appears last.

Key insight: process edges in order with union-find. The first edge whose endpoints are already connected closes the only cycle. It is also the last cycle edge in the input, because the cycle is incomplete until its final edge arrives, so it satisfies the "last" tie-break.

class Solution {
    public int[] findRedundantConnection(int[][] edges) {
        int[] parent = new int[edges.length + 1];       // nodes are 1..n and there are n edges
        for (int i = 0; i < parent.length; i++) {
            parent[i] = i;
        }
        for (int[] e : edges) {
            int ra = find(parent, e[0]), rb = find(parent, e[1]);
            if (ra == rb) {
                return e;   // already connected: this edge closes the cycle, and it is the last such edge
            }
            parent[ra] = rb;
        }
        return new int[0];
    }

    private int find(int[] parent, int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];
            x = parent[x];
        }
        return x;
    }
}

Complexity: O(n · α(n)) time, O(n) space.

Edge cases: nodes are 1-indexed (array size n + 1); the extra edge might be the first or last in the list. Follow-up: the directed version (LeetCode 685) also has to handle a node with two parents, which union-find alone does not catch; check indegrees first.

8. Evaluate Division

LeetCode 399 · Medium · InMobi. You get equations like a / b = 2.0 and b / c = 3.0, then queries like a / c. Answer each query, or −1.0 if it cannot be determined.

Key insight: variables are nodes; a / b = v gives an edge a → b with weight v and b → a with weight 1 / v. The value of x / y is the product of weights along any path from x to y (the intermediate variables cancel: a/b · b/c = a/c). Unknown variables answer −1, even for x / x.

import java.util.ArrayDeque;
import java.util.Deque;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;

class Solution {
    public double[] calcEquation(List<List<String>> equations, double[] values, List<List<String>> queries) {
        Map<String, Map<String, Double>> graph = new HashMap<>();
        for (int i = 0; i < values.length; i++) {
            String a = equations.get(i).get(0), b = equations.get(i).get(1);
            graph.computeIfAbsent(a, k -> new HashMap<>()).put(b, values[i]);        // a / b = v
            graph.computeIfAbsent(b, k -> new HashMap<>()).put(a, 1.0 / values[i]);  // b / a = 1 / v
        }
        double[] out = new double[queries.size()];
        for (int i = 0; i < out.length; i++) {
            out[i] = ratio(graph, queries.get(i).get(0), queries.get(i).get(1));
        }
        return out;
    }

    // DFS from src multiplying edge weights; the product along any path src -> dst is src / dst.
    private double ratio(Map<String, Map<String, Double>> graph, String src, String dst) {
        if (!graph.containsKey(src) || !graph.containsKey(dst)) {
            return -1.0;                                  // unknown variable, even for x / x
        }
        Deque<String> nodes = new ArrayDeque<>();
        Deque<Double> products = new ArrayDeque<>();
        Set<String> seen = new HashSet<>();
        nodes.push(src);
        products.push(1.0);
        seen.add(src);
        while (!nodes.isEmpty()) {
            String node = nodes.pop();
            double product = products.pop();
            if (node.equals(dst)) {
                return product;
            }
            for (Map.Entry<String, Double> e : graph.get(node).entrySet()) {
                if (seen.add(e.getKey())) {
                    nodes.push(e.getKey());
                    products.push(product * e.getValue());
                }
            }
        }
        return -1.0;                                      // different components
    }
}

Complexity: O(Q · (V + E)) time for Q queries, O(V + E) space. With many queries, a weighted union-find (store each node's ratio to its root) answers each query in near-O(1): x / y = ratio(x) / ratio(y) when they share a root.

Edge cases: query variable never seen → −1; x / x for a known x → 1; variables in different components → −1; floating-point accumulation is fine at this scale (answers compared to 1e-5).

9. Detonate the Maximum Bombs

LeetCode 2101 · Medium · PhonePe. Each bomb has a position and a radius. Detonating a bomb detonates every bomb inside its circle, which chain-react. You may detonate one bomb; return the maximum number that explode.

Key insight: edges are directed: a big bomb can reach a small one that cannot reach it back. That is why union-find (which assumes symmetric connectivity) gives wrong answers here, and the most common mistake in this problem. Build the directed graph with a squared-distance check, then BFS from every bomb and take the largest reach.

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;

class Solution {
    public int maximumDetonation(int[][] bombs) {
        int n = bombs.length;
        List<List<Integer>> reach = new ArrayList<>();      // directed: i -> j if j lies inside i's radius
        for (int i = 0; i < n; i++) {
            reach.add(new ArrayList<>());
            for (int j = 0; j < n; j++) {
                long dx = bombs[i][0] - bombs[j][0], dy = bombs[i][1] - bombs[j][1], r = bombs[i][2];
                if (i != j && dx * dx + dy * dy <= r * r) {   // long: coordinates up to 10^5, squares overflow int
                    reach.get(i).add(j);
                }
            }
        }
        int best = 0;
        for (int start = 0; start < n; start++) {           // reachability is not symmetric: BFS from every bomb
            boolean[] seen = new boolean[n];
            Deque<Integer> queue = new ArrayDeque<>();
            seen[start] = true;
            queue.offer(start);
            int count = 1;
            while (!queue.isEmpty()) {
                for (int next : reach.get(queue.poll())) {
                    if (!seen[next]) {
                        seen[next] = true;
                        count++;
                        queue.offer(next);
                    }
                }
            }
            best = Math.max(best, count);
        }
        return best;
    }
}

Complexity: O(n²) to build the graph, O(n · (n + E)) = O(n³) worst case for the BFS runs; n ≤ 100 makes that about 10^6 operations.

Edge cases: squared distances overflow int (2 × (10^5)² = 2×10^10), so use long; comparing with Math.sqrt introduces floating-point error at the boundary; a bomb exactly on the circle edge counts; a single bomb → 1.

05Common mistakes and follow-ups interviewers ask

Mistakes that cost candidates the round
  • Marking visited on dequeue (duplicates in the queue, TLE on large grids).
  • Reversed edge direction in course problems ([a, b] means b before a).
  • Using union-find for directed reachability (Detonate Bombs).
  • Running a separate BFS from every source in a spreading problem instead of one multi-source BFS.
  • Recursive DFS on big grids in Java without mentioning stack overflow.
  • Not saying the complexity in terms of V and E, or for grids R·C.
Number of Islands: the grid is 10^6 × 10^6 and does not fit in memory. What now?

Stream it row by row with union-find over the current and previous row only: union land cells with their left and upper neighbours, and count components that close (no land below them) as you go. Memory O(columns). In a distributed setting, partition into tiles, solve each, then merge components across tile borders with union-find.

Number of Islands II: land is added one cell at a time; report the count after each addition.

Union-find over cells (id = r · cols + c). Adding a cell increments the count; each successful union with a land neighbour decrements it. O(k · α(RC)) for k additions; re-running BFS each time would be O(k · RC).

Kahn's algorithm vs DFS for topological sort: which do you prefer?

Kahn: iterative (no stack overflow), detects cycles by counting, naturally gives levels (parallel build stages). DFS: reverse post-order, needs three colours to detect cycles, recursion depth risk. In production (a build tool, a workflow DAG, migration ordering) I would use Kahn for the level information.

Course Schedule: return the minimum number of semesters if you can take any number of courses per semester.

Run Kahn level by level; the number of levels is the length of the longest path in the DAG, which is the answer. With a cap of k courses per semester (LeetCode 1494) it becomes NP-hard in general and the intended solution is bitmask DP for n ≤ 15.

Rotting Oranges: what if some oranges take 2 minutes to rot their neighbours?

Edges now have weights, so plain BFS breaks. Use 0-1 BFS for weights 0/1, or Dijkstra with a min-heap keyed on time. Multi-source still works: push every rotten orange at time 0.

Where does this show up in backend work?

Topological sort orders Flyway-style migrations, Spring bean initialisation and workflow DAGs (Airflow, Temporal). Union-find appears in deduplicating accounts that share an email or phone (LeetCode 721, Accounts Merge). BFS is the "degrees of separation" query in social graphs. Saying one of these shows you can map the pattern to systems.

06Self-check

Why does BFS find shortest paths in an unweighted graph but DFS does not?

BFS processes all nodes at distance d before any node at distance d + 1, so the first time it reaches a node is via a shortest path. DFS may reach a node first along a long path.

How does Kahn's algorithm detect a cycle?

Nodes on a cycle always have an incoming edge from another cycle node, so their indegree never reaches 0 and they are never polled. If the number of polled nodes is less than V, there is a cycle.

What do path compression and union by rank each fix?

Union by rank keeps trees shallow (O(log n) height) when merging; path compression flattens paths during find so repeated queries are fast. Together the amortised cost is O(α(n)).

Given a / b = 2 and b / c = 3, what is c / a, and which edges does the DFS use?

c → b with weight 1/3, then b → a with weight 1/2: c / a = 1/6 ≈ 0.1667.

Why can't Detonate the Maximum Bombs be solved with union-find?

Reachability is directed: bomb A reaching B does not mean B reaches A. Union-find merges symmetrically and would overcount.
