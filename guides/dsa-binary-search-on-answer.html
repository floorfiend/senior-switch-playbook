Binary Search on the Answer

When a problem asks for the smallest capacity, the fastest speed or the largest minimum gap, you usually do not search the array. You search the range of possible answers with a yes/no feasibility check. Plus the rotated-array searches that keep showing up at Swiggy and Walmart.

01When to use this pattern

Recognition phrases, roughly in order of how loudly they shout "binary search on the answer":

  • "Minimise the maximum…" (largest subarray sum, largest load per day, time for the slowest worker) and "maximise the minimum…" (smallest gap between placed items).
  • "Smallest capacity / speed / radius / time such that…" some process finishes within a limit.
  • The answer is an integer (or real) in a range you can bound, the input is up to 10^5 elements, and values go up to 10^9. That range is too big to try every value, but log₂(10^9) ≈ 30 tries is nothing.
  • Given a candidate answer x, you can check "is x good enough?" with a greedy pass in O(n), even though computing the best x directly looks hard (often a DP).
The one property you must state out loud

Monotonicity: if capacity x works, every capacity larger than x also works. Then feasible(x) over the answer range looks like false false false true true true, and you want the first true. Say this sentence in the interview; it is what the interviewer is listening for.

The second family on this page is rotated sorted arrays: the array is sorted and then rotated, so it is not globally sorted, but at every mid at least one half is sorted, which is enough to discard half the range.

02The mental model, from scratch

Classic binary search answers "where is value v in a sorted array?". Generalise it: you have any range [lo, hi] and a predicate that is false up to some point and true after it. Binary search finds the boundary in O(log(hi − lo)) predicate calls. The array is gone; the "array" is the answer space, and you evaluate each "element" by running a simulation.

  1. Define the answer (e.g. eating speed k).
  2. Write feasible(k): a greedy simulation that answers "can it be done with k?". It must be monotonic.
  3. Pick bounds: lo = an answer that is definitely the smallest possible (often max element, or 1), hi = an answer that definitely works (often sum, or max).
  4. Search for the first true with the template below.

Notice hi = mid (not mid − 1) when mid is feasible: mid might be the answer. And lo = mid + 1 when it is not: mid is ruled out. With lo < hi as the loop condition and mid rounded down, the range shrinks every iteration, so it always terminates with lo == hi = the first true.

Rotated arrays

Take [0,1,2,4,5,6,7] rotated to [4,5,6,7,0,1,2]. Pick any mid: either nums[lo..mid] or nums[mid..hi] is sorted. Compare with an endpoint to know which. For the minimum, compare nums[mid] with nums[hi]: if larger, the drop is to the right of mid.

03Java templates

Memorise these two. Almost every bug in binary search comes from mixing the loop condition, the mid rounding and the updates from different templates.

import java.util.function.LongPredicate;

class SearchTemplates {
    // FIRST TRUE: feasible is false...false true...true on [lo, hi] and feasible(hi) is true.
    // Returns the smallest x with feasible(x). O(log(hi - lo)) calls to feasible.
    static long firstTrue(long lo, long hi, LongPredicate feasible) {
        while (lo < hi) {
            long mid = lo + (hi - lo) / 2;      // never (lo + hi) / 2: it overflows near Long.MAX_VALUE
            if (feasible.test(mid)) {
                hi = mid;                       // mid works; the answer is mid or something smaller
            } else {
                lo = mid + 1;                   // mid fails; everything <= mid fails too
            }
        }
        return lo;
    }

    // LAST TRUE: ok is true...true false...false on [lo, hi] and ok(lo) is true.
    // Returns the largest x with ok(x). Note the upper-rounded mid.
    static long lastTrue(long lo, long hi, LongPredicate ok) {
        while (lo < hi) {
            long mid = lo + (hi - lo + 1) / 2;  // round up, otherwise lo = mid can loop forever
            if (ok.test(mid)) {
                lo = mid;
            } else {
                hi = mid - 1;
            }
        }
        return lo;
    }
}

Complexity: O(log(hi − lo)) predicate calls; with an O(n) predicate, O(n log R) total, O(1) extra space.

Overflow checklist
  • mid = lo + (hi - lo) / 2, never (lo + hi) / 2. (Java's own Arrays.binarySearch uses (low + high) >>> 1, which is also safe for non-negative ints.)
  • Accumulators inside feasible (total hours, sums) go in long: 10^5 elements × 10^9 overflows int.
  • Ceil division without overflow: (p - 1) / k + 1 for p ≥ 1, instead of (p + k - 1) / k.
  • Bounds that are sums: compute hi as long.

04Worked problems

1. Koko Eating Bananas

LeetCode 875 · Medium. There are piles of bananas and h hours. Each hour Koko picks one pile and eats up to k bananas from it. Find the minimum k that finishes all piles within h hours.

Key insight: hours needed is non-increasing in k, so hours(k) ≤ h is a monotonic predicate. Search k in [1, max(piles)]. The trace is in section 02.

class Solution {
    public int minEatingSpeed(int[] piles, int h) {
        int lo = 1, hi = 0;
        for (int p : piles) {
            hi = Math.max(hi, p);              // speed = max pile always finishes in n <= h hours
        }
        while (lo < hi) {                      // first speed where canFinish is true
            int mid = lo + (hi - lo) / 2;
            if (canFinish(piles, h, mid)) {
                hi = mid;
            } else {
                lo = mid + 1;
            }
        }
        return lo;
    }

    private boolean canFinish(int[] piles, int h, int speed) {
        long hours = 0;                        // long: up to 10^4 piles * 10^9 hours overflows int
        for (int p : piles) {
            hours += (p - 1) / speed + 1;      // ceil(p / speed), no overflow, no floating point
        }
        return hours <= h;
    }
}

Complexity: O(n log M) time where M = max pile, O(1) space.

Edge cases: h == number of piles → answer is max pile; one huge pile; total hours overflowing int when k is small (hence long).

2. Capacity To Ship Packages Within D Days

LeetCode 1011 · Medium. Packages must ship in the given order; each day the ship carries a prefix of what is left, up to its capacity. Find the minimum capacity that ships everything within days days.

Key insight: for a fixed capacity, greedy is optimal: load each day until the next package would overflow. Fewer days needed as capacity grows → monotonic. lo = heaviest package (anything smaller can never carry it), hi = total weight.

class Solution {
    public int shipWithinDays(int[] weights, int days) {
        int lo = 0, hi = 0;
        for (int w : weights) {
            lo = Math.max(lo, w);   // must carry the heaviest package
            hi += w;                // ship everything in one day
        }
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (daysNeeded(weights, mid) <= days) {
                hi = mid;
            } else {
                lo = mid + 1;
            }
        }
        return lo;
    }

    private int daysNeeded(int[] weights, int capacity) {
        int d = 1, load = 0;
        for (int w : weights) {
            if (load + w > capacity) {   // greedy: start a new day only when forced
                d++;
                load = 0;
            }
            load += w;
        }
        return d;
    }
}

Complexity: O(n log(sum)) time, O(1) space.

Edge cases: days == n (answer = max weight); days == 1 (answer = sum); forgetting lo = max lets the greedy produce a wrong day count for a capacity smaller than one package.

3. Split Array Largest Sum (= Book Allocation = Painter's Partition)

LeetCode 410 · Hard. Split an array into k non-empty contiguous parts to minimise the largest part sum. Book Allocation (allocate contiguous books to k students, minimise the maximum pages) and Painter's Partition (k painters, contiguous boards, minimise the time of the slowest) are the same problem with different nouns.

Key insight: identical to shipping packages, with "days" renamed k. Feasible(x) = "greedy cut into pieces with sum ≤ x needs at most k pieces". Needing fewer than k pieces is fine: you can always split a piece further without increasing the max (every element is ≤ x because lo starts at the max element).

class Solution {
    public int splitArray(int[] nums, int k) {
        long lo = 0, hi = 0;
        for (int x : nums) {
            lo = Math.max(lo, x);
            hi += x;
        }
        while (lo < hi) {
            long mid = lo + (hi - lo) / 2;
            if (piecesNeeded(nums, mid) <= k) {   // fewer pieces is fine: split further, the max only drops
                hi = mid;
            } else {
                lo = mid + 1;
            }
        }
        return (int) lo;
    }

    private int piecesNeeded(int[] nums, long maxSum) {
        int pieces = 1;
        long sum = 0;
        for (int x : nums) {
            if (sum + x > maxSum) {
                pieces++;
                sum = 0;
            }
            sum += x;
        }
        return pieces;
    }
}

Complexity: O(n log(sum)) time, O(1) space. The DP alternative is O(k · n²); mention it and why the search is better.

Edge cases: k == n (answer = max element); k == 1 (answer = sum); zeros in the array. In Book Allocation, return −1 when there are fewer books than students (each student must get at least one book); LeetCode guarantees k ≤ n.

4. Magnetic Force Between Two Balls (= Aggressive Cows)

LeetCode 1552 · Medium. Place m balls in baskets at given positions so that the minimum distance between any two balls is as large as possible. Return that distance. Aggressive Cows (place c cows in stalls, maximise the minimum distance) is the same problem.

Key insight: "maximise the minimum" → find the last gap d for which you can place all m balls with every adjacent pair ≥ d apart. Smaller gaps are easier, so the predicate is true … true false … false. The check is greedy after sorting: put a ball in the first basket and then in each basket at least d past the previous ball.

import java.util.Arrays;

class Solution {
    public int maxDistance(int[] position, int m) {
        Arrays.sort(position);
        int lo = 1, hi = (position[position.length - 1] - position[0]) / (m - 1);
        while (lo < hi) {                       // last distance where canPlace is true
            int mid = lo + (hi - lo + 1) / 2;   // round UP, or lo = mid loops forever
            if (canPlace(position, m, mid)) {
                lo = mid;
            } else {
                hi = mid - 1;
            }
        }
        return lo;
    }

    private boolean canPlace(int[] pos, int m, int gap) {
        int placed = 1, last = pos[0];          // greedy: always put the first ball in the first basket
        for (int i = 1; i < pos.length && placed < m; i++) {
            if (pos[i] - last >= gap) {
                placed++;
                last = pos[i];
            }
        }
        return placed >= m;
    }
}

Complexity: O(n log n) for the sort + O(n log R) for the search, O(log n) sort stack space.

Edge cases: m == 2 (answer = max − min); unsorted input (sort first, the most common bug); the up-rounded mid in last-true, without which lo = mid loops forever when hi = lo + 1.

5. Heaters

LeetCode 475 · Medium · Microsoft. Houses and heaters sit at integer positions on a line. All heaters share one radius r. Find the minimum r so every house is within r of some heater.

Key insight: a bigger radius covers everything a smaller one does → search r in [0, 10^9]. With both arrays sorted, coverage is one forward pass: for each house, skip heaters that are too far to its left (they are also too far for every later house), then check the current heater. An equally good direct answer: for each house, find its nearest heater with Arrays.binarySearch on sorted heaters and take the max of those distances. Say both; the interviewer often asks for the second as a follow-up.

import java.util.Arrays;

class Solution {
    public int findRadius(int[] houses, int[] heaters) {
        Arrays.sort(houses);
        Arrays.sort(heaters);
        int lo = 0, hi = 1_000_000_000;         // positions are in [1, 10^9]
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (coversAll(houses, heaters, mid)) {
                hi = mid;
            } else {
                lo = mid + 1;
            }
        }
        return lo;
    }

    // Both arrays sorted: one forward pass with a heater pointer, O(n + m).
    private boolean coversAll(int[] houses, int[] heaters, int r) {
        int j = 0;
        for (int house : houses) {
            while (j < heaters.length && (long) heaters[j] + r < house) {
                j++;                            // this heater is too far left for this and all later houses
            }
            if (j == heaters.length || (long) heaters[j] - r > house) {
                return false;
            }
        }
        return true;
    }
}

Complexity: O(n log n + m log m + (n + m) log R) time, O(log n) sort space.

Edge cases: a single heater; houses on both sides of all heaters; duplicates in either array; heaters[j] + r exceeding int when r ≈ 10^9 (cast to long).

6. Find Minimum in Rotated Sorted Array

LeetCode 153 · Medium · Swiggy (twice). A sorted array of distinct values was rotated an unknown number of times. Return its minimum in O(log n).

Key insight: compare nums[mid] with nums[hi], not nums[lo]. If nums[mid] > nums[hi] the rotation point is strictly right of mid; otherwise mid..hi is sorted and the minimum is at mid or left of it. Comparing with nums[lo] fails on an unrotated array. This is the first-true template with predicate nums[i] ≤ nums[last].

class Solution {
    public int findMin(int[] nums) {
        int lo = 0, hi = nums.length - 1;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] > nums[hi]) {   // the drop (and the minimum) is strictly right of mid
                lo = mid + 1;
            } else {                      // mid..hi is sorted, so mid could be the minimum
                hi = mid;
            }
        }
        return nums[lo];
    }
}

Complexity: O(log n) time, O(1) space.

Edge cases: not rotated (or rotated n times); one or two elements. Follow-up with duplicates (LeetCode 154): when nums[mid] == nums[hi] you cannot tell which side, so do hi--; worst case degrades to O(n) (e.g. [1,1,1,0,1]).

7. Search in Rotated Sorted Array

LeetCode 33 · Medium · Walmart. Same rotated array of distinct values; return the index of a target, or −1, in O(log n).

Key insight: at each mid, one half is sorted. Check whether nums[lo] ≤ nums[mid] (left sorted) or not (right sorted). If the target lies inside the sorted half's value range, search there; otherwise search the other half. Note ≤: when lo == mid the left half is one element and counts as sorted.

class Solution {
    public int search(int[] nums, int target) {
        int lo = 0, hi = nums.length - 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] == target) {
                return mid;
            }
            if (nums[lo] <= nums[mid]) {                          // left half lo..mid is sorted
                if (nums[lo] <= target && target < nums[mid]) {
                    hi = mid - 1;
                } else {
                    lo = mid + 1;
                }
            } else {                                              // right half mid..hi is sorted
                if (nums[mid] < target && target <= nums[hi]) {
                    lo = mid + 1;
                } else {
                    hi = mid - 1;
                }
            }
        }
        return -1;
    }
}

Complexity: O(log n) time, O(1) space.

Edge cases: one element; target at the rotation point; two elements [3,1] (the ≤ matters here). The alternative "find the pivot with problem 6, then binary search the right half" is two clean searches and perfectly acceptable.

05Common mistakes and follow-ups interviewers ask

Mistakes that cost candidates the round
  • Not stating why feasible is monotonic. Interviewers mark "pattern matched without understanding" when you cannot justify it.
  • Wrong lo: starting Ship Packages or Split Array at 0 or 1 instead of the max element, so the greedy silently accepts an impossible capacity.
  • Mixing templates: while (lo <= hi) with hi = mid loops forever; last-true with a down-rounded mid loops forever.
  • Integer overflow in the predicate's accumulator or in lo + hi.
  • Forgetting to sort in Aggressive Cows / Heaters.
  • Writing the O(n·k) DP for Split Array without first checking whether binary search on the answer applies.
Return the actual split (which books go to which student), not just the max.

Run the greedy once more with the final answer and record the cut points. If exactly k parts are required and the greedy made fewer, split the largest-count parts further; any split keeps every part ≤ the answer.

Koko: what if the answer can be a real number (eating speed in kg/hour)?

Binary search on doubles: loop a fixed number of times (e.g. 100) or until hi − lo < 1e-7, set lo = mid / hi = mid without ±1. A fixed iteration count avoids precision-dependent infinite loops.

Why does greedy give the minimum number of days for a fixed capacity?

Exchange argument: any optimal schedule can be transformed so day 1 takes as many packages as fit, without increasing the number of days, because moving a package from day 2 to day 1 never makes later days heavier. Induct on the remaining packages.

How would this look in production code rather than LeetCode?

Same shape as capacity planning: find the minimum number of Kafka partitions / pods such that a load simulation meets a p99 latency SLO. The simulation is the expensive predicate, so you minimise how many times you call it; that is exactly what binary search does (about 30 calls for a range of 10^9).

Search in a rotated array with duplicates (LeetCode 81)?

When nums[lo] == nums[mid] == nums[hi] you cannot tell which half is sorted; shrink both ends (lo++, hi--) and continue. Worst case O(n); say so.

Find the k-th smallest element in a sorted n×n matrix, or the k-th smallest pair distance.

Binary search on the value: feasible(x) = "count of elements ≤ x is at least k", counted in O(n) with a staircase walk (matrix) or two pointers on the sorted array (pair distances). Answer = first true.

06Self-check

What two things must be true before binary search on the answer applies?

The answer lies in a bounded ordered range, and the feasibility predicate is monotonic over it (once true, always true, or the reverse).

In first-true, why hi = mid and not hi = mid − 1?

mid passed the check, so it may be the answer; excluding it could skip the answer. The loop ends when lo == hi, which is then the first true.

Positions [1,2,8,4,9], m = 3. What is the largest minimum distance?

Sorted: 1,2,4,8,9. Gap 3: place at 1, 4, 8 → works. Gap 4: 1, 8 → only 2 balls. Answer 3.

In Find Minimum in Rotated Sorted Array, why compare with nums[hi] instead of nums[lo]?

If the array is not rotated, nums[mid] > nums[lo] would wrongly send you right. Comparing with nums[hi] tells you directly whether the drop is to the right of mid in every case.

What is the time complexity of Split Array Largest Sum with values up to 10^6 and n = 1000?

Sum ≤ 10^9, so about 30 iterations × O(n) = roughly 30,000 operations: O(n log(sum)).
