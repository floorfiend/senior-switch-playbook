Binary Search on the Answer

Spot "minimum capacity / maximum minimum gap" problems and solve them by binary searching the answer range with a yes/no check.

Study time: 1–2 sessions of 2 h Worked problems: 7 Seen: ~8 reports, 2025–26

In 30 seconds
  • Don't search the array; search the range of possible answers.
  • Write feasible(x): a greedy O(n) check "can it be done with x?".
  • It must be monotonic: false false … true true. Find the first true.
  • Cost: O(n · log range), about 30 passes for a range of 10^9.
Picture it

Booking a tempo to move house. You don't compute the perfect truck size; you ask "does a 1-tonne tempo fit everything?". No → try bigger. Yes → try smaller. Each answer rules out half the sizes.

01When to use this pattern

"Minimise the maximum"

Largest subarray sum, largest load per day, time of the slowest worker.

"Maximise the minimum"

Smallest gap between placed items (cows, balls, routers).

"Smallest capacity / speed such that…"

Some process must finish within a limit.

Big range, cheap check

n up to 10^5, values to 10^9. Trying every value is too slow; log₂(10^9) ≈ 30 tries is nothing.

Say this sentence out loud

"If capacity x works, every larger capacity works too." Then feasible looks like F F F T T T and you want the first T. Interviewers listen for it.

FFFTTT
Go deeper: recognition phrases in full
  • "Minimise the maximum…" (largest subarray sum, largest load per day, time for the slowest worker) and "maximise the minimum…" (smallest gap between placed items).
  • "Smallest capacity / speed / radius / time such that…" some process finishes within a limit.
  • The answer is an integer (or real) in a range you can bound, the input is up to 10^5 elements, and values go up to 10^9. That range is too big to try every value, but log₂(10^9) ≈ 30 tries is nothing.
  • Given a candidate answer x, you can check "is x good enough?" with a greedy pass in O(n), even though computing the best x directly looks hard (often a DP).

Monotonicity: if capacity x works, every capacity larger than x also works. Then feasible(x) over the answer range looks like false false false true true true, and you want the first true. Say this sentence in the interview; it is what the interviewer is listening for.

The second family on this page is rotated sorted arrays: the array is sorted and then rotated, so it is not globally sorted, but at every mid at least one half is sorted, which is enough to discard half the range.

Go deeper: the four steps and the trace table

Classic binary search answers "where is value v in a sorted array?". Generalise it: you have any range [lo, hi] and a predicate that is false up to some point and true after it. Binary search finds the boundary in O(log(hi − lo)) predicate calls. The array is gone; the "array" is the answer space, and you evaluate each "element" by running a simulation.

  1. Define the answer (e.g. eating speed k).
  2. Write feasible(k): a greedy simulation that answers "can it be done with k?". It must be monotonic.
  3. Pick bounds: lo = an answer that is definitely the smallest possible (often max element, or 1), hi = an answer that definitely works (often sum, or max).
  4. Search for the first true with the template below.

Hours at speed k = Σ ceil(pile / k). lo = 1, hi = 11 (at speed 11 every pile takes 1 hour, 4 ≤ 8).

Notice hi = mid (not mid − 1) when mid is feasible: mid might be the answer. And lo = mid + 1 when it is not: mid is ruled out. With lo < hi as the loop condition and mid rounded down, the range shrinks every iteration, so it always terminates with lo == hi = the first true.

05Java templates

First true minimise

  • mid = lo + (hi − lo) / 2
  • true → hi = mid
  • false → lo = mid + 1

Koko, ship packages, split array, heaters.

Last true maximise

  • mid = lo + (hi − lo + 1) / 2 (round up)
  • true → lo = mid
  • false → hi = mid − 1

Aggressive cows, magnetic force.

Most bugs come from mixing parts of the two templates.

Show Java solution: first-true and last-true templates
import java.util.function.LongPredicate;

class SearchTemplates {
    // FIRST TRUE: feasible is false...false true...true on [lo, hi] and feasible(hi) is true.
    // Returns the smallest x with feasible(x). O(log(hi - lo)) calls to feasible.
    static long firstTrue(long lo, long hi, LongPredicate feasible) {
        while (lo < hi) {
            long mid = lo + (hi - lo) / 2;      // never (lo + hi) / 2: it overflows near Long.MAX_VALUE
            if (feasible.test(mid)) {
                hi = mid;                       // mid works; the answer is mid or something smaller
            } else {
                lo = mid + 1;                   // mid fails; everything <= mid fails too
            }
        }
        return lo;
    }

    // LAST TRUE: ok is true...true false...false on [lo, hi] and ok(lo) is true.
    // Returns the largest x with ok(x). Note the upper-rounded mid.
    static long lastTrue(long lo, long hi, LongPredicate ok) {
        while (lo < hi) {
            long mid = lo + (hi - lo + 1) / 2;  // round up, otherwise lo = mid can loop forever
            if (ok.test(mid)) {
                lo = mid;
            } else {
                hi = mid - 1;
            }
        }
        return lo;
    }
}

Java's own Arrays.binarySearch uses (low + high) >>> 1, which is also safe for non-negative ints. Complexity: O(log(hi − lo)) predicate calls; with an O(n) predicate, O(n log R) total, O(1) extra space.

Overflow checklist
  • mid = lo + (hi - lo) / 2, never (lo + hi) / 2.
  • Accumulators inside feasible go in long: 10^5 × 10^9 overflows int.
  • Ceil division: (p - 1) / k + 1 for p ≥ 1, instead of (p + k - 1) / k.
  • Bounds that are sums: compute hi as long.

06Worked problems

1. Koko Eating Bananas LeetCode 875 · Medium ↗

Task
Each hour Koko eats up to k bananas from one pile. Minimum k that finishes all piles in h hours.
Insight
Hours needed only drops as k grows, so hours(k) ≤ h is monotonic. Search k in [1, max(piles)].
Cost
O(n log M) time where M = max pile, O(1) space
piles
36711
hours at k = 4 (total 8)
1223
Show Java solution
class Solution {
    public int minEatingSpeed(int[] piles, int h) {
        int lo = 1, hi = 0;
        for (int p : piles) {
            hi = Math.max(hi, p);              // speed = max pile always finishes in n <= h hours
        }
        while (lo < hi) {                      // first speed where canFinish is true
            int mid = lo + (hi - lo) / 2;
            if (canFinish(piles, h, mid)) {
                hi = mid;
            } else {
                lo = mid + 1;
            }
        }
        return lo;
    }

    private boolean canFinish(int[] piles, int h, int speed) {
        long hours = 0;                        // long: up to 10^4 piles * 10^9 hours overflows int
        for (int p : piles) {
            hours += (p - 1) / speed + 1;      // ceil(p / speed), no overflow, no floating point
        }
        return hours <= h;
    }
}
Edge cases

h == number of piles → answer is max pile; one huge pile; total hours overflowing int when k is small (hence long).

2. Capacity To Ship Packages Within D Days LeetCode 1011 · Medium ↗

Task
Ship packages in order; each day carries a prefix up to capacity. Minimum capacity for days days.
Insight
For a fixed capacity, greedy (load until the next one overflows) is optimal. lo = heaviest package, hi = total.
Cost
O(n log(sum)) time, O(1) space
weights 1..10, days = 5, capacity 15: one colour per day
12345678910
Show Java solution
class Solution {
    public int shipWithinDays(int[] weights, int days) {
        int lo = 0, hi = 0;
        for (int w : weights) {
            lo = Math.max(lo, w);   // must carry the heaviest package
            hi += w;                // ship everything in one day
        }
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (daysNeeded(weights, mid) <= days) {
                hi = mid;
            } else {
                lo = mid + 1;
            }
        }
        return lo;
    }

    private int daysNeeded(int[] weights, int capacity) {
        int d = 1, load = 0;
        for (int w : weights) {
            if (load + w > capacity) {   // greedy: start a new day only when forced
                d++;
                load = 0;
            }
            load += w;
        }
        return d;
    }
}
Edge cases

Fewer days needed as capacity grows → monotonic. days == n (answer = max weight); days == 1 (answer = sum); forgetting lo = max lets the greedy produce a wrong day count for a capacity smaller than one package.

3. Split Array Largest Sum (= Book Allocation = Painter's Partition) LeetCode 410 · Hard ↗

Task
Split into k contiguous parts to minimise the largest part sum. Book Allocation and Painter's Partition are the same problem with different nouns.
Insight
Ship packages with "days" renamed k. Needing fewer than k pieces is fine: splitting further never raises the max.
Cost
O(n log(sum)) time, O(1) space; the DP is O(k · n²)
[7,2,5,10,8], k = 2 → 18
725108
Show Java solution
class Solution {
    public int splitArray(int[] nums, int k) {
        long lo = 0, hi = 0;
        for (int x : nums) {
            lo = Math.max(lo, x);
            hi += x;
        }
        while (lo < hi) {
            long mid = lo + (hi - lo) / 2;
            if (piecesNeeded(nums, mid) <= k) {   // fewer pieces is fine: split further, the max only drops
                hi = mid;
            } else {
                lo = mid + 1;
            }
        }
        return (int) lo;
    }

    private int piecesNeeded(int[] nums, long maxSum) {
        int pieces = 1;
        long sum = 0;
        for (int x : nums) {
            if (sum + x > maxSum) {
                pieces++;
                sum = 0;
            }
            sum += x;
        }
        return pieces;
    }
}
Details and edge cases

Feasible(x) = "greedy cut into pieces with sum ≤ x needs at most k pieces". Needing fewer than k pieces is fine: you can always split a piece further without increasing the max (every element is ≤ x because lo starts at the max element). The DP alternative is O(k · n²); mention it and why the search is better.

k == n (answer = max element); k == 1 (answer = sum); zeros in the array. In Book Allocation, return −1 when there are fewer books than students (each student must get at least one book); LeetCode guarantees k ≤ n.

4. Magnetic Force Between Two Balls (= Aggressive Cows) LeetCode 1552 · Medium ↗

Task
Place m balls in baskets to make the minimum distance between any two as large as possible.
Insight
"Maximise the minimum" → last true gap. Sort, then greedily place each ball at the first basket ≥ d past the previous one.
Cost
O(n log n) sort + O(n log R) search
positions [1,2,3,4,7], m = 3 → gap 3
12347
Show Java solution
import java.util.Arrays;

class Solution {
    public int maxDistance(int[] position, int m) {
        Arrays.sort(position);
        int lo = 1, hi = (position[position.length - 1] - position[0]) / (m - 1);
        while (lo < hi) {                       // last distance where canPlace is true
            int mid = lo + (hi - lo + 1) / 2;   // round UP, or lo = mid loops forever
            if (canPlace(position, m, mid)) {
                lo = mid;
            } else {
                hi = mid - 1;
            }
        }
        return lo;
    }

    private boolean canPlace(int[] pos, int m, int gap) {
        int placed = 1, last = pos[0];          // greedy: always put the first ball in the first basket
        for (int i = 1; i < pos.length && placed < m; i++) {
            if (pos[i] - last >= gap) {
                placed++;
                last = pos[i];
            }
        }
        return placed >= m;
    }
}
Details and edge cases

Aggressive Cows (place c cows in stalls, maximise the minimum distance) is the same problem. Smaller gaps are easier, so the predicate is true … true false … false. The check is greedy after sorting: put a ball in the first basket and then in each basket at least d past the previous ball. Space: O(log n) sort stack.

m == 2 (answer = max − min); unsorted input (sort first, the most common bug); the up-rounded mid in last-true, without which lo = mid loops forever when hi = lo + 1.

5. Heaters LeetCode 475 · Medium ↗

Task
Minimum shared radius so every house is within r of a heater. Microsoft.
Insight
Bigger radius covers more → search r in [0, 10^9]. Check coverage in one forward pass over both sorted arrays.
Cost
O(n log n + m log m + (n + m) log R) time
houses 1..4, heaters at 1 and 4 → r = 1
1234
Show Java solution
import java.util.Arrays;

class Solution {
    public int findRadius(int[] houses, int[] heaters) {
        Arrays.sort(houses);
        Arrays.sort(heaters);
        int lo = 0, hi = 1_000_000_000;         // positions are in [1, 10^9]
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (coversAll(houses, heaters, mid)) {
                hi = mid;
            } else {
                lo = mid + 1;
            }
        }
        return lo;
    }

    // Both arrays sorted: one forward pass with a heater pointer, O(n + m).
    private boolean coversAll(int[] houses, int[] heaters, int r) {
        int j = 0;
        for (int house : houses) {
            while (j < heaters.length && (long) heaters[j] + r < house) {
                j++;                            // this heater is too far left for this and all later houses
            }
            if (j == heaters.length || (long) heaters[j] - r > house) {
                return false;
            }
        }
        return true;
    }
}
The direct answer and edge cases

For each house, skip heaters that are too far to its left (they are also too far for every later house), then check the current heater. An equally good direct answer: for each house, find its nearest heater with Arrays.binarySearch on sorted heaters and take the max of those distances. Say both; the interviewer often asks for the second as a follow-up. Space: O(log n) sort.

A single heater; houses on both sides of all heaters; duplicates in either array; heaters[j] + r exceeding int when r ≈ 10^9 (cast to long).

6. Find Minimum in Rotated Sorted Array LeetCode 153 · Medium ↗

Task
Minimum of a rotated sorted array of distinct values in O(log n). Swiggy (twice).
Insight
Compare nums[mid] with nums[hi], not nums[lo] (that fails on an unrotated array). See the stepper.
Cost
O(log n) time, O(1) space
4567012
Show Java solution
class Solution {
    public int findMin(int[] nums) {
        int lo = 0, hi = nums.length - 1;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] > nums[hi]) {   // the drop (and the minimum) is strictly right of mid
                lo = mid + 1;
            } else {                      // mid..hi is sorted, so mid could be the minimum
                hi = mid;
            }
        }
        return nums[lo];
    }
}
Edge cases and duplicates

If nums[mid] > nums[hi] the rotation point is strictly right of mid; otherwise mid..hi is sorted and the minimum is at mid or left of it.

Not rotated (or rotated n times); one or two elements. Follow-up with duplicates (LeetCode 154): when nums[mid] == nums[hi] you cannot tell which side, so do hi--; worst case degrades to O(n) (e.g. [1,1,1,0,1]).

7. Search in Rotated Sorted Array LeetCode 33 · Medium ↗

Task
Index of a target in the rotated array, or −1, in O(log n). Walmart.
Insight
One half is sorted (nums[lo] ≤ nums[mid] → left). If the target is in that half's range, go there; else go to the other half.
Cost
O(log n) time, O(1) space
target 0: left half 4..7 is sorted, 0 isn't in it → go right
4567012
Show Java solution
class Solution {
    public int search(int[] nums, int target) {
        int lo = 0, hi = nums.length - 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] == target) {
                return mid;
            }
            if (nums[lo] <= nums[mid]) {                          // left half lo..mid is sorted
                if (nums[lo] <= target && target < nums[mid]) {
                    hi = mid - 1;
                } else {
                    lo = mid + 1;
                }
            } else {                                              // right half mid..hi is sorted
                if (nums[mid] < target && target <= nums[hi]) {
                    lo = mid + 1;
                } else {
                    hi = mid - 1;
                }
            }
        }
        return -1;
    }
}
Edge cases

Note ≤: when lo == mid the left half is one element and counts as sorted. One element; target at the rotation point; two elements [3,1] (the ≤ matters here). The alternative "find the pivot with problem 6, then binary search the right half" is two clean searches and perfectly acceptable.

07Common mistakes

Mistakes that cost candidates the round
  • Not saying why feasible is monotonic: reads as "pattern matched without understanding".
  • Wrong lo: starting Ship Packages or Split Array at 0 or 1, so the greedy accepts an impossible capacity.
  • Mixing templates: while (lo <= hi) with hi = mid loops forever; so does last-true with a down-rounded mid.
  • Integer overflow in the accumulator or in lo + hi.
  • Forgetting to sort in Aggressive Cows / Heaters.
  • Jumping to the O(n·k) DP for Split Array.

08Interview questions

Return the actual split (which books go to which student), not just the max.

Run the greedy once more with the final answer and record the cut points. If exactly k parts are required and the greedy made fewer, split the largest-count parts further; any split keeps every part ≤ the answer.

Koko: what if the answer can be a real number (eating speed in kg/hour)?

Binary search on doubles: loop a fixed number of times (e.g. 100) or until hi − lo < 1e-7, set lo = mid / hi = mid without ±1. A fixed iteration count avoids precision-dependent infinite loops.

Why does greedy give the minimum number of days for a fixed capacity?

Exchange argument: any optimal schedule can be transformed so day 1 takes as many packages as fit, without increasing the number of days, because moving a package from day 2 to day 1 never makes later days heavier. Induct on the remaining packages.

How would this look in production code rather than LeetCode?

Same shape as capacity planning: find the minimum number of Kafka partitions / pods such that a load simulation meets a p99 latency SLO. The simulation is the expensive predicate, so you minimise how many times you call it; that is exactly what binary search does (about 30 calls for a range of 10^9).

Search in a rotated array with duplicates (LeetCode 81)?

When nums[lo] == nums[mid] == nums[hi] you cannot tell which half is sorted; shrink both ends (lo++, hi--) and continue. Worst case O(n); say so.

Find the k-th smallest element in a sorted n×n matrix, or the k-th smallest pair distance.

Binary search on the value: feasible(x) = "count of elements ≤ x is at least k", counted in O(n) with a staircase walk (matrix) or two pointers on the sorted array (pair distances). Answer = first true.

What two things must be true before binary search on the answer applies?

The answer lies in a bounded ordered range, and the feasibility predicate is monotonic over it (once true, always true, or the reverse).

In first-true, why hi = mid and not hi = mid − 1?

mid passed the check, so it may be the answer; excluding it could skip the answer. The loop ends when lo == hi, which is then the first true.

Positions [1,2,8,4,9], m = 3. What is the largest minimum distance?

Sorted: 1,2,4,8,9. Gap 3: place at 1, 4, 8 → works. Gap 4: 1, 8 → only 2 balls. Answer 3.

In Find Minimum in Rotated Sorted Array, why compare with nums[hi] instead of nums[lo]?

If the array is not rotated, nums[mid] > nums[lo] would wrongly send you right. Comparing with nums[hi] tells you directly whether the drop is to the right of mid in every case.

What is the time complexity of Split Array Largest Sum with values up to 10^6 and n = 1000?

Sum ≤ 10^9, so about 30 iterations × O(n) = roughly 30,000 operations: O(n log(sum)).

09Quick check

What must hold before binary search on the answer is valid?

The input need not be sorted (Koko's piles aren't). What you search is the answer range, and it needs an F…F T…T shape.

First-true template: feasible(mid) returns true. What next?

mid works, so it may be the answer. Keep it in range; the loop ends at lo == hi.

Last-true with mid = lo + (hi − lo) / 2 and lo = mid on success. lo = 3, hi = 4. What happens?

mid rounds down to 3; if it passes, lo stays 3 forever. Round up: lo + (hi − lo + 1) / 2.

Ship Packages: why is lo the heaviest package, not 1?

The greedy assumes every package fits. Smaller capacities give a wrong (too small) day count and a wrong answer.

10Cheat sheet

Cheat sheet
  • "Minimise the max" / "maximise the min" / "smallest speed such that" → search the answer.
  • State the monotonicity: if x works, every bigger x works.
  • feasible(x) = greedy O(n) simulation; accumulate in long.
  • First true: while (lo < hi), mid down, true → hi = mid, false → lo = mid + 1.
  • Last true: mid rounded up, true → lo = mid, false → hi = mid − 1.
  • Bounds: lo = could-be answer (often max element), hi = surely works (often sum).
  • Rotated min: compare with nums[hi]. Rotated search: find the sorted half, check the target range.
  • Cost: O(n log R) ≈ 30 passes for R = 10^9.
