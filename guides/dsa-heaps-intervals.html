Heaps and Intervals

Six techniques cover almost every interval or "top/median/rooms" question: sort and sweep, a min-heap of end times, two heaps for a running median, a difference array for capacity, sort + DP + binary search for weighted scheduling, and a size-K heap for top-K.

01When to use these patterns

The input is a list of [start, end] pairs, or a stream where you need "the best so far". Map the phrase in the problem to the tool:

Phrase in the problemToolCost
"merge overlapping", "insert interval", "remove the fewest to make non-overlapping"Sort by start (or end), sweep onceO(n log n)
"minimum rooms / platforms / servers", "max concurrent sessions"Sort by start + min-heap of end times (or sorted starts and ends with two pointers)O(n log n)
"median of a stream", "balance two halves"Two heaps: max-heap low half, min-heap high halfO(log n) add, O(1) query
"capacity never exceeded", "add k to every position in [l, r)", small coordinate rangeDifference array + prefix sumO(n + C)
"choose non-overlapping jobs to maximise profit"Sort by end, DP, binary search for the last compatible jobO(n log n)
"top K", "K closest", "K most frequent"Min-heap capped at K (or bucket sort / quickselect)O(n log K)
"book if no conflict", online inserts with overlap checkTreeMap floor/ceiling lookupsO(log n) per op
Decide the boundary rule first

Does [1,5] overlap [5,8]? In merge-intervals yes (they touch and merge). In meeting rooms and calendars the intervals are half-open [start, end), so a meeting ending at 5 frees the room for one starting at 5. Say this out loud in the interview; it decides < versus <=.

02The mental model, with traces

Sort and sweep

Once intervals are sorted by start, any interval can only overlap the block you are currently building, never an older one. So you keep one "current block" and either extend its end or close it and start a new one. One pass after the sort.

Min-heap of end times (counting rooms)

Process meetings in start order. The heap holds the end time of every occupied room. Before placing a meeting, every room whose end time is <= start is free. The smallest end time sits at the heap's root, so checking "is any room free?" is a peek(). The heap's size is the number of rooms in use; its maximum over the sweep is the answer.

Trace on [[0,30],[5,10],[15,20],[18,40],[31,35]]:

[15,20]10 <= 15reuse the room freed at 10{20, 30}2

Answer: 3. Note that at [31,35] two rooms are actually free (ends 20 and 30), but popping only one keeps the heap size equal to the peak so far, which is all the problem asks.

Two heaps (running median)

Split the numbers into a low half (max-heap, root = largest of the small numbers) and a high half (min-heap, root = smallest of the large numbers). Keep low.size() == high.size() or one more. The median is then low.peek() or the average of both roots. Trace adding 5, 15, 1, 3:

Addlow (max-heap)high (min-heap)Median
5{5}{}5

1{5, 1}{15}5
3{3, 1}{5, 15}4.0

Difference array

When coordinates are small integers (car pooling: 0..1000) you do not need a heap at all. Record +k where a range starts and -k where it ends; a running prefix sum then gives the load at every point. Trips [[2,1,5],[3,3,7]] give diff[1]=+2, diff[3]=+3, diff[5]=-2, diff[7]=-3, and the prefix sums are 2, 2, 5, 5, 3, 3, 0 at locations 1..7. With capacity 4, location 3 fails.

Weighted interval scheduling

Sort jobs by end time. dp[i] is the best profit using only the first i jobs. For job i you either skip it (dp[i-1]) or take it and add the best from jobs that end by its start. Those jobs form a prefix of the sorted array (ends are sorted), so a binary search finds its length k: dp[i] = max(dp[i-1], dp[k] + profit).

Sort by end→ For job ibinary search k = jobs ending ≤ start→ dp[i] = max(skip, dp[k] + p)→ dp[n]

Figure: the three steps of weighted interval scheduling. Greedy by earliest end works only when every job has the same weight.

Top-K with a heap

To keep the K largest, use a min-heap of size K. The root is the weakest of your current top K; any new item bigger than it evicts it. You never hold more than K items, so each step is O(log K), not O(log n).

03Java templates

All four templates compile as one class. Sweep and heap are O(n log n) time, O(n) space; the difference array is O(n + C) time and O(C) space; top-K is O(n log K) time and O(K) space.

import java.util.*;

class HeapTemplates {
    // 1. Sort by start, sweep, compare with the last kept interval. O(n log n).
    static List<int[]> sweep(int[][] iv) {
        Arrays.sort(iv, Comparator.comparingInt(a -> a[0]));
        List<int[]> kept = new ArrayList<>();
        for (int[] cur : iv) {
            int[] last = kept.isEmpty() ? null : kept.get(kept.size() - 1);
            if (last == null || last[1] < cur[0]) {
                kept.add(cur.clone());              // no overlap: start a new block
            } else {
                last[1] = Math.max(last[1], cur[1]); // overlap: extend the block
            }
        }
        return kept;
    }

    // 2. Max simultaneous intervals (rooms, CPUs, platforms). Min-heap of end times. O(n log n).
    static int maxOverlap(int[][] iv) {
        Arrays.sort(iv, Comparator.comparingInt(a -> a[0]));
        PriorityQueue<Integer> ends = new PriorityQueue<>();
        int best = 0;
        for (int[] cur : iv) {
            while (!ends.isEmpty() && ends.peek() <= cur[0]) {
                ends.poll();                         // these have finished before cur starts
            }
            ends.offer(cur[1]);
            best = Math.max(best, ends.size());
        }
        return best;
    }

    // 3. Difference array: many range additions, then one prefix-sum pass. O(n + C).
    static int maxLoad(int[][] ranges, int maxCoord) {     // ranges: {from, to, amount}, half-open [from, to)
        int[] diff = new int[maxCoord + 1];
        for (int[] r : ranges) {
            diff[r[0]] += r[2];
            diff[r[1]] -= r[2];
        }
        int load = 0;
        int best = 0;
        for (int d : diff) {
            load += d;
            best = Math.max(best, load);
        }
        return best;
    }

    // 4. Top-K largest: min-heap capped at k; root is the weakest survivor. O(n log k).
    static int[] topK(int[] values, int k) {
        PriorityQueue<Integer> heap = new PriorityQueue<>();
        for (int v : values) {
            heap.offer(v);
            if (heap.size() > k) {
                heap.poll();
            }
        }
        return heap.stream().mapToInt(Integer::intValue).toArray();
    }
}
Comparator hygiene

Use Integer.compare(a[0], b[0]) or Comparator.comparingInt, never a[0] - b[0]. Subtraction overflows when values span negative and large positive numbers, and the sort silently goes wrong.

04Worked problems

4.1 Merge Intervals

LeetCode 56: merge-intervals · Medium

Problem. Given a list of intervals, merge every group that overlaps (touching counts as overlapping) and return the merged list.

Key insight. After sorting by start, an interval overlaps the result only if it starts at or before the end of the last merged block.

import java.util.*;

class Solution {
    public int[][] merge(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
        List<int[]> out = new ArrayList<>();
        for (int[] cur : intervals) {
            if (out.isEmpty() || out.get(out.size() - 1)[1] < cur[0]) {
                out.add(new int[]{cur[0], cur[1]});
            } else {
                int[] last = out.get(out.size() - 1);
                last[1] = Math.max(last[1], cur[1]);
            }
        }
        return out.toArray(new int[0][]);
    }
}

Complexity. O(n log n) time for the sort, O(n) space for the output.

Edge cases. One interval; touching intervals [1,4],[4,5] merge to [1,5]; an interval fully inside another ([1,10],[2,3]) needs the Math.max, not a plain assignment.

4.2 Meeting Rooms II Premium

LeetCode 253: meeting-rooms-ii · Medium · Premium

Problem. Given meeting times [start, end), return the minimum number of conference rooms needed so no two overlapping meetings share a room.

Key insight. The min-heap of end times from section 02. When the earliest-ending room is free, reuse it; otherwise open a room. Heap size at the end equals the peak.

import java.util.*;

class Solution {
    public int minMeetingRooms(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
        PriorityQueue<Integer> ends = new PriorityQueue<>();   // end time of each busy room
        for (int[] m : intervals) {
            if (!ends.isEmpty() && ends.peek() <= m[0]) {
                ends.poll();                                   // reuse the room that frees up first
            }
            ends.offer(m[1]);
        }
        return ends.size();
    }
}

Complexity. O(n log n) time, O(n) space.

Alternative without a heap. Sort starts and ends separately. Walk the starts with pointer i; if starts[i] < ends[j] you need a room (rooms++), otherwise a meeting ended (j++) and its room is reused. Same complexity, smaller constants. Interviewers like hearing both.

Edge cases. Empty input returns 0; back-to-back meetings [1,5],[5,10] need one room because of <=.

4.3 Meeting Rooms III

LeetCode 2402: meeting-rooms-iii · Hard

Problem. Rooms 0..n-1. Meetings (unique starts) are assigned in start order to the lowest-numbered free room. If none is free, the meeting waits for the room that frees up first (lowest number on ties) and keeps its original duration. Return the room that hosted the most meetings (lowest number on ties).

Key insight. Two heaps: free room numbers (min by number) and busy rooms (min by end time, then number). Before each meeting, move every room whose end is <= start back to the free heap. If none is free, pop the earliest busy room and shift the meeting.

import java.util.*;

class Solution {
    public int mostBooked(int n, int[][] meetings) {
        Arrays.sort(meetings, (a, b) -> Integer.compare(a[0], b[0]));
        PriorityQueue<Integer> free = new PriorityQueue<>();                 // free room numbers
        for (int i = 0; i < n; i++) {
            free.offer(i);
        }
        // busy rooms as {endTime, room}; earliest end first, then lowest room number
        PriorityQueue<long[]> busy = new PriorityQueue<>(
            (x, y) -> x[0] != y[0] ? Long.compare(x[0], y[0]) : Long.compare(x[1], y[1]));
        int[] count = new int[n];
        for (int[] m : meetings) {
            long start = m[0];
            long duration = m[1] - m[0];
            while (!busy.isEmpty() && busy.peek()[0] <= start) {
                free.offer((int) busy.poll()[1]);
            }
            int room;
            long end;
            if (!free.isEmpty()) {
                room = free.poll();
                end = start + duration;
            } else {
                long[] first = busy.poll();                                  // wait for earliest room
                room = (int) first[1];
                end = first[0] + duration;                                   // delayed, same duration
            }
            count[room]++;
            busy.offer(new long[]{end, room});
        }
        int best = 0;
        for (int i = 1; i < n; i++) {
            if (count[i] > count[best]) {
                best = i;
            }
        }
        return best;
    }
}

Complexity. O(m log m + m log n) for m meetings, O(n + m) space.

Edge cases. Delayed meetings push end times beyond the input range, so store ends as long; tie-break the busy heap on room number or you pick the wrong room; release all rooms that are free by start (a while, not an if) so the lowest-numbered one is chosen.

4.4 Car Pooling Amazon ×2

LeetCode 1094: car-pooling · Medium

Problem. A car drives east only. Each trip is [passengers, from, to]; passengers board at from and leave at to. Return whether the car's capacity is ever exceeded.

Key insight. The first answer most people give is "sort by start, min-heap of (end, passengers), drop finished trips": O(n log n). Amazon asked for the O(N) follow-up in both reports: locations are bounded (0..1000), so a difference array removes the sort.

import java.util.*;

class Solution {
    public boolean carPooling(int[][] trips, int capacity) {
        int[] diff = new int[1001];                 // locations are 0..1000
        for (int[] t : trips) {
            diff[t[1]] += t[0];                     // passengers board at from
            diff[t[2]] -= t[0];                     // and leave at to (not on board at 'to')
        }
        int load = 0;
        for (int d : diff) {
            load += d;
            if (load > capacity) {
                return false;
            }
        }
        return true;
    }
}

Complexity. O(n + C) time with C = 1001, O(C) space. If coordinates were up to 109, you would fall back to a TreeMap<Integer, Integer> of deltas (O(n log n)) or sort the events.

Edge cases. Drop-off and pick-up at the same location: the -k at to and +k at the next from land in the same cell, so they cancel correctly. A single trip larger than capacity fails immediately.

4.5 My Calendar I Uber

LeetCode 729: my-calendar-i · Medium

Problem. Implement book(start, end) on half-open intervals: accept and store it if it does not overlap any accepted booking, otherwise reject.

Key insight. Store accepted bookings in a TreeMap keyed by start. Since accepted bookings never overlap, only two neighbours matter: the booking that starts at or before the new start (must end by start) and the one that starts at or after it (must start at or after end).

import java.util.*;

class MyCalendar {
    private final TreeMap<Integer, Integer> bookings = new TreeMap<>();   // start -> end

    public MyCalendar() {
    }

    public boolean book(int start, int end) {
        Map.Entry<Integer, Integer> prev = bookings.floorEntry(start);     // latest start <= start
        if (prev != null && prev.getValue() > start) {
            return false;
        }
        Integer next = bookings.ceilingKey(start);                         // earliest start >= start
        if (next != null && next < end) {
            return false;
        }
        bookings.put(start, end);
        return true;
    }
}

Complexity. O(log n) per booking, O(n) space. The O(n) list scan is fine to mention as a first step but expect "do better".

Edge cases. Booking [20,30) right after [10,20) succeeds. Uber-style follow-up: make it thread-safe for a real booking service. The simple answer is a synchronized book; the senior answer is that in production the check-and-insert belongs in the database (an exclusion constraint on a range type in Postgres, or a row lock on the resource) so two app instances cannot double-book.

4.6 Find Median from Data Stream Amazon ×2 Uber Walmart Intuit

LeetCode 295: find-median-from-data-stream · Hard

Problem. Support addNum(num) and findMedian() over all numbers seen so far.

Key insight. The two-heap split from section 02. The add routine always passes the number through low into high, then rebalances, which keeps every value in low <= every value in high without comparing roots by hand.

import java.util.*;

class MedianFinder {
    private final PriorityQueue<Integer> low = new PriorityQueue<>(Collections.reverseOrder()); // max-heap
    private final PriorityQueue<Integer> high = new PriorityQueue<>();                          // min-heap

    public MedianFinder() {
    }

    public void addNum(int num) {
        low.offer(num);
        high.offer(low.poll());              // largest of the low half moves up
        if (high.size() > low.size()) {
            low.offer(high.poll());          // keep low.size() == high.size() or one more
        }
    }

    public double findMedian() {
        if (low.size() > high.size()) {
            return low.peek();
        }
        return (low.peek() + (long) high.peek()) / 2.0;
    }
}

Complexity. addNum O(log n), findMedian O(1), O(n) space.

Edge cases. Two copies of Integer.MAX_VALUE: summing as int overflows, hence the (long) cast. Duplicates are fine in PriorityQueue (unlike a TreeSet).

Follow-ups asked. All numbers in [0, 100]: use a 101-slot count array and walk it, O(100) per query. 99% in [0, 100]: count array plus two overflow counters (below 0, above 100); the median almost always lands in the array. Sliding-window median: two heaps with lazy deletion (a map of "to be removed" counts) or two TreeMap multisets.

4.7 Maximum Profit in Job Scheduling Google ×2 Salesforce

LeetCode 1235: maximum-profit-in-job-scheduling · Hard

Problem. Each job has a start, end and profit. Pick jobs with no overlap (a job may start exactly when another ends) to maximise total profit.

Key insight. Weighted interval scheduling: sort by end, DP over prefixes, binary search for how many jobs end by the current start.

import java.util.*;

class Solution {
    public int jobScheduling(int[] startTime, int[] endTime, int[] profit) {
        int n = startTime.length;
        int[][] jobs = new int[n][];
        for (int i = 0; i < n; i++) {
            jobs[i] = new int[]{startTime[i], endTime[i], profit[i]};
        }
        Arrays.sort(jobs, (a, b) -> Integer.compare(a[1], b[1]));      // by end time
        int[] dp = new int[n + 1];                                      // dp[i] = best using first i jobs
        for (int i = 1; i <= n; i++) {
            int[] job = jobs[i - 1];
            int k = lastEndingBy(jobs, i - 1, job[0]);                  // jobs[0..k) end <= start
            dp[i] = Math.max(dp[i - 1], dp[k] + job[2]);
        }
        return dp[n];
    }

    // number of jobs among jobs[0..hi) whose end <= t (upper bound on end time)
    private int lastEndingBy(int[][] jobs, int hi, int t) {
        int lo = 0;
        while (lo < hi) {
            int mid = (lo + hi) >>> 1;
            if (jobs[mid][1] <= t) {
                lo = mid + 1;
            } else {
                hi = mid;
            }
        }
        return lo;
    }
}

Complexity. O(n log n) time, O(n) space.

Trace on starts [1,2,3,3], ends [3,4,5,6], profits [50,10,40,70]: dp = 0, 50, 50, 90, 120. The last job (3–6, 70) has k = 1 (only the 1–3 job ends by 3), so 50 + 70 = 120.

Edge cases. Use upper bound (end <= start) so a job ending exactly at the start counts; several jobs with the same end; worst-case total 5·104 × 104 = 5·108 fits in int, but say you checked.

4.8 Top K Frequent Elements

LeetCode 347: top-k-frequent-elements · Medium

Problem. Return the K values that appear most often in the array; any order is accepted and the answer is unique.

Key insight. Count with a HashMap, then keep a min-heap of K entries ordered by count.

import java.util.*;

class Solution {
    public int[] topKFrequent(int[] nums, int k) {
        Map<Integer, Integer> freq = new HashMap<>();
        for (int x : nums) {
            freq.merge(x, 1, Integer::sum);
        }
        // min-heap by frequency, capped at k: the root is the weakest of the current top k
        PriorityQueue<Map.Entry<Integer, Integer>> heap =
            new PriorityQueue<>((a, b) -> Integer.compare(a.getValue(), b.getValue()));
        for (Map.Entry<Integer, Integer> e : freq.entrySet()) {
            heap.offer(e);
            if (heap.size() > k) {
                heap.poll();
            }
        }
        int[] out = new int[k];
        for (int i = k - 1; i >= 0; i--) {
            out[i] = heap.poll().getKey();
        }
        return out;
    }
}

Complexity. O(n + u log K) time where u is the number of distinct values, O(u) space.

Follow-up: better than n log K. Bucket sort: an array of lists indexed by frequency (0..n), walked from the top until K values are collected, is O(n). Quickselect on the distinct values is O(u) average. For a stream that never ends (trending hashtags), see the Count-Min Sketch discussion in Top-K Trending.

Edge cases. K equals the number of distinct values; all elements identical.

05Common mistakes and follow-ups interviewers ask

Mistakes that cost the round
  • Not asking whether endpoints are inclusive, then fixing < versus <= by trial and error.
  • Sorting by start for weighted scheduling. The DP needs ends sorted so "jobs that finish by t" is a prefix.
  • Using a max-heap for top-K largest and polling K times. It works but costs O(n log n) and O(n) memory; the interviewer wants the size-K min-heap.
  • Comparator by subtraction (a[0] - b[0]) and overflow.
  • For the median, forgetting that PriorityQueue is a min-heap by default; the low half needs Collections.reverseOrder().
Why is greedy-by-earliest-end correct for unweighted scheduling but not here?

With equal weights, finishing earliest leaves the most room for the rest, and an exchange argument proves it optimal. With weights, one long valuable job can beat two short cheap ones, so you must compare "take" and "skip" for each job, which is the DP.

Merge intervals arrive as a stream. How do you keep them merged?

Keep a TreeMap<start, end> of disjoint intervals. On insert, find the floor entry, merge forward while the next start is <= the new end, and remove the absorbed entries. Amortised O(log n) per insert (LeetCode 352, Data Stream as Disjoint Intervals).

Can you find the minimum rooms without a heap?

Yes: sort starts and ends separately and sweep two pointers, or emit +1/−1 events and track the running maximum. Both are O(n log n); the event version extends naturally to "which time had the peak".

Median of a huge stream that does not fit in memory?

Exact median needs all the data. In practice you approximate: bucketed histograms if the range is known, or quantile sketches such as t-digest (used by Elasticsearch percentiles and many metrics systems). Mention the error bound you accept.

Top-K across many servers?

Each node computes a local top-K with counts; a coordinator merges them. That is exact only if you send full counts; with local top-K lists you can miss an item that is moderately frequent everywhere. Production systems use Count-Min Sketch plus a heap and accept small error.

06Self-check

1. For top-K largest, why a min-heap and not a max-heap?

The min-heap's root is the smallest of the current K candidates, the one to evict when something bigger arrives. Size stays K, so each operation is O(log K).

2. What is diff after adding 3 to positions [2, 5) in an array of size 8, and what are the prefix sums?

diff[2] = +3, diff[5] = -3. Prefix sums: 0, 0, 3, 3, 3, 0, 0, 0.

3. In MedianFinder, which heap holds the extra element when the count is odd, and what is the median then?

low (the max-heap) holds one extra; the median is low.peek().

4. In weighted job scheduling, why binary search with upper bound (<=)?

A job that ends exactly at the current start is compatible, so you want the count of jobs with end <= start, which is the first index with end > start.

5. Meeting Rooms III: why must end times be long?

Delayed meetings start at the previous end, so ends accumulate: up to 105 meetings of length up to 5·105 can exceed Integer.MAX_VALUE.
