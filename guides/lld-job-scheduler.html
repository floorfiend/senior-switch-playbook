In-Process Job / Task Scheduler

Three prompts share one skeleton: a background job queue with leases and retries (Razorpay), a dependency-aware task runner with priorities and cycle detection (Media.net), and a ScheduledExecutorService built from scratch (Uber, Goldman Sachs, Rubrik). A senior answer has an explicit state machine, one place where state changes under a lock, lease tokens that stop stale workers, backoff with jitter, and tests that actually exercise concurrency.

01What the interviewer is grading

Razorpay's June 2026 agentic round is the clearest spec in the reports: build an in-process background job service ("a minimal Sidekiq / Celery / SQS-with-workers") with submit(job_spec) -> job_id, priority 0–9, max_retries, workers registering for job types and pulling jobs under a lease (visibility timeout) that they must renew, and the lifecycle pending → claimed → succeeded | failed (DLQ) | retry_scheduled → pending, with lease expiry returning claimed jobs to pending. Process rules: write PLAN.md first and walk the interviewer through it, commit incrementally (the git log is a deliverable), "no done without green tests", tests must exercise concurrency, and an extension arrives around minute 70. The candidate finished everything and was still rejected; their own read was that how you drive the agent (plan, parallelise, verify) is graded as much as the result.

Media.net's version (Nov 2025) asked for dependencies, priority, retry after failure (5 attempts), cancel, parallel execution, history and circular-dependency protection; the candidate could not get the code running and expected a reject. Walmart's SDE-III round wanted one-time and recurring jobs, status, retry, cancel, multiple workers and priority, and discussed PriorityBlockingQueue vs DelayQueue and exponential backoff with jitter.

State machine

Every transition named and guarded; illegal ones throw. Draw it before coding.

Correct under concurrency

Two workers never hold the same job; a stale worker cannot complete a job it lost.

Failure semantics

At-least-once stated plainly; idempotent handlers; backoff with jitter; DLQ.

Testability

Injected clock and random; no Thread.sleep in tests except the explicit concurrency test.

Observability

Queue depth per state, oldest pending age, DLQ size, stuck (expired-lease) count.

Process (agentic rounds)

Plan first, small commits, tests as the unit of progress, absorb the minute-70 extension cleanly.

02Clarifying questions to ask

QuestionWhy it matters
Delivery guarantee: at-least-once or at-most-once?At-least-once (leases + redelivery) forces idempotent handlers. Exactly-once is not achievable in general; say so.
Does lease expiry count as a failed attempt?If not, a job that crashes its worker every time loops forever (poison job).
Priority semantics: strict, or with ageing?Strict priority starves low-priority jobs under sustained load.
Within one priority: FIFO?Needs a sequence number tie-breaker; PriorityQueue is not stable.
Backoff formula and cap?Exponential with full jitter, capped; make base and cap configurable.
Can a running job be cancelled?Cooperative cancel (flag + interrupt) vs only cancelling queued jobs.
Dependencies: if a parent fails permanently, what happens to children?Usually mark them SKIPPED / UPSTREAM_FAILED transitively.
Recurring jobs: fixed rate or fixed delay? Overlap allowed?Fixed rate can pile up if the job is slower than the period.

03Requirements

Functional

  • submit(spec) returns id; spec has type, payload, priority, maxRetries, optional runAt and dependsOn.
  • Workers register types; claim leases the highest-priority due job of those types.
  • renew, complete, fail take the lease token.
  • Retry with backoff; DLQ after retries are exhausted; redrive from DLQ.
  • Cancel; status and history per job; queue stats.

Non-functional

  • No job held by two live leases.
  • O(log n) claim; no busy-waiting.
  • Graceful shutdown: stop claiming, finish or release in-flight jobs.
  • Deterministic tests via Clock and seeded RandomGenerator.

Out of scope (say so)

  • Persistence and multi-process workers (describe the Postgres SKIP LOCKED or SQS version instead).
  • Exactly-once side effects.
  • Cron expression parsing (accept a fixed period).

Patterns and why. State pattern as an enum with an allowed-transitions table: small, explicit and easy to test. Strategy for backoff and for handlers (a registry Map<String, JobHandler> keyed by type). Producer-consumer with a monitor (ReentrantLock + Condition) so idle workers sleep until a job is due instead of polling. Lease plus fencing token, the same idea as SQS's visibility timeout and receipt handle.

05Core code

Model

public enum JobState {
    PENDING, CLAIMED, SUCCEEDED, RETRY_SCHEDULED, FAILED, CANCELLED;

    private static final Map<JobState, Set<JobState>> ALLOWED = Map.of(
        PENDING, EnumSet.of(CLAIMED, CANCELLED),
        CLAIMED, EnumSet.of(SUCCEEDED, RETRY_SCHEDULED, FAILED, PENDING),   // PENDING = lease expired
        RETRY_SCHEDULED, EnumSet.of(PENDING, CANCELLED),
        SUCCEEDED, EnumSet.noneOf(JobState.class),
        FAILED, EnumSet.of(PENDING),                                         // redrive from DLQ
        CANCELLED, EnumSet.noneOf(JobState.class));

    boolean canMoveTo(JobState next) { return ALLOWED.get(this).contains(next); }
}

public record JobSpec(String type, Object payload, int priority, int maxRetries, Instant runAt) {
    public JobSpec {
        if (priority < 0 || priority > 9) throw new IllegalArgumentException("priority 0-9");
        if (maxRetries < 0) throw new IllegalArgumentException("maxRetries >= 0");
    }
    public static JobSpec of(String type, Object payload) { return new JobSpec(type, payload, 5, 3, null); }
}

public final class Job {
    final String id;
    final JobSpec spec;
    final long seq;                 // FIFO tie-break within a priority
    JobState state = JobState.PENDING;
    int attempts;
    Instant runAt;
    long leaseToken;
    Instant leaseExpiresAt;
    String lastError;
    final List<String> history = new ArrayList<>();

    Job(String id, JobSpec spec, long seq, Instant now) {
        this.id = id; this.spec = spec; this.seq = seq;
        this.runAt = spec.runAt() == null ? now : spec.runAt();
    }

    void moveTo(JobState next, Instant at, String note) {
        if (!state.canMoveTo(next)) throw new IllegalStateException(id + ": " + state + " -> " + next);
        history.add(at + " " + state + "->" + next + (note == null ? "" : " " + note));
        state = next;
    }
}

public record Lease(String jobId, long token, Instant expiresAt, String type, Object payload, int attempt) {}

The queue: one lock, three indexes, lazy cleanup

All transitions happen under one ReentrantLock. Priority queues are cleaned lazily: an entry whose job is no longer in the expected state is skipped when polled, which makes cancel and lease renewal O(1).

public final class JobQueue {
    private record LeaseEntry(Instant expiresAt, String jobId, long token) {}

    private static final Comparator<Job> BY_PRIORITY =
        Comparator.comparingInt((Job j) -> -j.spec.priority()).thenComparingLong(j -> j.seq);

    private final ReentrantLock lock = new ReentrantLock();
    private final Condition changed = lock.newCondition();
    private final Map<String, Job> jobs = new HashMap<>();
    private final Map<String, PriorityQueue<Job>> ready = new HashMap<>();          // per type
    private final PriorityQueue<Job> delayed = new PriorityQueue<>(Comparator.comparing((Job j) -> j.runAt));
    private final PriorityQueue<LeaseEntry> leases = new PriorityQueue<>(Comparator.comparing(LeaseEntry::expiresAt));
    private final Deque<Job> dlq = new ArrayDeque<>();
    private final AtomicLong seq = new AtomicLong();
    private final AtomicLong tokens = new AtomicLong();
    private final Clock clock;
    private final BackoffPolicy backoff;

    public JobQueue(Clock clock, BackoffPolicy backoff) { this.clock = clock; this.backoff = backoff; }

    public String submit(JobSpec spec) {
        lock.lock();
        try {
            Instant now = clock.instant();
            Job job = new Job(UUID.randomUUID().toString(), spec, seq.incrementAndGet(), now);
            jobs.put(job.id, job);
            job.history.add(now + " submitted");
            if (job.runAt.isAfter(now)) delayed.add(job); else readyFor(spec.type()).add(job);
            changed.signalAll();
            return job.id;
        } finally { lock.unlock(); }
    }

    /** Blocks up to maxWait for a due job of one of the given types. */
    public Optional<Lease> claim(Set<String> types, Duration leaseFor, Duration maxWait) throws InterruptedException {
        long remaining = maxWait.toNanos();
        lock.lock();
        try {
            while (true) {
                Instant now = clock.instant();
                promoteDue(now);
                Job best = pollBest(types);
                if (best != null) {
                    best.attempts++;
                    best.leaseToken = tokens.incrementAndGet();
                    best.leaseExpiresAt = now.plus(leaseFor);
                    best.moveTo(JobState.CLAIMED, now, "attempt " + best.attempts);
                    leases.add(new LeaseEntry(best.leaseExpiresAt, best.id, best.leaseToken));
                    return Optional.of(new Lease(best.id, best.leaseToken, best.leaseExpiresAt,
                            best.spec.type(), best.spec.payload(), best.attempts));
                }
                if (remaining <= 0) return Optional.empty();
                // Sleep until the next retry or lease expiry is due, or until signalled, whichever is first.
                remaining = changed.awaitNanos(Math.min(remaining, nanosUntilNextDue(now)));
            }
        } finally { lock.unlock(); }
    }

    public void renew(String jobId, long token, Duration extendBy) {
        withLease(jobId, token, job -> {
            job.leaseExpiresAt = clock.instant().plus(extendBy);
            leases.add(new LeaseEntry(job.leaseExpiresAt, job.id, token));   // old entry ignored lazily
        });
    }

    public void complete(String jobId, long token) {
        withLease(jobId, token, job -> job.moveTo(JobState.SUCCEEDED, clock.instant(), null));
    }

    public void fail(String jobId, long token, String error) {
        withLease(jobId, token, job -> { job.lastError = error; retryOrDeadLetter(job, clock.instant(), error); });
    }

    public boolean cancel(String jobId) {
        lock.lock();
        try {
            Job job = jobs.get(jobId);
            if (job == null || !job.state.canMoveTo(JobState.CANCELLED)) return false;
            job.moveTo(JobState.CANCELLED, clock.instant(), null);   // queue entries are skipped lazily
            return true;
        } finally { lock.unlock(); }
    }

    // ---- internals, all called with lock held ----

    private void withLease(String jobId, long token, Consumer<Job> action) {
        lock.lock();
        try {
            Job job = jobs.get(jobId);
            // Fencing: a worker whose lease expired and was re-issued holds an old token.
            if (job == null || job.state != JobState.CLAIMED || job.leaseToken != token)
                throw new StaleLeaseException(jobId);
            action.accept(job);
            changed.signalAll();
        } finally { lock.unlock(); }
    }

    private void retryOrDeadLetter(Job job, Instant now, String reason) {
        if (job.attempts > job.spec.maxRetries()) {
            job.moveTo(JobState.FAILED, now, reason);
            dlq.add(job);
        } else {
            job.runAt = now.plus(backoff.delay(job.attempts));
            job.moveTo(JobState.RETRY_SCHEDULED, now, reason + ", retry at " + job.runAt);
            delayed.add(job);
        }
    }

    private void promoteDue(Instant now) {
        while (!delayed.isEmpty() && !delayed.peek().runAt.isAfter(now)) {
            Job j = delayed.poll();
            if (j.state == JobState.RETRY_SCHEDULED) j.moveTo(JobState.PENDING, now, null);
            if (j.state == JobState.PENDING) readyFor(j.spec.type()).add(j);
        }
        while (!leases.isEmpty() && !leases.peek().expiresAt().isAfter(now)) {
            LeaseEntry e = leases.poll();
            Job j = jobs.get(e.jobId());
            boolean live = j.state == JobState.CLAIMED && j.leaseToken == e.token()
                    && !j.leaseExpiresAt.isAfter(now);                       // not renewed since
            if (!live) continue;
            if (j.attempts > j.spec.maxRetries()) {                          // poison job: crashes every worker
                j.moveTo(JobState.FAILED, now, "lease expired, retries exhausted");
                dlq.add(j);
            } else {
                j.moveTo(JobState.PENDING, now, "lease expired");
                readyFor(j.spec.type()).add(j);
            }
        }
    }

    private Job pollBest(Set<String> types) {
        Job best = null;
        PriorityQueue<Job> from = null;
        for (String t : types) {
            PriorityQueue<Job> q = ready.get(t);
            if (q == null) continue;
            while (!q.isEmpty() && q.peek().state != JobState.PENDING) q.poll();   // drop cancelled
            if (!q.isEmpty() && (best == null || BY_PRIORITY.compare(q.peek(), best) < 0)) { best = q.peek(); from = q; }
        }
        return best == null ? null : from.poll();
    }

    private long nanosUntilNextDue(Instant now) {
        Instant next = Stream.of(delayed.peek() == null ? null : delayed.peek().runAt,
                                 leases.peek() == null ? null : leases.peek().expiresAt())
                .filter(Objects::nonNull).min(Comparator.naturalOrder()).orElse(now.plus(Duration.ofSeconds(1)));
        return Math.max(1, Duration.between(now, next).toNanos());
    }

    private PriorityQueue<Job> readyFor(String type) {
        return ready.computeIfAbsent(type, t -> new PriorityQueue<>(BY_PRIORITY));
    }
}

One lock is a deliberate simplification: every operation is O(log n) in memory, so a single lock handles hundreds of thousands of operations per second. If asked, stripe by job type.

Backoff with full jitter

public interface BackoffPolicy { Duration delay(int attempt); }

public record ExponentialFullJitter(Duration base, Duration cap, RandomGenerator random) implements BackoffPolicy {
    public Duration delay(int attempt) {
        long ceiling = Math.min(cap.toMillis(), base.toMillis() * (1L << Math.min(attempt, 20)));  // no overflow
        return Duration.ofMillis(random.nextLong(ceiling + 1));    // uniform in [0, ceiling]
    }
}

Worker with lease renewal

public final class Worker implements Runnable {
    private final JobQueue queue;
    private final Map<String, JobHandler> handlers;
    private final Duration leaseFor;
    private final ScheduledExecutorService renewer;
    private volatile boolean running = true;

    public Worker(JobQueue q, Map<String, JobHandler> handlers, Duration leaseFor, ScheduledExecutorService renewer) {
        this.queue = q; this.handlers = handlers; this.leaseFor = leaseFor; this.renewer = renewer;
    }

    @Override
    public void run() {
        while (running && !Thread.currentThread().isInterrupted()) {
            Optional<Lease> claimed;
            try {
                claimed = queue.claim(handlers.keySet(), leaseFor, Duration.ofSeconds(1));
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                return;
            }
            claimed.ifPresent(this::execute);
        }
    }

    private void execute(Lease lease) {
        long every = leaseFor.toMillis() / 3;     // renew well before expiry
        ScheduledFuture<?> heartbeat = renewer.scheduleAtFixedRate(
                () -> queue.renew(lease.jobId(), lease.token(), leaseFor), every, every, TimeUnit.MILLISECONDS);
        try {
            handlers.get(lease.type()).handle(lease);
            queue.complete(lease.jobId(), lease.token());
        } catch (StaleLeaseException e) {
            // Lease was lost (GC pause, slow handler). Another worker owns the job now; drop our result.
        } catch (Exception e) {
            try { queue.fail(lease.jobId(), lease.token(), e.toString()); } catch (StaleLeaseException ignored) { }
        } finally {
            heartbeat.cancel(false);
        }
    }

    public void stop() { running = false; }
}

Media.net variant: dependency DAG with priority and cycle detection

public final class TaskGraph {
    private final Map<String, Task> tasks = new HashMap<>();
    private final Map<String, Set<String>> dependents = new HashMap<>();

    /** Rejects the add if it would create a cycle. */
    public synchronized void add(String id, int priority, Set<String> dependsOn, Callable<?> body) {
        for (String d : dependsOn) if (!tasks.containsKey(d)) throw new IllegalArgumentException("unknown " + d);
        if (dependsOn.contains(id) || reachable(id, dependsOn)) throw new CycleException(id);
        tasks.put(id, new Task(id, priority, Set.copyOf(dependsOn), body));
        dependsOn.forEach(d -> dependents.computeIfAbsent(d, k -> new HashSet<>()).add(id));
    }

    /** DFS from the new task's parents up their own parents: does any path lead back to id? */
    private boolean reachable(String id, Set<String> start) {
        Deque<String> stack = new ArrayDeque<>(start);
        Set<String> seen = new HashSet<>();
        while (!stack.isEmpty()) {
            String cur = stack.pop();
            if (cur.equals(id)) return true;
            if (seen.add(cur)) stack.addAll(tasks.get(cur).dependsOn());
        }
        return false;
    }
}

// Runner: Kahn's algorithm with a priority queue of ready tasks and a fixed pool.
// remaining[id] = AtomicInteger(#deps). On success: for each dependent, if decrementAndGet() == 0, offer it.
// On permanent failure (5 attempts): mark it FAILED and every transitive dependent SKIPPED.
// cancel(id): mark CANCELLED and SKIP its transitive dependents; running tasks get Future.cancel(true).
// history: append-only ConcurrentLinkedQueue<TaskEvent(taskId, from, to, at, attempt)>.

If tasks are all known up front, run Kahn's algorithm once: if the number of tasks it can order is less than the total, there is a cycle, and the unvisited nodes are on it or behind it. The Media.net report lists cycle protection as "last thing to check"; doing it at add time means the runner never sees a cycle.

Uber / GS / Rubrik variant: ScheduledExecutorService from scratch

final class ScheduledTask implements Delayed, Runnable {
    private static final AtomicLong SEQ = new AtomicLong();
    final Runnable body;
    final long periodNanos;          // 0 = one-shot, >0 fixed rate, <0 fixed delay
    final long seq = SEQ.incrementAndGet();
    volatile long triggerNanos;
    volatile boolean cancelled;

    ScheduledTask(Runnable body, long triggerNanos, long periodNanos) {
        this.body = body; this.triggerNanos = triggerNanos; this.periodNanos = periodNanos;
    }
    public long getDelay(TimeUnit unit) { return unit.convert(triggerNanos - System.nanoTime(), TimeUnit.NANOSECONDS); }
    public int compareTo(Delayed o) {
        ScheduledTask t = (ScheduledTask) o;
        int c = Long.compare(triggerNanos, t.triggerNanos);
        return c != 0 ? c : Long.compare(seq, t.seq);
    }
    public void run() { body.run(); }
}

public final class SimpleScheduler {
    private final DelayQueue<ScheduledTask> queue = new DelayQueue<>();
    private final List<Thread> workers = new ArrayList<>();
    private volatile boolean shutdown;

    public SimpleScheduler(int threads) {
        for (int i = 0; i < threads; i++) workers.add(Thread.ofPlatform().name("sched-" + i).start(this::loop));
    }

    public ScheduledTask scheduleAtFixedRate(Runnable r, Duration initial, Duration period) {
        return submit(new ScheduledTask(r, System.nanoTime() + initial.toNanos(), period.toNanos()));
    }
    public ScheduledTask scheduleWithFixedDelay(Runnable r, Duration initial, Duration delay) {
        return submit(new ScheduledTask(r, System.nanoTime() + initial.toNanos(), -delay.toNanos()));
    }

    private ScheduledTask submit(ScheduledTask t) {
        if (shutdown) throw new RejectedExecutionException();
        queue.put(t);
        return t;
    }

    private void loop() {
        while (!shutdown) {
            ScheduledTask t;
            try { t = queue.take(); } catch (InterruptedException e) { return; }   // blocks until due
            if (t.cancelled) continue;
            try { t.run(); }
            catch (RuntimeException e) { continue; }   // like the JDK: a throwing periodic task stops recurring
            if (t.periodNanos > 0) t.triggerNanos += t.periodNanos;                     // fixed rate
            else if (t.periodNanos < 0) t.triggerNanos = System.nanoTime() - t.periodNanos; // fixed delay
            else continue;
            if (!shutdown) queue.put(t);
        }
    }

    public void shutdownNow() { shutdown = true; workers.forEach(Thread::interrupt); queue.clear(); }
}

Rubrik also asks for a thread pool from a bounded blocking queue with submit, execute, shutdown and shutdownNow. A candidate got "Lean Hire" partly over shutdown() semantics and exception handling. Know the difference: shutdown stops accepting and drains the queue; shutdownNow interrupts workers and returns the unstarted tasks; workers must restore the interrupt flag and exit, and task exceptions must not kill the worker thread.

06Concurrency and edge cases

  • Double claim. Prevented because claim, state change and lease creation happen under one lock. In Postgres the equivalent is SELECT … FOR UPDATE SKIP LOCKED LIMIT 1 followed by an update in the same transaction.
  • Zombie worker. A worker pauses (GC, network) past its lease, the job is re-leased, then the first worker calls complete. The token check rejects it. Without tokens, a stale completion would overwrite the new attempt.
  • Renew after expiry. Same token check: once the lease has been reissued, renewal fails and the worker should abort.
  • Lost wake-ups. awaitNanos in a loop that re-checks state, with signalAll on every change. The timeout is capped at the next due retry or lease expiry so promotions happen without a separate sweeper thread.
  • At-least-once means duplicates. A handler can run twice (lease expired mid-run). Handlers must be idempotent: dedupe by job id, use idempotency keys on downstream calls (for example a payment provider), or make writes upserts.
  • Poison jobs. Lease expiry counts as an attempt, so a job that kills its worker reaches the DLQ instead of looping.
  • Starvation. Strict priority can starve priority 0. Fix with ageing (effective priority rises with wait time) or weighted fair selection across priorities.
  • Thundering herd on retry. Pure exponential backoff makes failed jobs retry in synchronised waves; full jitter spreads them (AWS Architecture Blog).
  • Time. Inject Clock for runAt and lease logic. In tests, a mutable clock plus a direct call that triggers promotion; never Thread.sleep to wait for a lease to expire.
  • Interrupts. Never swallow InterruptedException; restore the flag and exit the loop.

07Extensions interviewers add mid-round

DLQ inspection and redrive

FAILED → PENDING is already an allowed transition. redrive(jobId) resets attempts and re-queues. Add listDlq(type, limit).

Observability: queue health

stats() under the lock: counts by state and type, oldest pending age (head of each ready queue), number of leases expired in the last minute (stuck jobs), DLQ size, p95 time from submit to claim. Expose as Micrometer gauges in Spring.

Unique / deduplicated jobs

Optional dedupeKey in the spec; a map from key to job id for non-terminal jobs; submit returns the existing id.

Rate limit per job type, or max concurrency per type

Per-type in-flight counter checked in pollBest: skip a type at its limit. Rate limit: a token bucket per type consulted before claiming.

Recurring and cron jobs (Walmart)

A schedule definition produces the next job instance on completion (fixed delay) or at each tick (fixed rate). Prevent overlap by not scheduling the next instance while one is CLAIMED.

Why PriorityBlockingQueue and not DelayQueue? (Walmart)

Priority ordering and time ordering are different keys. PriorityBlockingQueue orders ready jobs by priority; a DelayQueue (or the delayed heap above) holds not-yet-due jobs by time. Use both: move from delayed to ready when due.

Make it survive restarts / run on many machines

Persist jobs in Postgres: jobs(id, type, state, priority, run_at, attempts, lease_token, lease_expires_at, payload jsonb) with an index on (state, type, priority DESC, run_at). Claim with FOR UPDATE SKIP LOCKED; a reaper updates expired leases. Or use SQS: visibility timeout is the lease (max 12 hours, extendable), the receipt handle is the token, a redrive policy is the DLQ. Kafka is a poor fit for per-message retry with backoff without retry topics.

09Mistakes that got candidates rejected

Rejected for this
  • Code that does not run at the end (Media.net, Nov 2025). Get a thin end-to-end path green first, then add features.
  • In agentic rounds: letting the agent write everything without a plan, no incremental commits, or "done" without tests that exercise concurrency (Razorpay's stated rules).
  • No lease token, so a slow worker completes a job someone else is re-running.
  • Busy-wait polling with Thread.sleep(10) instead of a condition or blocking queue.
  • Catching InterruptedException and continuing; shutdown() that does not actually stop workers (Rubrik feedback).
  • Using PriorityQueue without a sequence tie-breaker and claiming FIFO within a priority.
  • Claiming exactly-once delivery.

Code-review viva

Why lazy deletion in the heaps?

PriorityQueue.remove(Object) is O(n). Cancel and renew happen often; skipping stale entries on poll keeps them O(1) and claim amortised O(log n). The cost is some garbage entries, bounded by the number of renewals.

Why does lease expiry count as an attempt?

Otherwise a job that crashes or hangs every worker retries forever. Counting it sends poison jobs to the DLQ after maxRetries.

Why full jitter instead of equal jitter or none?

Without jitter, jobs that failed together retry together and hit the recovering dependency at the same instant. AWS's simulation found no-jitter backoff the clear loser; full jitter and decorrelated jitter both did well, with full jitter doing the least client work.

What would you change for 10,000 job types?

pollBest scans the worker's types; with many types per worker, keep a single heap keyed by (priority, seq) per worker group, or a global heap with type filtering, and stripe locks by type group.

How do you shut down gracefully?

Stop claiming, wait up to a deadline for in-flight handlers, then interrupt them; their leases expire and the jobs are re-run by the next process. That is safe because handlers are idempotent.
