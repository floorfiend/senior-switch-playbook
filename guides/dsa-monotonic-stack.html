Monotonic Stack

A stack kept in sorted order turns "for every element, find the nearest bigger or smaller one" from O(n²) into O(n). Learn the one loop, then recognise it in histograms, temperatures and digit removal.

01When to use this pattern

Reach for a monotonic stack when the answer for each position depends on the nearest element to its left or right that is bigger or smaller. Phrases that give it away:

  • "next greater element", "next warmer day", "how many days until", "stock span"
  • "largest rectangle", "maximal rectangle", "trapping rain water", "visible people in a queue"
  • "remove k digits to make the smallest number", "smallest subsequence of distinct characters", "lexicographically smallest"
  • "sum of subarray minimums" (each element's contribution = how far it stays the minimum to the left and right)

The brute force is two nested loops scanning outward from every index: O(n²). If n is 105 that is 1010 steps, which is the interviewer's hint that an O(n) idea exists.

02The mental model, with a trace

Think of the stack as a waiting room of indices whose answer is not known yet. When a new element arrives, it is the answer for every waiting element smaller than it, and those leave the room. Everyone still waiting is bigger than the newcomer, so the room is always sorted (decreasing from bottom to top). The newcomer then waits too.

Why O(n): each index is pushed once and popped at most once, so the inner while runs at most n times across the whole loop, even though it looks nested.

The histogram technique

For the largest rectangle in a histogram, each bar's best rectangle uses its own height and stretches left and right until a shorter bar. So you need, for every bar, the previous smaller and the next smaller index: width = next - prev - 1. An increasing stack gives both in one pass. When bar i pops bar t, i is t's next smaller, and the element under t on the stack is its previous smaller. A sentinel height 0 at i = n flushes the stack at the end.

03Java templates

Both run in O(n) time and O(n) space. Use ArrayDeque as the stack (push/pop/peek work on the head); java.util.Stack is synchronised and slower, and a reviewer will mention it. For the hottest loops an int[] with a top pointer avoids boxing.

import java.util.*;

class StackTemplates {
    // Next greater element to the right (index), -1 if none. Each index is pushed and popped once: O(n).
    static int[] nextGreater(int[] a) {
        int[] res = new int[a.length];
        Arrays.fill(res, -1);
        Deque<Integer> stack = new ArrayDeque<>();      // indices whose answer is still unknown
        for (int i = 0; i < a.length; i++) {
            while (!stack.isEmpty() && a[stack.peek()] < a[i]) {
                res[stack.pop()] = i;                   // a[i] resolves everything smaller on top
            }
            stack.push(i);
        }
        return res;
    }

    // Previous smaller element to the left (index), -1 if none. The stack holds candidates; O(n).
    static int[] prevSmaller(int[] a) {
        int[] res = new int[a.length];
        Deque<Integer> stack = new ArrayDeque<>();
        for (int i = 0; i < a.length; i++) {
            while (!stack.isEmpty() && a[stack.peek()] >= a[i]) {
                stack.pop();                            // can never be the answer for anyone right of i
            }
            res[i] = stack.isEmpty() ? -1 : stack.peek();
            stack.push(i);
        }
        return res;
    }
}
Store indices, not values

Indices give you both the value (a[idx]) and the distance (i - idx), which daily temperatures and the histogram both need.

04Worked problems

4.1 Next Greater Element I

LeetCode 496: next-greater-element-i · Easy

Problem. nums1 is a subset of nums2 (all values distinct). For each value in nums1, return the first greater value to its right in nums2, or −1.

Key insight. Run the next-greater loop over nums2 once, record answers in a map keyed by value (values are distinct), then look each nums1 value up.

import java.util.*;

class Solution {
    public int[] nextGreaterElement(int[] nums1, int[] nums2) {
        Map<Integer, Integer> next = new HashMap<>();
        Deque<Integer> stack = new ArrayDeque<>();            // decreasing values still waiting
        for (int x : nums2) {
            while (!stack.isEmpty() && stack.peek() < x) {
                next.put(stack.pop(), x);                     // x is the first greater to the right
            }
            stack.push(x);
        }
        int[] out = new int[nums1.length];
        for (int i = 0; i < nums1.length; i++) {
            out[i] = next.getOrDefault(nums1[i], -1);
        }
        return out;
    }
}

Complexity. O(n + m) time, O(n) space.

Edge cases. The last element always maps to −1; a strictly decreasing nums2 leaves everything on the stack. Follow-up: Next Greater Element II (circular array) — loop i from 0 to 2n − 1 and use i % n, pushing only in the first pass.

4.2 Daily Temperatures

LeetCode 739: daily-temperatures · Medium

Problem. For each day, how many days until a strictly warmer temperature? 0 if none.

Key insight. Next greater element, but the answer is the distance i − j, so store indices.

import java.util.*;

class Solution {
    public int[] dailyTemperatures(int[] temperatures) {
        int n = temperatures.length;
        int[] answer = new int[n];
        Deque<Integer> stack = new ArrayDeque<>();            // indices, temperatures decreasing
        for (int i = 0; i < n; i++) {
            while (!stack.isEmpty() && temperatures[stack.peek()] < temperatures[i]) {
                int j = stack.pop();
                answer[j] = i - j;
            }
            stack.push(i);
        }
        return answer;                                        // indices left in stack keep 0
    }
}

Complexity. O(n) time, O(n) space.

Edge cases. Equal temperatures are not warmer, so pop on strict <; with <= you would wrongly answer equal days. Trace on [73,74,75,71,69,72,76,73] gives [1,1,4,2,1,1,0,0].

Follow-up. O(1) extra space: iterate from the right and jump using the answers already computed (j += answer[j]) until you find a warmer day. Still amortised O(n).

4.3 Largest Rectangle in Histogram

LeetCode 84: largest-rectangle-in-histogram · Hard

Problem. Bars of width 1 with given heights. Return the area of the largest rectangle that fits under the skyline.

Key insight. The histogram technique from section 02: an increasing stack; on pop, the current index is the right boundary and the new top is the left boundary.

import java.util.*;

class Solution {
    public int largestRectangleArea(int[] heights) {
        int n = heights.length;
        Deque<Integer> stack = new ArrayDeque<>();            // indices, heights increasing
        int best = 0;
        for (int i = 0; i <= n; i++) {
            int h = i == n ? 0 : heights[i];                  // sentinel 0 flushes the stack
            while (!stack.isEmpty() && heights[stack.peek()] >= h) {
                int height = heights[stack.pop()];
                int left = stack.isEmpty() ? -1 : stack.peek(); // previous smaller bar
                best = Math.max(best, height * (i - left - 1)); // i is the next smaller bar
            }
            stack.push(i);
        }
        return best;
    }
}

Complexity. O(n) time, O(n) space.

Edge cases. All bars equal ([3,3,3] → 9): popping on >= means each equal bar is popped by the next one with too narrow a width, but the last bar left on the stack has nothing below it (left = −1), so the sentinel pop computes the full width. Strictly increasing input: nothing pops until the sentinel. Area fits in int for the given limits (105 × 104).

Follow-up. Maximal Rectangle (LeetCode 85) on a 0/1 matrix: build a heights array row by row (height + 1 on a 1, reset to 0 on a 0) and run this function on each row. O(rows × cols).

4.4 Remove K Digits PhonePe

LeetCode 402: remove-k-digits · Medium

Problem. Given a non-negative integer as a string, remove exactly k digits to make the smallest possible number. No leading zeros in the answer; return "0" if nothing remains.

Key insight. A number is smaller when its leftmost digits are smaller. Scan left to right; while the previous kept digit is larger than the current one and you still have removals, drop it. That leaves a non-decreasing stack. If removals remain, the largest digits are at the tail, so cut from the end.

class Solution {
    public String removeKdigits(String num, int k) {
        StringBuilder stack = new StringBuilder();            // digits kept so far, non-decreasing
        for (char c : num.toCharArray()) {
            while (k > 0 && stack.length() > 0 && stack.charAt(stack.length() - 1) > c) {
                stack.deleteCharAt(stack.length() - 1);       // a smaller digit earlier wins
                k--;
            }
            stack.append(c);
        }
        stack.setLength(stack.length() - k);                  // still owe removals: drop from the tail
        int i = 0;
        while (i < stack.length() - 1 && stack.charAt(i) == '0') {
            i++;                                              // strip leading zeros, keep one digit
        }
        String result = stack.substring(i);
        return result.isEmpty() ? "0" : result;
    }
}

Complexity. O(n) time (each digit pushed and popped at most once), O(n) space.

Trace on "1432219", k = 3: 1 → 14 → 13 (drop 4) → 12 (drop 3) → 122 → 121 (drop 2, k = 0) → 1219.

Edge cases. k == num.length() → "0"; leading zeros after removal ("10200", k = 1 → "200"); non-decreasing input such as "112" removes from the tail → "11"; never use Long.parseLong, the string can be 105 digits.

05Common mistakes and follow-ups interviewers ask

Mistakes that cost the round
  • Calling it O(n²) because of the nested loop, or failing to explain the amortised argument when asked.
  • Strict versus non-strict comparisons chosen at random. Decide what happens with equal values before coding; it changes the answer for duplicates.
  • Forgetting the leftover stack at the end (histogram without a sentinel misses the increasing tail; remove-k-digits without the tail cut ignores remaining k).
  • Using java.util.Stack without being able to say why ArrayDeque is preferred.
Why is the stack approach O(n) when it has a while inside a for?

Every index is pushed exactly once and popped at most once. The total number of pops over the whole run is at most n, so total work is O(n) amortised.

Sum of Subarray Minimums: how does the stack help?

Each a[i] is the minimum of left × right subarrays, where left is the distance to the previous smaller and right the distance to the next smaller-or-equal (asymmetric to avoid double counting duplicates). Two monotonic passes give both; sum a[i] × left × right mod 109+7.

Trapping Rain Water with a stack?

Keep a decreasing stack of indices. When a taller bar arrives, pop the bottom of a "valley", and the water above it is (min(left, right) − bottom) × width. The two-pointer solution is O(1) space and usually preferred; know both.

Online version: stock span arriving one price at a time?

Online Stock Span (LeetCode 901): keep a stack of (price, span). For a new price, pop all entries with price <= it and add their spans. Each call is amortised O(1).

Sliding window maximum — is that the same pattern?

It is the queue cousin: a monotonic deque where you also evict indices that fall out of the window from the front. See the sliding window lesson.

06Self-check

1. To find the next smaller element to the right, is the stack increasing or decreasing from bottom to top?

Increasing. You pop while a[top] > a[i], so everything left is <= the newcomer.

2. In the histogram loop, what are the left and right boundaries of a popped bar?

Right boundary: the current index i (its next smaller). Left boundary: the index now on top of the stack, or −1 if empty (its previous smaller). Width = i − left − 1.

3. What is Remove K Digits for "9", k = 1, and for "10", k = 2?

Both return "0".

4. Daily temperatures for [30, 30, 31]?

[2, 1, 0]. Equal is not warmer, so the first 30 waits for 31.
