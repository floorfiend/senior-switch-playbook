Dynamic Programming Core

Every DP answer is three things said out loud: the state, the transition and the base case. Then you move from memoised recursion to a table to O(1) or O(n) space. This lesson covers the five shapes that came up in interviews: 1D, unbounded knapsack, partition, subsequence, and LIS in O(n log n).

01When to use DP

DP applies when a problem has overlapping subproblems (plain recursion would solve the same smaller question many times) and optimal substructure (the best answer is built from best answers to smaller questions). Recognition cues:

  • The question asks for a count ("number of ways"), a minimum/maximum ("fewest coins", "max money"), or a yes/no ("can you partition").
  • Each step is a choice: take or skip, which coin next, where to cut, match or skip a character.
  • Greedy fails on a small counter-example (coins [1, 3, 4], amount 6: greedy takes 4+1+1, optimal is 3+3).
  • Constraints are around n ≤ 103 to 104 for O(n²), or amounts ≤ 104 for O(n × amount).

02The mental model, with traces

State, transition, base case

Take House Robber: houses in a row, no two adjacent can be robbed, maximise loot.

  • State: dp[i] = most money from the first i houses. Write the definition in a comment before coding; most DP bugs come from a vague state.
  • Transition: for house i, skip it (dp[i-1]) or rob it (dp[i-2] + nums[i-1]). Take the max.
  • Base case: dp[0] = 0 (no houses), dp[1] = nums[0].
  • Answer: dp[n].
Recursionexponential→ Memoisationtop-down, cache by state→ Tabulationbottom-up loop→ Space optimisedkeep only rows you read

Figure: the four-step progression interviewers expect you to narrate. Memoisation is the safest start under pressure; tabulation removes recursion depth risk; the last step drops memory.

Space optimisation works whenever the transition reads a fixed window of previous states. House Robber reads only dp[i-1] and dp[i-2], so two variables suffice. Trace on [2, 7, 9, 3, 1]:

Unbounded knapsack

Items can be reused. For the fewest coins, dp[a] = min over coins c ≤ a of dp[a − c] + 1. With coins [1, 2, 5] and amount 11, dp[0..11] = 0, 1, 1, 2, 2, 1, 2, 2, 3, 3, 2, 3. For counting combinations, loop coins on the outside so each combination is counted once in a fixed coin order; loop amounts on the outside and you count permutations instead.

LIS in O(n log n): patience sorting

Keep tails[k] = the smallest possible last value of an increasing subsequence of length k + 1. tails is always sorted, so for each new value binary search the first tail ≥ it and overwrite it (or append). The length of tails is the LIS length; its contents are not necessarily a valid subsequence.

03Java templates

Memoised and tabulated House Robber (O(n) time, O(n) space; the space-optimised version is in problem 4.1), unbounded-knapsack counting (O(coins × amount) time, O(amount) space) and two-string subsequence DP (O(m × n) time and space).

import java.util.*;

class DpTemplates {
    // Step 1: memoised recursion. best(i) = max loot from houses i..n-1.
    static int robMemo(int[] nums) {
        Integer[] memo = new Integer[nums.length];
        return best(nums, 0, memo);
    }

    private static int best(int[] nums, int i, Integer[] memo) {
        if (i >= nums.length) {
            return 0;                                           // base case: no houses left
        }
        if (memo[i] != null) {
            return memo[i];
        }
        int skip = best(nums, i + 1, memo);
        int take = nums[i] + best(nums, i + 2, memo);
        return memo[i] = Math.max(skip, take);
    }

    // Step 2: tabulation. dp[i] = max loot from the first i houses.
    static int robTable(int[] nums) {
        int n = nums.length;
        int[] dp = new int[n + 1];
        dp[1] = n > 0 ? nums[0] : 0;
        for (int i = 2; i <= n; i++) {
            dp[i] = Math.max(dp[i - 1], dp[i - 2] + nums[i - 1]);
        }
        return dp[n];
    }

    // Unbounded knapsack: number of ways to make amount (coin order does not matter).
    static int countWays(int[] coins, int amount) {
        int[] ways = new int[amount + 1];
        ways[0] = 1;
        for (int c : coins) {                                   // coins outer: combinations, not permutations
            for (int a = c; a <= amount; a++) {                 // ascending a: coin c reusable
                ways[a] += ways[a - c];
            }
        }
        return ways[amount];
    }

    // Subsequence DP on two strings: longest common subsequence.
    static int lcs(String x, String y) {
        int[][] dp = new int[x.length() + 1][y.length() + 1];
        for (int i = 1; i <= x.length(); i++) {
            for (int j = 1; j <= y.length(); j++) {
                dp[i][j] = x.charAt(i - 1) == y.charAt(j - 1)
                    ? dp[i - 1][j - 1] + 1
                    : Math.max(dp[i - 1][j], dp[i][j - 1]);
            }
        }
        return dp[x.length()][y.length()];
    }
}
Use Integer[] for memo, not int[]

null means "not computed", so a real answer of 0 is not confused with "missing". With int[] you need Arrays.fill(memo, -1) and must be sure −1 is never a valid answer.

Partition DP shape

dp[j] = best answer for the prefix ending at j. Try every possible last piece s[i..j]; if it is valid, combine with dp[i-1]. That is O(n²) transitions, so validity must be O(1), usually via a precomputed table. Word Break and Palindrome Partitioning II both follow it.

04Worked problems

4.1 House Robber

LeetCode 198: house-robber · Medium

Problem. Houses in a line, each with some money. You cannot rob two adjacent houses. Return the maximum you can take.

Key insight. best(i) = max(best(i-1), best(i-2) + nums[i]), needing only the last two values.

class Solution {
    public int rob(int[] nums) {
        int prev2 = 0;                 // best up to house i-2
        int prev1 = 0;                 // best up to house i-1
        for (int x : nums) {
            int cur = Math.max(prev1, prev2 + x);
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
}

Complexity. O(n) time, O(1) space.

Edge cases. One house; two houses (take the larger); all zeros.

4.2 House Robber II PhonePe Amazon Walmart Zeta Flipkart

LeetCode 213: house-robber-ii · Medium

Problem. Same rule, but the houses form a circle, so the first and last are neighbours.

Key insight. In any valid plan, at least one of house 0 or house n−1 is skipped. So run the linear robber twice, on [0, n−2] and on [1, n−1], and take the max. This was the most-reported DP problem in the set; interviewers then ask for House Robber III (tree) as the follow-up.

class Solution {
    public int rob(int[] nums) {
        int n = nums.length;
        if (n == 1) {
            return nums[0];
        }
        // the first and last house are neighbours, so never take both
        return Math.max(robLine(nums, 0, n - 2), robLine(nums, 1, n - 1));
    }

    private int robLine(int[] nums, int from, int to) {
        int prev2 = 0;
        int prev1 = 0;
        for (int i = from; i <= to; i++) {
            int cur = Math.max(prev1, prev2 + nums[i]);
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
}

Complexity. O(n) time, O(1) space.

Edge cases. n = 1 must return nums[0] (both ranges would otherwise be empty); n = 2 returns the larger value; [1, 2, 3] → 3, not 4.

Follow-up: House Robber III (binary tree). Post-order DFS returning a pair {robThis, skipThis}: robThis = node.val + left.skip + right.skip, skipThis = max(left) + max(right). O(n) time, O(h) stack.

4.3 Coin Change Kotak

LeetCode 322: coin-change · Medium

Problem. Unlimited coins of given denominations. Return the fewest coins that sum to amount, or −1 if impossible.

Key insight. Unbounded knapsack minimum: dp[a] = min(dp[a − c] + 1). Use amount + 1 as infinity so + 1 never overflows.

import java.util.*;

class Solution {
    public int coinChange(int[] coins, int amount) {
        int[] dp = new int[amount + 1];              // dp[a] = fewest coins to make a
        Arrays.fill(dp, amount + 1);                 // amount + 1 acts as infinity
        dp[0] = 0;
        for (int a = 1; a <= amount; a++) {
            for (int c : coins) {
                if (c <= a) {
                    dp[a] = Math.min(dp[a], dp[a - c] + 1);
                }
            }
        }
        return dp[amount] > amount ? -1 : dp[amount];
    }
}

Complexity. O(amount × coins) time, O(amount) space.

Edge cases. amount = 0 → 0; unreachable amount ([2], 3) → −1; using Integer.MAX_VALUE as infinity overflows on + 1. Follow-up: Coin Change II (number of combinations) uses the countWays template with coins in the outer loop.

4.4 Decode Ways Angel One

LeetCode 91: decode-ways · Medium

Problem. Letters map to "1".."26". Given a digit string, count how many ways it can be decoded.

Key insight. Like climbing stairs with conditions: the last letter used either one digit (valid if not '0') or two digits (valid if 10..26). dp[i] = (one-digit ok ? dp[i-1] : 0) + (two-digit ok ? dp[i-2] : 0).

class Solution {
    public int numDecodings(String s) {
        int prev2 = 1;                                    // ways to decode s[0..i-2) (empty prefix = 1)
        int prev1 = s.charAt(0) == '0' ? 0 : 1;           // ways to decode s[0..i-1)
        for (int i = 2; i <= s.length(); i++) {
            int cur = 0;
            if (s.charAt(i - 1) != '0') {
                cur += prev1;                             // last char as a single letter
            }
            int two = (s.charAt(i - 2) - '0') * 10 + (s.charAt(i - 1) - '0');
            if (two >= 10 && two <= 26) {
                cur += prev2;                             // last two chars as one letter
            }
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
}

Complexity. O(n) time, O(1) space.

Trace on "226": start (1, 1); i = 2: "2" ok → 1, "22" ok → +1 = 2; i = 3: "6" ok → 2, "26" ok → +1 = 3. Answer 3 (2-2-6, 22-6, 2-26).

Edge cases. Leading '0' → 0; "10" → 1; "100" → 0 (the second '0' cannot stand alone and "00" is not valid); "27" → 1. Follow-up: Decode Ways II with '*' wildcards multiplies counts per case and needs mod 109+7.

4.5 Palindrome Partitioning II Zeta

LeetCode 132: palindrome-partitioning-ii · Hard

Problem. Cut a string into pieces that are all palindromes. Return the minimum number of cuts.

Key insight. Partition DP: cuts[j] = min cuts for s[0..j]. Try every last piece s[i..j]; if it is a palindrome, cuts[j] = min(cuts[i−1] + 1), or 0 when i = 0. Fill the palindrome table in the same loop: s[i..j] is a palindrome if the end characters match and the inside is one (or the length is ≤ 2).

class Solution {
    public int minCut(String s) {
        int n = s.length();
        boolean[][] pal = new boolean[n][n];             // pal[i][j]: s[i..j] is a palindrome
        int[] cuts = new int[n];                         // cuts[j]: min cuts for s[0..j]
        for (int j = 0; j < n; j++) {
            cuts[j] = j;                                 // worst case: every char alone
            for (int i = 0; i <= j; i++) {
                if (s.charAt(i) == s.charAt(j) && (j - i < 2 || pal[i + 1][j - 1])) {
                    pal[i][j] = true;
                    cuts[j] = i == 0 ? 0 : Math.min(cuts[j], cuts[i - 1] + 1);
                }
            }
        }
        return cuts[n - 1];
    }
}

Complexity. O(n²) time, O(n²) space for the table. An O(n) space variant expands around each centre and updates cuts as it goes.

Edge cases. Single character → 0; whole string already a palindrome → 0; all distinct characters → n − 1. Order of loops matters: pal[i+1][j-1] must be filled before pal[i][j], which holds because column j−1 is complete when you reach column j.

4.6 Longest Palindromic Subsequence Paytm OA LinkedIn

LeetCode 516: longest-palindromic-subsequence · Medium

Problem. Return the length of the longest subsequence (not necessarily contiguous) of s that reads the same both ways.

Key insight. Interval DP on s[i..j]: if the ends match, both join the palindrome (dp[i+1][j−1] + 2); otherwise drop one end (max(dp[i+1][j], dp[i][j−1])). Fill i from right to left so the shorter ranges are ready. Equivalent view: LPS(s) = LCS(s, reverse(s)), using the template.

class Solution {
    public int longestPalindromeSubseq(String s) {
        int n = s.length();
        int[][] dp = new int[n][n];                      // dp[i][j]: LPS length inside s[i..j]
        for (int i = n - 1; i >= 0; i--) {
            dp[i][i] = 1;
            for (int j = i + 1; j < n; j++) {
                if (s.charAt(i) == s.charAt(j)) {
                    dp[i][j] = dp[i + 1][j - 1] + 2;     // both ends join the palindrome
                } else {
                    dp[i][j] = Math.max(dp[i + 1][j], dp[i][j - 1]);
                }
            }
        }
        return dp[0][n - 1];
    }
}

Complexity. O(n²) time, O(n²) space; reducible to O(n) with two rows since row i reads only row i+1.

Edge cases. Length 1 → 1; all same characters → n; "cbbd" → 2. Related follow-ups: minimum insertions to make a palindrome = n − LPS; longest palindromic substring is a different problem (expand around centre).

4.7 Longest Increasing Subsequence Visa Staff

LeetCode 300: longest-increasing-subsequence · Medium

Problem. Return the length of the longest strictly increasing subsequence.

Key insight (baseline). dp[i] = LIS ending at i = 1 + max dp[j] over j < i with nums[j] < nums[i]. O(n²). Say this first, then offer the faster version.

class Solution {
    public int lengthOfLIS(int[] nums) {
        int n = nums.length;
        int[] dp = new int[n];                           // dp[i]: longest increasing run ending at i
        int best = 0;
        for (int i = 0; i < n; i++) {
            dp[i] = 1;
            for (int j = 0; j < i; j++) {
                if (nums[j] < nums[i]) {
                    dp[i] = Math.max(dp[i], dp[j] + 1);
                }
            }
            best = Math.max(best, dp[i]);
        }
        return best;
    }
}

Follow-up asked at Visa: O(n log n). The patience-sorting tails array from section 02 with a lower-bound binary search.

class Solution {
    public int lengthOfLIS(int[] nums) {
        int[] tails = new int[nums.length];              // tails[k]: smallest tail of an increasing run of length k+1
        int size = 0;
        for (int x : nums) {
            int lo = 0;
            int hi = size;
            while (lo < hi) {                            // first tail >= x (lower bound)
                int mid = (lo + hi) >>> 1;
                if (tails[mid] < x) {
                    lo = mid + 1;
                } else {
                    hi = mid;
                }
            }
            tails[lo] = x;
            if (lo == size) {
                size++;
            }
        }
        return size;
    }
}

Complexity. O(n log n) time, O(n) space.

Edge cases. Strictly increasing means duplicates do not extend: lower bound (first tail >= x) replaces an equal tail, so [7,7,7,7] → 1. For non-decreasing, use upper bound (first tail > x). To reconstruct the actual subsequence, store for each element the index that sits before it (the tail at position lo − 1) and walk back from the last tail.

05Common mistakes and follow-ups interviewers ask

Mistakes that cost the round
  • Jumping to a table without saying what dp[i] means. The interviewer cannot follow, and you lose the chance to catch an off-by-one.
  • Off-by-one between "first i items" (size n + 1) and "ending at index i" (size n) states.
  • Using Integer.MAX_VALUE as infinity and adding 1.
  • House Robber II without the n = 1 guard.
  • Claiming the tails array is the LIS itself.
  • Deep recursion in Java memoisation for n around 105: the default thread stack overflows; convert to tabulation.
Memoisation or tabulation: which do you choose?

Memoisation is quicker to get right and only computes reachable states. Tabulation avoids recursion overhead and stack overflow, and makes space optimisation possible because you control the fill order. In an interview, start with whichever you can write correctly, then convert if asked.

How do you know a greedy will not work?

Find a small counter-example. For coin change, [1, 3, 4] with amount 6 breaks largest-coin-first. For house robber, [2, 1, 1, 2] breaks "take every other house".

Coin change: combinations versus permutations?

Coins in the outer loop and amounts inner counts combinations (1+2 equals 2+1). Amounts outer, coins inner counts ordered sequences, which is Combination Sum IV.

Can LIS be done with a TreeSet?

Yes for strictly increasing: for each x, remove ceiling(x) if present and add x; the set size is the answer. Same O(n log n), but the array version has lower constants and handles reconstruction more easily.

Russian Doll Envelopes is a common LIS follow-up. What is the trick?

Sort by width ascending and, for equal widths, height descending; then run LIS on heights. The descending tie-break stops two envelopes of the same width from nesting.

06Self-check

1. State, transition and base case for Decode Ways?

State: dp[i] = number of decodings of the first i characters. Transition: add dp[i−1] if s[i−1] ≠ '0', add dp[i−2] if s[i−2..i−1] is 10..26. Base: dp[0] = 1, dp[1] = s[0] == '0' ? 0 : 1.

2. Why does House Robber II split into two linear runs?

House 0 and house n−1 are adjacent, so at least one of them is never robbed. Excluding each in turn covers every valid plan.

3. What does tails look like after processing [3, 1, 4, 1, 5]?

[3] → [1] → [1, 4] → [1, 4] (1 replaces 1) → [1, 4, 5]. LIS length 3.

4. Longest palindromic subsequence of "bbbab"?

4 ("bbbb").

5. When can a 2D DP drop to one row?

When row i reads only row i and row i ± 1. Keep two arrays, or one array if you choose the inner loop direction so you never overwrite a value you still need.
