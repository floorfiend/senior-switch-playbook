Parking Lot

Build a parking lot with many gates. Two cars must never get the same spot. No car should ever be charged twice. You must also explain why your design is safe.

Time-box: 60–90 min Seen: ~6 reports, 2025–26, plus a Rubrik concurrency variant
SwiggyCashfreeAngel OneUberPayPalAmazonRubrik
In 30 seconds
  • Keep the free spots of each type in a sorted list that many threads can share safely.
  • pollFirst() takes the best spot in one step, so two gates never get the same one.
  • A ticket moves ACTIVE, then PAYING, then CLOSED. Only one exit gate can make that move.
  • Pricing and spot choice are swappable parts. Money is stored in paise as a long.
Picture it

Think of a mall parking with a token machine at every gate. Each machine pulls the top token off one shared stack. So two gates can never hand out the same bay. At the exit, the token is first stamped "paying". A second exit lane then cannot charge the same car again.

Words you'll see
Atomic
Happens in one step that nobody can interrupt. Another thread sees either "before" or "after", never half.
Race condition
Two threads touch the same data at the same time, and the result depends on who is faster.
Check-then-act
You read a value, then act on it in a second step. Another thread can change it in between.
CAS (compare-and-set)
"Change the value to B only if it is still A." If someone changed it first, your update fails.
Strategy pattern
A rule you can swap without changing the main code, like "hourly pricing" or "weekend pricing".
Comparator
A rule that says which of two items comes first. Here it decides which spot is "best".
Idempotent
Doing it twice has the same effect as doing it once. Pressing "Pay" twice charges you once.
Paise
1/100 of a rupee. Storing whole paise avoids rounding errors that decimals like 0.1 cause.

01What the interviewer is grading

Runnable code

Park, exit, pay and show free spots, from a main or from tests. A diagram alone does not pass a machine-coding round.

Correct spot assignment

Two gates never get the same spot. A car cannot enter twice. An exit cannot be paid twice.

Easy to extend

You can swap how spots are chosen and how prices work. Which vehicle fits which spot is data. Display boards get told about changes.

Search (Cashfree)

Find free spots by type and floor without checking every spot. Also search by time window, if bookings are in scope.

Everyone knows the classes. You are judged on safety when many gates work at once. You are also judged on how easy it is to extend. And you must finish runnable code in time.

Go deeper: what each company asked

This is the classic question. It is still asked in 2025–26, now at senior level. Expect many floors and spot types. Expect swappable spot choice and pricing. Expect several entry and exit gates fighting for the same spots. Leave room for EV charging and bookings. The reports show how short the prompt is, and how much is expected:

  • Swiggy SDE-2 (Nov 2025, rejected after the next round): parking lot inside one hour of DSA plus LLD. They wanted the classes (Vehicle, Slot, Ticket, Payment), a spot-choice strategy and a class diagram. The candidate's lesson: startups expect you to "solve instantly".
  • Cashfree SDE-2 (Oct 2025, rejected): an "online parking lot". Search free slots, then book or reserve one. "The interviewer wanted a more refined approach for the search functionality." Search decided the result.
  • Angel One SDE-2 (2026, selected): parking lot LLD inside a round that mixed system design and database design.
  • Rubrik: a systems-coding twist. Build thread-safe car and truck parking in a one-row array. A car takes one unit. A truck takes two.
  • Uber, PayPal (SE3, LLD and HLD) and Amazon also ask it. At senior level, the follow-up questions are about safety with many threads, and about adding features.

03Requirements

Functional (what it does)

  • A lot has floors. Spots are TWO_WHEELER, COMPACT, LARGE or EV.
  • Vehicles are BIKE, CAR, EV_CAR or TRUCK. Each has an ordered list of spot types it can use.
  • The entry gate gives a ticket and a spot, or says "full".
  • The exit gate works out the fee, takes payment and frees the spot.
  • Show free spots per type and floor on display boards.
  • Spot choice and pricing can be swapped.

Non-functional (how well it does it)

  • Many gates at once: no spot given twice, no ticket paid twice.
  • Finding a spot takes O(log n) time, not a scan of every spot.
  • Fee tests give the same result every run, because the test controls the Clock.
  • Money is a long in paise, never a double.

Out of scope

  • A real payment gateway. Use an interface and a fake.
  • Number-plate cameras (ANPR) and other hardware.
  • Many lots and a database. Only talk about these.

Patterns and why

Strategy

Use it for pricing and for the order spots are chosen in. Product teams change these the most.

Decorator

Wraps base pricing to add extra charges, such as EV energy or valet.

Observer

Display boards and metrics get told when free counts change.

State

The ticket's state is an enum: ACTIVE, PAYING, CLOSED. Each move uses CAS, so only one thread wins it.

Façade, not Singleton

ParkingLot is the one front door. A second lot or a test just calls new ParkingLot(...).

No class per vehicle

Skip Car extends Vehicle unless behaviour differs. An enum plus a "what fits where" table is less code. It is also easier to extend.

Show Java: SpotPool

The free-spot pool is the heart of the thread safety. ConcurrentSkipListSet.pollFirst() removes and returns the best spot in one step. So two gates can never get the same spot, and you need no lock. The sort rule (comparator) is the spot-choice strategy.

final class SpotPool {
    private final Map<SpotType, ConcurrentSkipListSet<Spot>> free = new EnumMap<>(SpotType.class);

    SpotPool(Collection<Spot> spots, Comparator<Spot> allocationOrder) {
        Comparator<Spot> total = allocationOrder.thenComparing(Spot::id); // ties must not collapse in a Set
        for (SpotType t : SpotType.values()) free.put(t, new ConcurrentSkipListSet<>(total));
        spots.forEach(s -> free.get(s.type()).add(s));
    }

    Optional<Spot> take(VehicleType vehicle) {
        for (SpotType type : Compatibility.preferenceFor(vehicle)) {
            Spot s = free.get(type).pollFirst(); // atomic remove-and-return
            if (s != null) return Optional.of(s);
        }
        return Optional.empty();
    }

    void release(Spot s) { free.get(s.type()).add(s); }

    int freeCount(SpotType t) { return free.get(t).size(); } // O(n) on a skip list; keep an AtomicInteger if hot
}

// Allocation strategies are just comparators:
//   lowest floor, then nearest:  Comparator.comparingInt(Spot::floor).thenComparingInt(Spot::distanceFromEntry)
//   nearest overall:             Comparator.comparingInt(Spot::distanceFromEntry)

public final class Ticket {
    public enum State { ACTIVE, PAYING, CLOSED }

    private final String id;
    private final Vehicle vehicle;
    private final Spot spot;
    private final Instant entryTime;
    private final String entryGate;
    private final AtomicReference<State> state = new AtomicReference<>(State.ACTIVE);

    Ticket(String id, Vehicle vehicle, Spot spot, Instant entryTime, String entryGate) {
        this.id = id; this.vehicle = vehicle; this.spot = spot; this.entryTime = entryTime; this.entryGate = entryGate;
    }

    boolean transition(State from, State to) { return state.compareAndSet(from, to); }

    public String id() { return id; }
    public Vehicle vehicle() { return vehicle; }
    public Spot spot() { return spot; }
    public Instant entryTime() { return entryTime; }
    public State state() { return state.get(); }
}

public interface PricingStrategy {
    long feePaise(Ticket ticket, Instant exitTime);
}

public final class HourlyPricing implements PricingStrategy {
    private final Map<VehicleType, Long> firstHour;
    private final Map<VehicleType, Long> perExtraHour;
    private final Duration grace;

    public HourlyPricing(Map<VehicleType, Long> firstHour, Map<VehicleType, Long> perExtraHour, Duration grace) {
        this.firstHour = Map.copyOf(firstHour); this.perExtraHour = Map.copyOf(perExtraHour); this.grace = grace;
    }

    @Override
    public long feePaise(Ticket t, Instant exit) {
        Duration stay = Duration.between(t.entryTime(), exit);
        if (stay.compareTo(grace) <= 0) return 0;
        long hours = (stay.toMinutes() + 59) / 60;     // any started hour is charged
        VehicleType v = t.vehicle().type();
        return firstHour.get(v) + Math.max(0, hours - 1) * perExtraHour.get(v);
    }
}

public interface PaymentProcessor {
    /** Must be idempotent on ticketId: a retry after a timeout must not charge twice. */
    void charge(String ticketId, long paise) throws PaymentException;
}

public class PaymentException extends Exception {
    public PaymentException(String msg) { super(msg); }
}

public record Receipt(String ticketId, String plate, Instant entry, Instant exit, long paidPaise) {}
Show Java: ParkingLot, gates, listener
public final class ParkingLot {
    private final SpotPool pool;
    private final PricingStrategy pricing;
    private final PaymentProcessor payments;
    private final Clock clock;
    private final List<AvailabilityListener> listeners;
    private final Map<String, Ticket> activeTickets = new ConcurrentHashMap<>();
    private final Set<String> platesInside = ConcurrentHashMap.newKeySet();
    private final AtomicLong ticketSeq = new AtomicLong();

    public ParkingLot(Collection<Spot> spots, Comparator<Spot> allocationOrder, PricingStrategy pricing,
                      PaymentProcessor payments, Clock clock, List<AvailabilityListener> listeners) {
        this.pool = new SpotPool(spots, allocationOrder);
        this.pricing = pricing; this.payments = payments; this.clock = clock; this.listeners = List.copyOf(listeners);
    }

    public Ticket park(Vehicle v, String gateId) {
        if (!platesInside.add(v.plate())) {                       // atomic: blocks double entry from two gates
            throw new IllegalStateException(v.plate() + " is already inside");
        }
        Optional<Spot> spot = pool.take(v.type());
        if (spot.isEmpty()) {
            platesInside.remove(v.plate());                       // undo the reservation of the plate
            throw new LotFullException(v.type());
        }
        Ticket t = new Ticket("T" + ticketSeq.incrementAndGet(), v, spot.get(), clock.instant(), gateId);
        activeTickets.put(t.id(), t);
        publish(spot.get().type());
        return t;
    }

    public Receipt exit(String ticketId) throws PaymentException {
        Ticket t = activeTickets.get(ticketId);
        if (t == null || !t.transition(Ticket.State.ACTIVE, Ticket.State.PAYING)) {
            throw new IllegalStateException("ticket not active: " + ticketId); // second exit gate loses here
        }
        Instant exitTime = clock.instant();
        long fee = pricing.feePaise(t, exitTime);
        try {
            payments.charge(t.id(), fee);
        } catch (PaymentException e) {
            t.transition(Ticket.State.PAYING, Ticket.State.ACTIVE); // let the driver retry
            throw e;
        }
        t.transition(Ticket.State.PAYING, Ticket.State.CLOSED);
        activeTickets.remove(ticketId);
        pool.release(t.spot());                                   // spot back only after payment succeeded
        platesInside.remove(t.vehicle().plate());
        publish(t.spot().type());
        return new Receipt(t.id(), t.vehicle().plate(), t.entryTime(), exitTime, fee);
    }

    public int available(SpotType type) { return pool.freeCount(type); }

    private void publish(SpotType type) {
        int free = pool.freeCount(type);
        listeners.forEach(l -> l.onChange(type, free));
    }
}

public final class LotFullException extends RuntimeException {
    public LotFullException(VehicleType t) { super("no spot for " + t); }
}

@FunctionalInterface
public interface AvailabilityListener { void onChange(SpotType type, int free); }

public record EntryGate(String id, ParkingLot lot) {
    public Ticket admit(Vehicle v) { return lot.park(v, id); }
}

public record ExitGate(String id, ParkingLot lot) {
    public Receipt release(String ticketId) throws PaymentException { return lot.exit(ticketId); }
}

07Concurrency and edge cases

Every reviewer looks for one bug. It is calling isFree() and then occupy() as two separate calls. This is called check-then-act. Another gate can take the spot between your two calls.

If the lot lives in a database

You get the same safety from SELECT ... FROM spot WHERE type = ? AND status = 'FREE' ORDER BY floor, distance LIMIT 1 FOR UPDATE SKIP LOCKED, then an update in the same transaction. SKIP LOCKED means "skip rows another gate has already locked". Another option is a conditional UPDATE ... WHERE id = ? AND status = 'FREE'. Then check how many rows changed. A unique partial index on active tickets per plate replaces platesInside. Say this when a PayPal-style round moves from LLD to HLD.

The Rubrik variant: a one-row lot, car = 1 unit, truck = 2 units side by side

Show Java: LinearParking
public final class LinearParking {
    private final String[] slots;                          // null = free; guarded by this
    private final Map<String, Integer> startOf = new HashMap<>();

    public LinearParking(int size) { slots = new String[size]; }

    public synchronized boolean tryPark(String id, VehicleType type) {
        if (startOf.containsKey(id)) return false;
        int need = type == VehicleType.TRUCK ? 2 : 1;
        int start = findFree(need);
        if (start < 0) return false;
        for (int i = start; i < start + need; i++) slots[i] = id;
        startOf.put(id, start);
        return true;
    }

    public synchronized void park(String id, VehicleType type) throws InterruptedException {
        while (!tryPark(id, type)) wait();                 // blocking variant
    }

    public synchronized boolean leave(String id) {
        Integer start = startOf.remove(id);
        if (start == null) return false;
        for (int i = start; i < slots.length && id.equals(slots[i]); i++) slots[i] = null;
        notifyAll();                                       // a car leaving may unblock a truck
        return true;
    }

    private int findFree(int need) {
        // ponytail: first-fit O(n) scan; best-fit or cars-from-left/trucks-from-right reduces fragmentation
        for (int i = 0, run = 0; i < slots.length; i++) {
            run = slots[i] == null ? run + 1 : 0;
            if (run == need) return i - need + 1;
        }
        return -1;
    }
}

Here is what they ask next. Fragmentation: cars in every other slot block all trucks. Fix it by putting cars into single gaps first (best fit). Or fill cars from the left and trucks from the right. Truck starvation: with the waiting version, a truck may wait forever while cars keep taking slots. Use a first-come-first-served queue of waiters, so a waiting truck holds the next free pair. Finer locking: you may lock sections of the row instead of the whole row. A truck can cross a section border. So always lock both sections, in index order, to avoid a deadlock.

08Extensions interviewers add mid-round

Search and book a time window (Cashfree)

Keep each spot's bookings in a TreeMap. For search, keep an hourly count of free spots per (type, floor).

EV charging

Add a ChargingSession and an EvChargingPricing decorator. Fee = base fee + kWh × rate.

Weekend, peak hours, slabs

Write new PricingStrategy classes. ParkingLot does not change.

Nearest to the entry gate

Keep one spot order per gate. Claim a spot with AtomicBoolean.compareAndSet.

Passes, spots for disabled drivers

A pricing decorator returns 0 for pass holders. The "what fits where" check looks at vehicle and driver.

Many lots, one app

A lot registry, Postgres, SKIP LOCKED, and free counts cached in Redis.

Go deeper: full answers for each extension
"Search available slots and reserve one for a time window" (Cashfree)

Now a spot is not just free or taken. It has bookings. For each spot, keep a TreeMap<Instant, Booking> sorted by start time. A window [s, e) includes s but not e. It is free if floorEntry(s) ends at or before s. It also needs ceilingEntry(s) to start at or after e. That check costs O(log b), where b is the number of bookings. Search should not check every spot. So group spots by (type, floor). Keep an hourly count of free spots for each (type, floor). Then "is anything free 6–8 pm on floor 2?" is answered from the counters. Pick the actual spot only at booking time. Do it under a per-spot lock, or with a database rule that blocks overlapping time ranges (an exclusion constraint). A booking is held for a short grace period. If the driver does not show up, it expires. This is the "more refined search" the Cashfree interviewer wanted.

"Add EV charging"

EV spots already exist as a type. Add a ChargingSession linked to the ticket. It stores kWh delivered, start and stop. Add an EvChargingPricing decorator: base.feePaise(t, exit) + kwh * ratePerKwh. Raise one policy question. Should a fully charged EV be allowed to keep blocking a charger? Maybe charge an idle fee after charging ends.

"Different pricing on weekends / peak hours / slabs"

Write new PricingStrategy classes. SlabPricing uses bands: 0–2 h, 2–6 h, 6 h+. TimeOfDayPricing splits the stay at each price boundary, using the lot's ZoneId. Pick one per lot or per vehicle type with a small composite. ParkingLot does not change.

"Nearest spot to the gate the car entered from"

Each gate has its own sort rule. That means one ordered set per gate, all over the same spots. Each spot has one shared AtomicBoolean occupied. A gate walks its own order and claims a spot with compareAndSet(false, true). It skips spots already taken. This is slower than pollFirst when the lot is nearly full, but it is correct. Mention a free counter per floor, so gates can skip full floors.

"Monthly passes and handicapped spots"

Pass: check a PassRepository at exit. Pricing returns 0 for an active pass (a decorator again). Spots for disabled drivers: add a spot type. Add an "eligible" flag on the vehicle or driver. The "what fits where" rule now looks at (vehicle, driver), not only the vehicle.

"Multiple lots, one app"

Give ParkingLot an id. A LotRegistry finds the right lot by id. Data moves to Postgres: spots, tickets and bookings. Spot choice uses FOR UPDATE SKIP LOCKED. Free counts per (lot, type) are cached in Redis and updated by events.

10Mistakes that got candidates rejected, and review questions

Rejected for this
  • Search that checks every spot, when the interviewer wanted indexed counts (Cashfree: "wanted a more refined approach for the search functionality").
  • Slow, unsure delivery of a "standard" problem. At Swiggy you are expected to finish the classes fast. Then spend your time on spot choice and thread safety.
  • ParkingLot as a Singleton with static state. Tests then break each other.
  • Car, Bike and Truck subclasses with no behaviour, plus an instanceof chain to decide which spot fits.
  • isFree() then occupy() as two calls, from many gates.
  • Fees stored as double rupees. Calling LocalDateTime.now() inside pricing, so tests cannot control time.
  • Spending 40 minutes on the class diagram and ending with no runnable code.

Interview questions

Why a skip-list set instead of a PriorityQueue with a lock?

Both work. ConcurrentSkipListSet keeps spots sorted. Its pollFirst works in one step. Many threads can add at once without a lock. So there is no lock to think about. A PriorityBlockingQueue also works. But it cannot quickly remove one specific spot, for example for repairs. The set can.

Why does the comparator need thenComparing(Spot::id)?

A sorted set treats "compare returns 0" as "same item". Two spots on the same floor at the same distance would then merge into one. One spot would silently disappear.

Where does the ticket state machine matter?

Exit is the only step with several parts: price, pay, free the spot. The CAS from ACTIVE to PAYING lets only one thread win. If payment fails, the rollback keeps the spot's state true to reality.

How do you add a new vehicle type?

Add the enum value and one row in the "what fits where" table. Add its prices. There is no class tree to change.

Is your free count accurate?

size() on a concurrent skip list is O(n). It is also only roughly right while threads are changing it. For boards, keep one AtomicInteger per type. Update it on take and release. The board is only a hint anyway.

12Quick check

Two entry gates want the last COMPACT spot at the same moment. What keeps this safe?

Only one thread can remove a given spot. The other thread gets the next spot, or null if none is left.

Why does the spot comparator end with thenComparing(Spot::id)?

Two spots on the same floor at the same distance compare as 0. The set thinks they are the same and keeps only one.

Payment fails at the exit. What state should the system be in?

The car is still inside. So the spot must stay taken. Free it only after a successful charge.

The interviewer adds an electric scooter. What do you change?

"What fits where" is data, not code. So a new vehicle type changes no logic.

Cheat sheet
  • Free spots: one ConcurrentSkipListSet per SpotType. The comparator is the spot-choice rule, with the id as a tie-breaker.
  • pollFirst() takes a spot in one step. Never call isFree() and then occupy().
  • "What fits where" is an EnumMap of preference lists. No vehicle subclasses.
  • platesInside.add stops a car entering twice. Undo it when the lot is full.
  • Ticket moves ACTIVE, PAYING, CLOSED with CAS. Roll back if payment fails. Free the spot only after the charge.
  • Fees in long paise. Charge every started hour. Have a grace period. Pass in the Clock.
  • Database version: FOR UPDATE SKIP LOCKED, or a conditional UPDATE.
  • Patterns: Strategy (pricing, spot choice), Decorator (EV), Observer (boards), Façade. No Singleton.
