Parking Lot

Build and defend a multi-gate parking lot where no two cars ever get the same spot and no ticket is charged twice.

Time-box: 60–90 min Seen: ~6 reports, 2025–26, plus a Rubrik concurrency variant
SwiggyCashfreeAngel OneUberPayPalAmazonRubrik
In 30 seconds
  • Free spots live in a sorted concurrent set per spot type.
  • pollFirst() takes the best spot atomically: no two gates share one.
  • Ticket state ACTIVE → PAYING → CLOSED via compare-and-set: one exit wins.
  • Pricing and allocation are strategies; money in paise as long.
Picture it

A mall parking with a token dispenser at every gate. Each dispenser pulls the top token off one shared stack, so two gates can never hand out the same bay. At exit, the token is stamped "paying" first, so a second exit lane cannot charge the same car again.

01What the interviewer is grading

Runnable code

Park, exit, pay, print availability, from a main or tests. A diagram alone does not pass a machine-coding round.

Allocation correctness

Two gates never get the same spot; a car cannot enter twice; exit cannot be paid twice.

Extension points

Allocation strategy, pricing strategy, vehicle-to-spot compatibility as data, observers for display boards.

Search (Cashfree)

Availability by type and floor without scanning every spot, and time-window search if reservations are in scope.

Everyone knows the entities. You are judged on concurrency, extension points, and finishing runnable code in time.

Go deeper: what each company asked

The classic, still asked in 2025–26, and now graded at senior level: multiple floors and spot types, pluggable allocation and pricing, several entry and exit gates racing for the same spots, and room for EV charging and reservations. The reports show how little the prompt says and how much is expected:

  • Swiggy SDE-2 (Nov 2025, rejected after the next round): parking lot in a combined DSA + LLD hour; entities (Vehicle, Slot, Ticket, Payment), allocation strategy and class diagram. The candidate's takeaway: startups expect you to "solve instantly".
  • Cashfree SDE-2 (Oct 2025, rejected): "online parking lot": search available slots, book/reserve a slot. "The interviewer wanted a more refined approach for the search functionality." Search was the deciding part.
  • Angel One SDE-2 (2026, selected): parking lot LLD inside a combined system design + DB design round.
  • Rubrik: a systems-coding twist: a thread-safe car and truck parking in a 1-D array, car takes one unit, truck takes two.
  • Uber, PayPal (SE3, LLD and HLD) and Amazon also ask it; at senior level the follow-ups are concurrency and extensibility.

03Requirements

Functional

  • Lot with floors; spots of type TWO_WHEELER, COMPACT, LARGE, EV.
  • Vehicles BIKE, CAR, EV_CAR, TRUCK with a compatibility order.
  • Entry gate issues a ticket and assigns a spot, or reports full.
  • Exit gate computes fee, takes payment, frees the spot.
  • Availability per spot type and floor (display boards).
  • Pluggable allocation and pricing.

Non-functional

  • Concurrent gates: no double allocation, no double exit.
  • Allocation in O(log n), not a scan of every spot.
  • Deterministic fee tests with injected Clock.
  • Money as long paise, never double.

Out of scope

  • Real payment gateway (interface + stub).
  • ANPR cameras and hardware.
  • Multi-lot platform and persistence (talk only).

Show Java: SpotPool

The free pool is the concurrency core. ConcurrentSkipListSet.pollFirst() removes and returns the best spot atomically, so two gates can never receive the same spot, with no explicit lock. The comparator is the allocation strategy.

final class SpotPool {
    private final Map<SpotType, ConcurrentSkipListSet<Spot>> free = new EnumMap<>(SpotType.class);

    SpotPool(Collection<Spot> spots, Comparator<Spot> allocationOrder) {
        Comparator<Spot> total = allocationOrder.thenComparing(Spot::id); // ties must not collapse in a Set
        for (SpotType t : SpotType.values()) free.put(t, new ConcurrentSkipListSet<>(total));
        spots.forEach(s -> free.get(s.type()).add(s));
    }

    Optional<Spot> take(VehicleType vehicle) {
        for (SpotType type : Compatibility.preferenceFor(vehicle)) {
            Spot s = free.get(type).pollFirst(); // atomic remove-and-return
            if (s != null) return Optional.of(s);
        }
        return Optional.empty();
    }

    void release(Spot s) { free.get(s.type()).add(s); }

    int freeCount(SpotType t) { return free.get(t).size(); } // O(n) on a skip list; keep an AtomicInteger if hot
}

// Allocation strategies are just comparators:
//   lowest floor, then nearest:  Comparator.comparingInt(Spot::floor).thenComparingInt(Spot::distanceFromEntry)
//   nearest overall:             Comparator.comparingInt(Spot::distanceFromEntry)
Show Java: Ticket, PricingStrategy, HourlyPricing, PaymentProcessor
public final class Ticket {
    public enum State { ACTIVE, PAYING, CLOSED }

    private final String id;
    private final Vehicle vehicle;
    private final Spot spot;
    private final Instant entryTime;
    private final String entryGate;
    private final AtomicReference<State> state = new AtomicReference<>(State.ACTIVE);

    Ticket(String id, Vehicle vehicle, Spot spot, Instant entryTime, String entryGate) {
        this.id = id; this.vehicle = vehicle; this.spot = spot; this.entryTime = entryTime; this.entryGate = entryGate;
    }

    boolean transition(State from, State to) { return state.compareAndSet(from, to); }

    public String id() { return id; }
    public Vehicle vehicle() { return vehicle; }
    public Spot spot() { return spot; }
    public Instant entryTime() { return entryTime; }
    public State state() { return state.get(); }
}

public interface PricingStrategy {
    long feePaise(Ticket ticket, Instant exitTime);
}

public final class HourlyPricing implements PricingStrategy {
    private final Map<VehicleType, Long> firstHour;
    private final Map<VehicleType, Long> perExtraHour;
    private final Duration grace;

    public HourlyPricing(Map<VehicleType, Long> firstHour, Map<VehicleType, Long> perExtraHour, Duration grace) {
        this.firstHour = Map.copyOf(firstHour); this.perExtraHour = Map.copyOf(perExtraHour); this.grace = grace;
    }

    @Override
    public long feePaise(Ticket t, Instant exit) {
        Duration stay = Duration.between(t.entryTime(), exit);
        if (stay.compareTo(grace) <= 0) return 0;
        long hours = (stay.toMinutes() + 59) / 60;     // any started hour is charged
        VehicleType v = t.vehicle().type();
        return firstHour.get(v) + Math.max(0, hours - 1) * perExtraHour.get(v);
    }
}

public interface PaymentProcessor {
    /** Must be idempotent on ticketId: a retry after a timeout must not charge twice. */
    void charge(String ticketId, long paise) throws PaymentException;
}

public class PaymentException extends Exception {
    public PaymentException(String msg) { super(msg); }
}

public record Receipt(String ticketId, String plate, Instant entry, Instant exit, long paidPaise) {}
Show Java: ParkingLot, gates, listener
public final class ParkingLot {
    private final SpotPool pool;
    private final PricingStrategy pricing;
    private final PaymentProcessor payments;
    private final Clock clock;
    private final List<AvailabilityListener> listeners;
    private final Map<String, Ticket> activeTickets = new ConcurrentHashMap<>();
    private final Set<String> platesInside = ConcurrentHashMap.newKeySet();
    private final AtomicLong ticketSeq = new AtomicLong();

    public ParkingLot(Collection<Spot> spots, Comparator<Spot> allocationOrder, PricingStrategy pricing,
                      PaymentProcessor payments, Clock clock, List<AvailabilityListener> listeners) {
        this.pool = new SpotPool(spots, allocationOrder);
        this.pricing = pricing; this.payments = payments; this.clock = clock; this.listeners = List.copyOf(listeners);
    }

    public Ticket park(Vehicle v, String gateId) {
        if (!platesInside.add(v.plate())) {                       // atomic: blocks double entry from two gates
            throw new IllegalStateException(v.plate() + " is already inside");
        }
        Optional<Spot> spot = pool.take(v.type());
        if (spot.isEmpty()) {
            platesInside.remove(v.plate());                       // undo the reservation of the plate
            throw new LotFullException(v.type());
        }
        Ticket t = new Ticket("T" + ticketSeq.incrementAndGet(), v, spot.get(), clock.instant(), gateId);
        activeTickets.put(t.id(), t);
        publish(spot.get().type());
        return t;
    }

    public Receipt exit(String ticketId) throws PaymentException {
        Ticket t = activeTickets.get(ticketId);
        if (t == null || !t.transition(Ticket.State.ACTIVE, Ticket.State.PAYING)) {
            throw new IllegalStateException("ticket not active: " + ticketId); // second exit gate loses here
        }
        Instant exitTime = clock.instant();
        long fee = pricing.feePaise(t, exitTime);
        try {
            payments.charge(t.id(), fee);
        } catch (PaymentException e) {
            t.transition(Ticket.State.PAYING, Ticket.State.ACTIVE); // let the driver retry
            throw e;
        }
        t.transition(Ticket.State.PAYING, Ticket.State.CLOSED);
        activeTickets.remove(ticketId);
        pool.release(t.spot());                                   // spot back only after payment succeeded
        platesInside.remove(t.vehicle().plate());
        publish(t.spot().type());
        return new Receipt(t.id(), t.vehicle().plate(), t.entryTime(), exitTime, fee);
    }

    public int available(SpotType type) { return pool.freeCount(type); }

    private void publish(SpotType type) {
        int free = pool.freeCount(type);
        listeners.forEach(l -> l.onChange(type, free));
    }
}

public final class LotFullException extends RuntimeException {
    public LotFullException(VehicleType t) { super("no spot for " + t); }
}

@FunctionalInterface
public interface AvailabilityListener { void onChange(SpotType type, int free); }

public record EntryGate(String id, ParkingLot lot) {
    public Ticket admit(Vehicle v) { return lot.park(v, id); }
}

public record ExitGate(String id, ParkingLot lot) {
    public Receipt release(String ticketId) throws PaymentException { return lot.exit(ticketId); }
}

The Rubrik variant: 1-D lot, car = 1 unit, truck = 2 contiguous units

Show Java: LinearParking
public final class LinearParking {
    private final String[] slots;                          // null = free; guarded by this
    private final Map<String, Integer> startOf = new HashMap<>();

    public LinearParking(int size) { slots = new String[size]; }

    public synchronized boolean tryPark(String id, VehicleType type) {
        if (startOf.containsKey(id)) return false;
        int need = type == VehicleType.TRUCK ? 2 : 1;
        int start = findFree(need);
        if (start < 0) return false;
        for (int i = start; i < start + need; i++) slots[i] = id;
        startOf.put(id, start);
        return true;
    }

    public synchronized void park(String id, VehicleType type) throws InterruptedException {
        while (!tryPark(id, type)) wait();                 // blocking variant
    }

    public synchronized boolean leave(String id) {
        Integer start = startOf.remove(id);
        if (start == null) return false;
        for (int i = start; i < slots.length && id.equals(slots[i]); i++) slots[i] = null;
        notifyAll();                                       // a car leaving may unblock a truck
        return true;
    }

    private int findFree(int need) {
        // ponytail: first-fit O(n) scan; best-fit or cars-from-left/trucks-from-right reduces fragmentation
        for (int i = 0, run = 0; i < slots.length; i++) {
            run = slots[i] == null ? run + 1 : 0;
            if (run == need) return i - need + 1;
        }
        return -1;
    }
}

What they probe next: fragmentation (cars in every other slot block all trucks; place cars best-fit into single gaps, or fill cars from the left and trucks from the right), truck starvation under the blocking API (a FIFO queue of waiters so a waiting truck reserves the next adjacent pair), and finer locking (segment locks fail when a truck spans a boundary unless you always lock both segments in index order, which avoids deadlock).

Go deeper: full answers for each extension
"Search available slots and reserve one for a time window" (Cashfree)

A spot is no longer free or occupied; it has bookings. Per spot keep a TreeMap<Instant, Booking> keyed by start; a window [s, e) is free if floorEntry(s) ends at or before s and ceilingEntry(s) starts at or after e: O(log b). To avoid checking every spot on search, index spots by (type, floor) and keep per-hour available counts per (type, floor) so "is anything free 6–8 pm on floor 2" is answered from counters, then pick the concrete spot at booking time under a per-spot lock (or a DB exclusion constraint on overlapping ranges). Reservations hold for a no-show grace period, then expire. This is the "more refined search" the Cashfree interviewer was after.

"Add EV charging"

EV spots already exist as a type. Add a ChargingSession (kWh delivered, start, stop) linked to the ticket, and an EvChargingPricing decorator: base.feePaise(t, exit) + kwh * ratePerKwh. Policy question to raise: should a fully charged EV keep blocking a charger (idle fee after charge completes)?

"Different pricing on weekends / peak hours / slabs"

New PricingStrategy implementations: SlabPricing (0–2 h, 2–6 h, 6 h+), TimeOfDayPricing splitting the stay at boundaries in the lot's ZoneId. Choose per lot or per vehicle type through a small composite. No change to ParkingLot.

"Nearest spot to the gate the car entered from"

One comparator per gate means one ordered set per gate over the same spots. Keep a shared AtomicBoolean occupied per spot; each gate iterates its own order and claims with compareAndSet(false, true), skipping taken ones. Slower than pollFirst under heavy occupancy but correct; mention a per-floor free counter to skip full floors.

"Monthly passes and handicapped spots"

Pass: a PassRepository checked at exit; pricing returns 0 for active passes (a decorator again). Handicapped: a spot type plus an eligibility flag on the vehicle or driver; compatibility becomes a function of (vehicle, driver) instead of vehicle only.

"Multiple lots, one app"

ParkingLot gets an id; a LotRegistry routes by lot id. Data moves to Postgres (spots, tickets, bookings), allocation uses FOR UPDATE SKIP LOCKED, availability is cached in Redis per (lot, type) and updated by events.

Interview questions

Why a skip-list set instead of a PriorityQueue with a lock?

Both work. ConcurrentSkipListSet gives sorted order plus atomic pollFirst and lock-free concurrent add, so no lock to reason about. A PriorityBlockingQueue also works but cannot remove a specific spot efficiently (maintenance), which the set can.

Why does the comparator need thenComparing(Spot::id)?

A sorted set treats compare == 0 as duplicates. Two spots on the same floor at the same distance would silently collapse into one.

Where does the ticket state machine matter?

Exit is the only multi-step operation (price, pay, release). The CAS on ACTIVE → PAYING makes it single-winner, and the rollback on failure keeps the spot consistent with reality.

How do you add a new vehicle type?

Add the enum value and one row in the compatibility table, plus prices. No class hierarchy to touch.

Is your free count accurate?

size() on a concurrent skip list is O(n) and weakly consistent. For boards, keep an AtomicInteger per type updated on take and release; display is advisory anyway.

12Quick check

Two entry gates want the last COMPACT spot at the same moment. What makes it safe here?

Only one thread can remove a given element. The other gets the next spot or null.

Why does the spot comparator end with thenComparing(Spot::id)?

Two spots on the same floor at the same distance compare as 0 and the set keeps only one.

Payment fails at the exit. What state should the system be in?

The car is still inside. Release the spot only after a successful charge.

The interviewer adds an electric scooter. What changes?

Compatibility is data, so a new vehicle type touches no logic.

Cheat sheet
  • Free spots: ConcurrentSkipListSet per SpotType; comparator = allocation strategy (+ id tiebreak).
  • pollFirst() = atomic take; never isFree() then occupy().
  • Compatibility as an EnumMap preference list; no vehicle subclasses.
  • platesInside.add blocks double entry; undo on lot full.
  • Ticket CAS ACTIVE → PAYING → CLOSED; roll back on failed payment; release after charge.
  • Fees in long paise, every started hour, grace period, injected Clock.
  • DB version: FOR UPDATE SKIP LOCKED or conditional UPDATE.
