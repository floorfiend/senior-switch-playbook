Sliding Window and Two Pointers

Turn O(n²) "check every subarray" brute force into a single O(n) pass. Learn the fixed window, the variable window (grow right, shrink left while invalid), the monotonic deque for window max/min, the "exactly K = atMost(K) − atMost(K−1)" trick, and two pointers from both ends.

01When to use this pattern

Reach for a window when the problem is about a contiguous piece of an array or string, and you can update the answer cheaply when one element enters on the right or leaves on the left.

Fixed window

"every subarray of size k", "average of each window", "maximum in each window of size k". The window length never changes; you add one and drop one each step.

Variable window

"longest substring such that…", "shortest subarray with sum ≥ S", "at most K distinct", "flip at most K zeros". Validity is monotonic: shrinking a valid window keeps it valid (for longest) or growing keeps it valid (for shortest).

Monotonic deque

"max/min of every window", "longest subarray where max − min ≤ limit". You need the window extreme in O(1) while elements leave from the left.

Two pointers from both ends

Sorted array pair sums, "container", "trapping water", palindromes. Each step you can prove one end can be discarded.

The test that decides it

Ask: "if the window [l, r] is invalid, is [l, r+1] also invalid?" If yes, a variable window works because you never need to move left backwards. Negative numbers in a sum problem usually break this (sum can drop as you grow), which is why "subarray sum equals K" with negatives needs prefix sums + a HashMap, not a window.

02The mental model, from scratch

Brute force tries every pair (left, right): O(n²) windows, often O(n³) with the inner check. The window idea: keep two indices, both only ever move forward, so together they make at most 2n moves. You keep a small piece of state (a count, a sum, a frequency map, a deque) that describes the current window and update it in O(1) as elements enter and leave.

The variable-window loop always has the same three beats:

  1. Grow: move right one step and add a[right] to the state.
  2. Shrink while invalid: while the state breaks the rule, remove a[left] and move left forward.
  3. Record: the window is now the longest valid one ending at right; update the answer.

Monotonic deque: why window max is O(n)

A heap gives window max in O(n log k) but deleting the leaving element is awkward. The deque trick: keep indices whose values are strictly decreasing from front to back. When a new value x arrives, any older value ≤ x can never be a window max again (x is newer and at least as large, so it outlives them). Pop them from the back. The front is always the max; pop it from the front when its index leaves the window. Every index is pushed once and popped at most once.

Exactly K = atMost(K) − atMost(K − 1)

"Exactly K distinct" is not monotonic: a window with too few distinct values may become valid by growing, one with too many by shrinking, so a single window cannot decide which way to move. "At most K" is monotonic. For a fixed right, every start in [left, right] gives a valid subarray, so the count of at-most-K subarrays ending at right is right − left + 1. Subarrays with exactly K = (those with ≤ K) minus (those with ≤ K − 1).

Two pointers from both ends

Start i = 0, j = n − 1. At each step compare the ends and prove that one of them cannot be part of a better answer, then discard it. The proof is the whole interview answer; the code is three lines.

i = 0→ compare a[i], a[j]prove one end is useless→ move that end inward→ stop when i meets j

Figure: each comparison permanently removes one index, so the loop runs n − 1 times.

03Java templates

Fixed and variable windows. Both run in O(n) time; space is O(1) for the fixed sum and O(alphabet) for the frequency map.

import java.util.HashMap;
import java.util.Map;

class SlidingTemplates {
    // FIXED window of size k: add the entering element, remove the leaving one. O(n) time, O(1) space.
    static long maxSumOfK(int[] a, int k) {
        long sum = 0, best = Long.MIN_VALUE;
        for (int right = 0; right < a.length; right++) {
            sum += a[right];                    // element entering
            if (right >= k) {
                sum -= a[right - k];            // element leaving
            }
            if (right >= k - 1) {
                best = Math.max(best, sum);
            }
        }
        return best;
    }

    // VARIABLE window: grow right every step, shrink left WHILE the window is invalid,
    // then the window [left, right] is the longest valid one ending at right. O(n) time.
    static int longestWithAtMostKDistinct(String s, int k) {
        Map<Character, Integer> count = new HashMap<>();
        int left = 0, best = 0;
        for (int right = 0; right < s.length(); right++) {
            count.merge(s.charAt(right), 1, Integer::sum);       // 1. include s[right]
            while (count.size() > k) {                          // 2. restore the invariant
                char out = s.charAt(left++);
                if (count.merge(out, -1, Integer::sum) == 0) {
                    count.remove(out);
                }
            }
            best = Math.max(best, right - left + 1);            // 3. record the answer
        }
        return best;
    }
}

The monotonic deque template is the Sliding Window Maximum solution below, the at-most-K counting template is this (LeetCode 992, Subarrays with K Different Integers), and the two-ends template is Container With Most Water.

import java.util.HashMap;
import java.util.Map;

class Solution {
    // LeetCode 992: number of subarrays with exactly k distinct values
    public int subarraysWithKDistinct(int[] nums, int k) {
        return atMost(nums, k) - atMost(nums, k - 1);
    }

    private int atMost(int[] nums, int k) {
        Map<Integer, Integer> count = new HashMap<>();
        int left = 0, total = 0;
        for (int right = 0; right < nums.length; right++) {
            count.merge(nums[right], 1, Integer::sum);
            while (count.size() > k) {
                if (count.merge(nums[left], -1, Integer::sum) == 0) {
                    count.remove(nums[left]);
                }
                left++;
            }
            total += right - left + 1;   // every subarray ending at right and starting in [left, right]
        }
        return total;
    }
}

Complexity: O(n) time (two passes, each amortised O(n)), O(K) map space.

Which variant am I in?
  • Longest valid window: shrink while invalid, record after the loop.
  • Shortest valid window: shrink while valid, record inside the loop (Minimum Window Substring).
  • Count windows: add right − left + 1 per step, use atMost differences for "exactly".

04Worked problems

1. Longest Substring Without Repeating Characters

LeetCode 3 · Medium. Given a string, return the length of the longest substring in which no character appears twice.

Key insight: variable window with "no duplicates" as the rule. Instead of shrinking one step at a time, remember where each character was last seen and jump left straight past the previous copy. Use max so left never moves backwards (the "abba" case: when the second 'a' arrives, its last copy is already outside the window).

class Solution {
    public int lengthOfLongestSubstring(String s) {
        int[] nextStart = new int[128]; // for each char: (last index seen) + 1
        int best = 0;
        for (int left = 0, right = 0; right < s.length(); right++) {
            char c = s.charAt(right);
            left = Math.max(left, nextStart[c]); // jump past the previous copy, never move left backwards
            best = Math.max(best, right - left + 1);
            nextStart[c] = right + 1;
        }
        return best;
    }
}

Complexity: O(n) time, O(1) space (128-entry array; use a HashMap<Character, Integer> if the input is full Unicode).

Edge cases: empty string → 0; all same character → 1; spaces and digits are characters too; "abba" (stale last-seen index).

2. Max Consecutive Ones III

LeetCode 1004 · Medium · asked at Groww, Paytm, LinkedIn (with a circular follow-up). Given a binary array and k, return the longest run of 1s you can get by flipping at most k zeros.

Key insight: rephrase as "longest window containing at most k zeros". You never flip anything; you just count zeros (the trace in section 02 is this problem). Circular follow-up: the array wraps around. Walk indices 0 … 2n − 1 using i % n, which unrolls every wrap-around window, and add a second shrink condition: the window may not exceed n elements, or you would count an element twice.

class Solution {
    public int longestOnes(int[] nums, int k) {
        int left = 0, zeros = 0, best = 0;
        for (int right = 0; right < nums.length; right++) {
            if (nums[right] == 0) {
                zeros++;
            }
            while (zeros > k) {           // window invalid: shrink from the left
                if (nums[left++] == 0) {
                    zeros--;
                }
            }
            best = Math.max(best, right - left + 1);
        }
        return best;
    }

    // Follow-up: the array is circular. Walk the doubled array (index i % n)
    // and also shrink whenever the window would exceed n elements.
    public int longestOnesCircular(int[] nums, int k) {
        int n = nums.length, left = 0, zeros = 0, best = 0;
        for (int right = 0; right < 2 * n; right++) {
            if (nums[right % n] == 0) {
                zeros++;
            }
            while (zeros > k || right - left + 1 > n) {
                if (nums[left++ % n] == 0) {
                    zeros--;
                }
            }
            best = Math.max(best, right - left + 1);
        }
        return best;
    }
}

Complexity: O(n) time, O(1) space for both versions (the circular one does 2n steps).

Edge cases: k = 0 (plain longest run of 1s); k ≥ number of zeros (answer n); all zeros with k = 0 → 0; circular with all 1s must return n, not 2n, which is why the length cap exists.

3. Minimum Window Substring

LeetCode 76 · Hard · LinkedIn, Goldman Sachs, Salesforce, Teradata. Given strings s and t, return the shortest substring of s that contains every character of t with multiplicity (t = "AAB" needs two A's), or "" if none.

Key insight: this is the "shortest" variant: grow until the window is valid, then shrink while it stays valid, recording each valid window. Track one integer, missing, instead of comparing two maps every step. need[c] goes negative for surplus characters; a character only counts toward missing while need[c] > 0.

class Solution {
    public String minWindow(String s, String t) {
        int[] need = new int[128];                 // how many more of each char the window needs
        for (char c : t.toCharArray()) {
            need[c]++;
        }
        int missing = t.length();                  // total chars still missing (with multiplicity)
        int bestStart = 0, bestLen = Integer.MAX_VALUE;
        for (int left = 0, right = 0; right < s.length(); right++) {
            if (need[s.charAt(right)]-- > 0) {     // this char was actually needed
                missing--;
            }
            while (missing == 0) {                 // window valid: record, then try to shrink
                if (right - left + 1 < bestLen) {
                    bestLen = right - left + 1;
                    bestStart = left;
                }
                if (++need[s.charAt(left++)] > 0) { // we just dropped a needed char
                    missing++;
                }
            }
        }
        return bestLen == Integer.MAX_VALUE ? "" : s.substring(bestStart, bestStart + bestLen);
    }
}

Complexity: O(|s| + |t|) time, O(1) space (fixed 128 array).

Edge cases: |t| > |s| → ""; duplicates in t ("aa" in "a" → ""); s == t; case sensitivity (A ≠ a). Store bestStart/bestLen and call substring once at the end; building substrings in the loop makes it O(n²).

4. Sliding Window Maximum

LeetCode 239 · Hard · Uber, PhonePe, Booking.com, Amazon, Twilio, Flipkart. Return the maximum of every window of size k as the window slides from left to right.

Key insight: monotonic decreasing deque of indices (indices let you detect expiry; values cannot, because of duplicates). See the trace in section 02.

import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public int[] maxSlidingWindow(int[] nums, int k) {
        int[] out = new int[nums.length - k + 1];
        Deque<Integer> dq = new ArrayDeque<>();    // indices; their values strictly decrease front to back
        for (int i = 0; i < nums.length; i++) {
            if (!dq.isEmpty() && dq.peekFirst() <= i - k) {
                dq.pollFirst();                    // front fell out of the window
            }
            while (!dq.isEmpty() && nums[dq.peekLast()] <= nums[i]) {
                dq.pollLast();                     // smaller elements can never be a max again
            }
            dq.offerLast(i);
            if (i >= k - 1) {
                out[i - k + 1] = nums[dq.peekFirst()];
            }
        }
        return out;
    }
}

Complexity: O(n) time (each index pushed and popped at most once), O(k) deque space.

Edge cases: k = 1 (output = input); k = n (one value); strictly decreasing input (deque grows to k, expiry pops do the work); duplicates (popping with <= keeps the newest copy, which is fine). Interviewers often ask for the O(n log n) TreeMap/heap version first, then push for O(n).

5. Longest Continuous Subarray With Absolute Diff ≤ Limit

LeetCode 1438 · Medium · Uber (twice), Oracle. Return the length of the longest subarray in which every pair of elements differs by at most limit.

Key insight: "every pair differs by ≤ limit" is the same as "window max − window min ≤ limit". That is a variable window whose validity check needs the max and the min, so keep two monotonic deques: one non-increasing (front = max), one non-decreasing (front = min). Here the deques hold values and pop with strict comparisons, so duplicates stay in; when the leaving value equals a front, pop that front.

import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public int longestSubarray(int[] nums, int limit) {
        Deque<Integer> maxQ = new ArrayDeque<>();  // values, non-increasing: front = window max
        Deque<Integer> minQ = new ArrayDeque<>();  // values, non-decreasing: front = window min
        int left = 0, best = 0;
        for (int right = 0; right < nums.length; right++) {
            int x = nums[right];
            while (!maxQ.isEmpty() && maxQ.peekLast() < x) {
                maxQ.pollLast();
            }
            while (!minQ.isEmpty() && minQ.peekLast() > x) {
                minQ.pollLast();
            }
            maxQ.offerLast(x);
            minQ.offerLast(x);
            while (maxQ.peekFirst() - minQ.peekFirst() > limit) {
                int out = nums[left++];            // shrink; drop the leaving value from a queue front
                if (out == maxQ.peekFirst()) {
                    maxQ.pollFirst();
                }
                if (out == minQ.peekFirst()) {
                    minQ.pollFirst();
                }
            }
            best = Math.max(best, right - left + 1);
        }
        return best;
    }
}

Complexity: O(n) time, O(n) space worst case. The TreeMap<Integer, Integer> multiset version is O(n log n) and is an acceptable first answer; say so, then optimise.

Edge cases: limit = 0 (longest run of equal values); all equal; maxQ.peekFirst() - minQ.peekFirst() cannot overflow because values are ≤ 10^9 and positive, but mention it if values can be negative and near Integer.MIN_VALUE.

6. Container With Most Water

LeetCode 11 · Medium. Vertical lines at each index; choose two that, with the x-axis, hold the most water. Area = width × the shorter line.

Key insight: start with the widest container. Moving the taller end inward can only shrink the width while the height stays capped by the shorter end, so it can never help. The shorter end is therefore useless for every remaining container: discard it.

class Solution {
    public int maxArea(int[] height) {
        int i = 0, j = height.length - 1, best = 0;
        while (i < j) {
            best = Math.max(best, (j - i) * Math.min(height[i], height[j]));
            if (height[i] < height[j]) {   // the shorter wall caps every narrower container: discard it
                i++;
            } else {
                j--;
            }
        }
        return best;
    }
}

Complexity: O(n) time, O(1) space.

Edge cases: two lines; equal heights (moving either is fine); width × height fits in int for the constraints (10^5 × 10^4), use long if they grow.

7. Trapping Rain Water

LeetCode 42 · Hard · Flipkart, Amazon, eBay, ServiceNow; the most common problem in Razorpay's online assessment. Given bar heights, compute how much rain is trapped between them.

Key insight: water above bar i = min(maxLeft(i), maxRight(i)) − height[i]. The prefix/suffix-max arrays solution is O(n) space. Two pointers remove the arrays: if height[i] < height[j], there is a wall at least height[i] tall on the right, so the water at i depends only on leftMax, which you already know. Settle i and move it; otherwise settle j symmetrically.

class Solution {
    public int trap(int[] height) {
        int i = 0, j = height.length - 1, leftMax = 0, rightMax = 0, water = 0;
        while (i < j) {
            if (height[i] < height[j]) {
                // the right side has a wall >= height[i], so leftMax alone bounds the water at i
                leftMax = Math.max(leftMax, height[i]);
                water += leftMax - height[i];
                i++;
            } else {
                rightMax = Math.max(rightMax, height[j]);
                water += rightMax - height[j];
                j--;
            }
        }
        return water;
    }
}

Complexity: O(n) time, O(1) space.

Edge cases: fewer than 3 bars → 0; strictly increasing or decreasing → 0; plateaus. Know the three solutions (prefix arrays, two pointers, monotonic stack that fills water layer by layer) and when each is natural; the stack version generalises to "water between bars as they arrive".

05Common mistakes and follow-ups interviewers ask

Mistakes that cost candidates the round
  • Using if instead of while to shrink: one removal is not always enough to restore validity.
  • Applying a window to sums with negative numbers. Validity is no longer monotonic; use prefix sums + HashMap.
  • Storing values instead of indices in the max deque, then failing to detect expiry with duplicates.
  • Moving left backwards (the "abba" bug in problem 1).
  • Calling substring or copying a map inside the loop, silently making it O(n²).
  • Claiming O(n²) because of the nested while. Explain the amortised bound: each pointer moves at most n times.
The input is a stream; you cannot store it. Which of these still work?

Fixed windows need only the last k elements (ring buffer) and work. Window max needs only the deque, at most k entries. Longest-without-repeats needs the last-seen map plus the current window, so O(alphabet + window). Two pointers from both ends do not work on a stream because they need the right end.

Max Consecutive Ones: what if k is huge and the array is a stream of billions of bits?

Keep only a queue of the positions of the last k + 1 zeros. The current window starts just after the oldest of those zeros. O(k) memory regardless of stream length.

Count subarrays with exactly K odd numbers / exactly K distinct values.

Write atMost(K) with the count-per-right trick and return atMost(K) − atMost(K − 1). For "exactly K odd numbers" with non-negative weights, prefix counts + HashMap is an equally good O(n) answer.

Sliding window median?

Two heaps (max-heap for the lower half, min-heap for the upper) with lazy deletion, or two TreeMap multisets. O(n log k). The deque trick does not work because the median is not an extreme.

Trapping Rain Water in 2D (a height map grid)?

LeetCode 407. Push all border cells into a min-heap; repeatedly pop the lowest wall, and for each unvisited neighbour add max(0, wall − height) water and push it with height max(wall, height). O(mn log(mn)). The 1D two-pointer proof generalises to "the lowest boundary decides".

Minimum Window Substring: t is huge and s is a stream of characters. How do you avoid the 128-array assumption?

Use HashMap<Character, Integer> (or int code points) for need; the algorithm is unchanged. Memory is O(distinct characters in t).

06Self-check

Why is a variable window O(n) when it contains a nested while loop?

Both pointers only move forward and each moves at most n times, so the total number of loop iterations across the whole run is at most 2n.

Why can't you solve "subarray sum equals K" with a window when numbers can be negative?

Adding an element can decrease the sum and removing one can increase it, so you cannot tell which pointer to move. Use prefix sums: count earlier prefixes equal to prefix − K in a HashMap.

In Sliding Window Maximum, why pop smaller values from the back?

The new element is larger and will stay in the window longer than any older element, so the older, smaller ones can never be the maximum of any future window.

In Trapping Rain Water, why is it safe to settle the left bar when height[i] < height[j]?

A wall at least height[i] exists on the right (at j), so the right side is never the bottleneck for i; the water at i is leftMax − height[i], which is already known.

How many subarrays of [1,2,1,2,3] have exactly 2 distinct values?

atMost(2) = 12, atMost(1) = 5, so 7: [1,2], [2,1], [1,2], [2,3], [1,2,1], [2,1,2], [1,2,1,2].
